# SephPlanner

세피리아(Sephiria)용 비공식 컴패니언 오버레이. 현재 인벤토리를 읽어 석판 배치를 최적화하고,
지금 상황에서 어떤 아티팩트를 고르는 게 좋은지 알려준다.

TEAM HORAY와 무관한 팬 제작 도구이며, 비영리로 배포한다.

## 구조

```
SephPlanner.Core      도메인 모델 + IPC 계약 + 솔버와 배치 계산 (netstandard2.1)
SephPlanner.Plugin    BepInEx 플러그인. 게임 상태를 읽어 명명 파이프로 내보내고,
                      싱글플레이 한정으로 자동 배치를 적용한다
SephPlanner.Overlay   WPF 오버레이. 파이프에 붙어 화면에 표시한다 (net10.0-windows)
SephPlanner.DataTool  게임 로컬라이제이션에서 이름/설명 텍스트를 추출하는 CLI
SephPlanner.Tests     Core 단위 테스트. 게임 없이 돈다
```

게임 ↔ 오버레이 통신에 localhost HTTP 대신 **명명 파이프**를 쓴다. 방화벽 팝업이 뜨지 않고,
포트가 충돌하지 않으며, 같은 사용자 세션 밖에서는 열 수 없다.

## 빌드

게임이 설치돼 있어야 한다. 기본 경로가 아니면 환경변수로 알려준다.

```powershell
$env:SEPHIRIA_DIR = "D:\SteamLibrary\steamapps\common\Sephiria"
dotnet build
```

테스트는 게임 없이 돈다.

```powershell
dotnet test
```

저장해 둔 스냅샷으로 우리 레벨 계산이 게임 값과 맞는지 볼 수 있다. 어긋나는 칸이 있으면 아직
읽지 않는 효과(각인, 세트 효과, 배치 보너스)가 걸려 있다는 뜻이다.

```powershell
dotnet run --project src/SephPlanner.DataTool -- --check <스냅샷.json>
```

콤보 한 단계가 아티팩트 레벨 몇 개 값어치인지 잰다. `Worth`의 상수를 짐작으로 두지 않기 위한
것이며, 게임을 한 번 켜서 카탈로그를 다시 덤프한 뒤에 돌아간다(방법은 docs/RESEARCH.md 참고).

```powershell
dotnet run --project src/SephPlanner.DataTool -- --measure
```

아티팩트 하나하나의 값어치가 어디까지 측정됐는지 보고, 아직 레어도 어림값에 기대고 있는 것들을
손으로 채울 초안으로 뽑는다. 채우는 법은 [data/values/README.md](data/values/README.md) 참고.

```powershell
dotnet run --project src/SephPlanner.DataTool -- --values
```

데이터 추출:

```powershell
dotnet run --project src/SephPlanner.DataTool
# -> data/generated/text.json  (석판 68종, 아티팩트 257종, 15개 언어)
```

`data/generated/`는 각자 PC에서 생성되며 저장소에 커밋하지 않는다. 이유는 [docs/LEGAL.md](docs/LEGAL.md) 참고.

## 배포

```powershell
scripts/make-release.ps1
# -> artifacts/SephPlanner-v{버전}.zip
```

오버레이는 .NET 런타임 없이 도는 자체 포함 exe로, 플러그인은 DLL 두 개로 묶인다. BepInEx와
게임 파일은 넣지 않는다. 버전은 `Directory.Build.props`의 `<Version>`에서 나온다.
사용자용 안내는 [docs/INSTALL.md](docs/INSTALL.md)가 zip에 `설치안내.md`로 들어간다.

## 인게임 화면

플러그인이 게임 HUD 캔버스 안에 같은 내용을 직접 그린다. 별도 창이 아니라 게임 UI 의 일부라
전용 전체화면에서도 보이고, 글꼴과 아이콘을 게임에서 빌려 쓴다. 크기는 게임 HUD 글자 크기에
대한 비율이라 해상도와 UI 배율을 따라간다.

**마우스와 키보드를 하나도 가져가지 않는다.** 그리는 것마다 `raycastTarget` 이 꺼져 있고
컨트롤 스택에도 들어가지 않는다. 그래서 누를 것이 없고 조작은 전부 단축키다. 커서 위치는
읽지만(이동 모드와 쪽지) 읽기만 하는 것이라 게임에서 가져가는 입력은 없다.

| 키 | |
|---|---|
| `F1` | 후보 미리보기 (차례로 돌고, 마지막 다음은 미리보기 없음) |
| `F2` | 빌드 창 (프리셋 코드·콤보 지정·강화 우선) |
| `F3` | 설정 창 |
| `F4` | 통째로 숨기기 (숨어 있어도 계산은 계속 돈다) |
| `F5` | 불투명도 |
| `F6` | 이동 모드 (커서를 따라오고, 다시 누르면 고정) |
| `F7` | 접기/펼치기 |
| `F8` | 자동 배치 (싱글플레이 한정) |

**접으면 정말 한 줄만 남는다.** 점수와 지금 옮길 것 하나뿐이고, 폭도 그 줄에 맞춰 줄어들며,
단축키 안내도 사라진다. 안내는 화면이 처음 뜰 때와 키를 누른 뒤 잠깐만 보인다. 게임 화면을
가리지 않는 것이 접는 이유이므로 접힌 상태에 무엇을 더 남기지 않는다.

**게임이 쓰지 않는 키만 고른다.** 게임은 수정키를 보지 않아서 `Ctrl+Alt+P` 같은 조합도 글자
키가 게임 조작을 함께 발동시킨다. F 키는 게임이 하나도 쓰지 않는다
([docs/RESEARCH.md](docs/RESEARCH.md) 의 "게임 단축키").

**설정은 `F3` 설정 창에서 바꾼다.** 켜고 끄기, 모서리, 크기, 폭, 불투명도, 후보 추천, 단축키가
거기 있다. **이 창만은 입력을 받는다** — HUD 의 무입력 원칙은 플레이 중 조작을 방해하지 않기
위한 것인데, 이 창은 플레이어가 일부러 연 것이라 그 이유가 걸리지 않는다. 게임의 `UIBase`를
상속해 컨트롤 스택에 올라가므로 **여는 동안 캐릭터 조작이 멈추고 ESC 로도 닫힌다** — 게임의 다른
창과 똑같이 행동한다.

**여는 동안 시간도 멈춘다**(싱글 한정, 게임의 `GameTimeManager`가 멀티에서는 스스로 거부한다).
게임에서 설정을 만지는 길은 ESC 일시정지 창을 거치는 것이라 그때는 시간이 이미 멈춰 있다.
우리 창만 시간이 흐르면 설정을 만지는 사이에 얻어맞는다.

게임 자체의 설정 창에 탭으로 붙이는 길은 만들어 보고 접었다. 그 창이 탭 다섯 개에 딱 맞게 짜여
있어 우리 탭이 들어갈 자리가 없고, 선택 표시가 탭 그림마다 박혀 있어 버튼을 옮기면 게임 탭들이
어긋난다. 잰 값은 [docs/RESEARCH.md](docs/RESEARCH.md) 에 남겼다.

같은 값이 BepInEx 설정의 `NativePanel` 절에도 있다. 어느 쪽으로 고쳐도 같은 자리를 읽고 쓴다.

**빌드 방향은 `F2` 빌드 창에서 고른다.** 설정 창과 같은 방식의 우리 창이고, 셋을 담는다.

- **프리셋 코드.** 게임에서 커스텀 로드아웃 코드를 복사한 뒤 "빌드 코드 붙여넣기"를 누르면
  클립보드에서 읽는다. 게임도 프리셋을 클립보드로 주고받으므로 입력 칸이 필요 없다. 그 빌드가
  즐겨찾기로 찍어 둔 아티팩트가 추천에서 올라가고, 과일 꼬치의 양수 카테고리는 아래 콤보 지정을
  대신 눌러 준다.
- **콤보.** 지금 걸려 있는 콤보가 `3 / 5` 처럼 다음 발동까지 몇 개 남았는지와 함께 나온다.
  누르면 밀고 있는 빌드로 지정(●)되어 그 콤보의 아티팩트와 진행을 추천에서 크게 친다.
- **아티팩트.** 가방에 있는 아티팩트를 눌러 강화 우선으로 지정한다. 지정하면 배치에서 가치를
  2배로 쳐 레벨 높은 칸을 먼저 받고, 격자에 ★ 로 표시된다.

목록은 여덟 줄씩 쪽으로 넘긴다. 누른다고 목록을 다시 정렬하지는 않는다 — 그러면 방금 누른 줄이
다른 것으로 바뀌어 연달아 누르다 엉뚱한 것을 지정하게 된다. 선택은
`%LOCALAPPDATA%\SephPlanner\plugin-settings.json`에 남는다.

**`F1` 로 후보를 미리본다.** 누를 때마다 다음 후보로 넘어가면서 그 후보를 집었을 때의 격자를
대신 그리고, 달라지는 칸을 금색 테두리로 짚는다. 마지막 다음은 미리보기 없음이라 한 키로 켜고
끈다. 솔버가 후보마다 이미 배치를 풀어 두므로 계산은 늘지 않는다. 무엇을 보고 있는지는 안내
줄에 늘 적힌다 — 미리보기 격자를 지금 배치로 착각하면 안 되기 때문이다. 후보를 가리키는 것은
번호가 아니라 후보의 열쇠라서, 계획이 다시 풀려 순서가 달라져도 보던 것을 계속 본다.

**칸이나 줄에 커서를 올리면 쪽지가 뜬다.** 아티팩트가 무슨 일을 하는지, 값어치를 어떻게 정했는지,
왜 꺼졌는지, 집으면 무엇이 빠지는지가 거기 있다. 오버레이가 툴팁으로 하던 일이고 문장도 같은
것을 쓴다(`SephPlanner.Core`의 `Explain`). **여기서도 입력은 가져가지 않는다** — 커서 좌표를
읽어 우리가 그린 사각형과 겹치는지 직접 세므로 `raycastTarget` 을 켜지 않는다. 펼쳤을 때만
뜬다. 접힌 화면은 곁눈질용 한 줄이라 그때 쪽지가 뜨면 플레이를 가린다.

## 원칙

- **쓰기는 자동 배치 하나뿐, 싱글플레이 한정.** 그 밖에는 게임 상태를 읽기만 한다. 멀티
  세션에서는 자동 배치도 잠긴다. 근거와 경위는 [docs/LEGAL.md](docs/LEGAL.md) 참고.
- **게임 저작물을 배포하지 않는다.** 데이터는 각자 PC의 게임 설치본에서 생성한다.
- **비영리.**

## 플러그인 설치

1. [BepInEx 5.4.23.5](https://github.com/BepInEx/BepInEx/releases) (win_x64, Mono)를 게임 폴더에 설치하고 한 번 실행한다.
2. `SephPlanner.Plugin.dll`과 `SephPlanner.Core.dll`을 `BepInEx/plugins/`에 넣는다.
3. 게임을 실행하면 석판/아티팩트 데이터가 `%LOCALAPPDATA%\SephPlanner\`에 덤프된다. F9로 다시 덤프할 수 있다.

인식이 이상한 아이템이 있으면 게임 안에서 F10을 누른다. 인벤토리 내용과 주변 선택지의 상태가
그대로 `%LOCALAPPDATA%\SephPlanner\inventory-dump.txt`에 기록된다.

단축키는 게임 창에 포커스가 있어야 먹는다. 그래서 **왜 어떤 선택지가 추천에 안 들어왔는지는
BepInEx 로그에 저절로 남는다.** 상태가 바뀔 때만 한 줄씩이다.

```
세피라이트 [NORMAL d=1818.5 gen=True acq=False n=5 active=True] -> 후보 5개
```

같은 폴더의 `query-verification.txt`에 질의 파서 검증 결과가 남는다. 불일치가 0이 아니면
솔버 결과를 믿을 수 없으므로 먼저 확인한다.

## 오버레이 실행

```powershell
dotnet run --project src/SephPlanner.Overlay -c Release
```

게임이 실행 중이면 자동으로 연결된다. 창은 끌어서 옮기고 Esc 또는 오른쪽 위 X로 닫는다.

게임 없이 화면만 확인하려면 `--preview`를 붙인다. 가짜 스냅샷으로 전체 UI가 채워져 뜨고,
파이프를 열지 않으므로 실제 오버레이와 같이 떠 있어도 서로 방해하지 않는다.

```powershell
dotnet run --project src/SephPlanner.Overlay -- --preview
```

XAML 은 컴파일 때 검증되지 않아 빌드가 성공해도 창이 안 뜰 수 있다(없는 리소스를 참조하면
로드에서 터진다). 프로세스만 보면 그 상태를 놓치므로, 보이는 창이 있는지까지 확인한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-overlay-window.ps1
```

화면은 게임 자체 UI의 문법을 따른다. 색은 게임 패널(가방·콤보 효과·스킬)에서 채집했고
글꼴은 [Galmuri](https://github.com/quiple/galmuri) 픽셀 폰트다(OFL-1.1, 라이선스는
`src/SephPlanner.Overlay/Fonts/LICENSE.txt`에 동봉). 값은 전부 `Theme.cs` 한곳에 있다.

오버레이는 **접힌 상태와 펼친 상태** 두 가지로 쓴다. 읽는 방식이 달라서 나눴다.

- **접힘.** 플레이 중에는 화면을 거의 가리지 않는다. 현재 점수와 최적 배치 점수, 그리고 지금
  옮길 것 하나만 보여준다.
- **펼침.** 상자나 상점이 열리거나 세피라이트를 여는 순간 저절로 펼쳐지고, 닫히면 되돌아간다.
  격자에 칸마다 놓일 아이템 이름과 레벨이 나오고, 무엇을 어디로 옮길지와 지금 집을 수 있는
  후보가 줄 세워진다.

**이동 목록은 위에서부터 그대로 따라 하면 된다.** 두 물건이 자리를 맞바꿔야 하면 목표 칸이 이미
차 있어 그냥은 옮길 수 없으므로, 한쪽을 빈 칸으로 "잠시 비켜두기" 하는 걸음을 끼워 넣는다.
하나 옮길 때마다 목록이 다시 계산되어 남은 걸음만 줄어든다.

**싱글플레이에서는 "자동 배치" 버튼이 함께 뜬다.** 누르면 제안된 배치가 게임에 그대로 적용된다.
게임이 수동 드래그에 쓰는 이동 경로를 그대로 타므로 손으로 옮긴 것과 결과가 같다. 계산 이후
인벤토리가 바뀌었으면 아무것도 건드리지 않고 물러서고, 적용 도중 실패하면 이미 옮긴 걸음을
역순으로 되돌린다. 결과와 이유는 오버레이에 한 줄로 표시되고 BepInEx 로그에도 남는다. 멀티
세션에서는 버튼이 나타나지 않는다([docs/LEGAL.md](docs/LEGAL.md)).

**후보 순위는 참고용이다.** 목록 위에 그렇게 적어 둔다. 자리 배치와 점수 증가분은 게임이
계산해 둔 레벨에서 나오지만, 아티팩트가 실제로 얼마나 센가는 게임 데이터만으로 다 잴 수 없기
때문이다. 능력치를 주는 아티팩트는 레벨별 능력치 표에서 값어치를 재고, 고유 효과에만 값어치가
있는 아티팩트는 레어도로 어림잡는다. 지금 보이는 후보 중 몇 개가 어림값인지 함께 적고, 어느
쪽인지는 후보에 마우스를 올리면 나온다. 남은 몫은 [docs/ROADMAP.md](docs/ROADMAP.md) 참고.

**후보에는 점수 증가분과 함께 그 석판이 미치는 범위를 적는다.** `6칸 +6` 처럼 읽으면 된다.
아티팩트가 적을 때는 서로 다른 석판이 똑같은 증가분으로 보이는데, 그때 무엇이 다른지는 범위가
알려준다. 증가분이 같으면 여력이 큰 쪽을 위로 올린다. 살 수 없는 것은 지우지 않고 아래로 내린다.

**빌드를 밀 수 있다.** 펼친 화면 아래 "빌드 우선"에 지금 모은 콤보들이 칩으로 나온다. 눌러서
지정하면(●) 그 콤보의 아티팩트와 진행을 추천에서 크게 치고, 목록에서 민트색으로 표시한다.
다시 누르면 풀린다. 선택은 오버레이를 껐다 켜도 유지된다. 칩에 마우스를 올리면 임계값마다
무슨 효과가 발동하는지 보여준다.

**후보는 화면에 보일 때만 뜬다.** 상자는 연 뒤에, 상점은 상점 창을 연 뒤에 후보가 된다.
가까이 가기만 해도 재고가 보이면 손으로는 할 수 없는 일이 되기 때문이다
([docs/RESEARCH.md](docs/RESEARCH.md) 의 "선택지 감지").

**가방이 차 있으면 무엇을 빼야 하는지 알려준다.** 후보의 증가분에는 자리를 내줄 아이템의
손해가 이미 계산돼 있고, 후보에 마우스를 올리면 "집으면 빠지는 것"으로 그 이름이 나온다.

**특정 아티팩트를 강화 우선으로 지정할 수 있다.** 격자의 아티팩트 칸을 우클릭하면 ★ 표시와
함께 그 아티팩트의 가치를 2배로 쳐서, 배치에서 레벨 높은 칸을 먼저 받는다. 점수도 그 기준으로
계산되므로 지정을 바꾸면 점수가 달라질 수 있다. 조화의 수정처럼 효과가 이웃 칸에 달린
아티팩트를 좋은 자리에 두고 싶을 때 쓴다. 같은 종류의 아이템에 계속 적용되며 우클릭으로 푼다.

**아티팩트 후보에는 콤보 진행이 함께 뜬다.** `잉걸불 7/8`은 이걸 집으면 잉걸불 콤보가 7개가
되고 다음 발동까지 8개가 필요하다는 뜻이다. 임계값에 닿아 콤보가 발동하는 후보는 초록으로
표시되고 줄 세우기에서도 위로 올라간다. 콤보 개수는 게임이 세어 둔 값을 그대로 쓰므로
(위치·레벨과 무관) 유니크 페어 같은 특수 규칙도 반영돼 있다. 이 표시는 게임을 한 번 실행해
데이터를 새로 덤프(F9)한 뒤부터 나온다.

`Ctrl+Alt+I`로 직접 접고 펼 수 있다. 게임에 포커스가 있어도 동작한다. 직접 접거나 펼친 상태는
상자·상점이 다시 열리거나 닫힐 때까지 유지된다. `Ctrl+Alt+O`는 오버레이를 통째로 숨겼다가
다시 보여준다(숨어 있어도 계산은 계속 돈다). 제목에 마우스를 올리면 단축키 안내가 나온다.

**추천은 끌 수 있다.** 배치(정렬)는 손으로도 할 수 있는 일의 대행이지만, 무엇을 집을지에 대한
조언은 판단을 빌려주는 것이라 난이도에 영향을 준다. 도전을 지키고 싶으면 범례 줄의 "추천 끄기"
버튼으로 후보 목록과 빌드 우선을 끈다. 끄면 화면에서 가리는 게 아니라 계산 자체를 하지 않고,
상자·상점이 열려도 저절로 펼쳐지지 않는다. 점수·격자·이동 목록·자동 배치는 그대로 남는다.

**격자와 후보 목록은 아이콘으로도 볼 수 있다.** 범례 줄의 버튼으로 아이콘/글자 모드를 오간다.
아이콘은 F9 덤프 때 각자 PC에 생성되며(배포물에는 없다), 아직 없는 항목은 글자로 나온다.
아이콘 모드에서 이름은 마우스를 올리면 보인다.

옮겨야 하는 칸은 노란 테두리로 강조된다. 효과가 꺼진 아티팩트는 `꺼짐`으로 표시하고, 칸에
마우스를 올리면 왜 꺼졌는지(무기 불일치, 석판이 막은 칸, 음수 레벨, 배치 조건) 알려준다.

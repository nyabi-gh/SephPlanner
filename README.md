# SephPlanner

세피리아(Sephiria)용 비공식 컴패니언. 현재 인벤토리를 읽어 더 나은 석판 배치를 탐색하고, 지금
상황에서 어떤 아티팩트를 고르는 게 좋은지 알려준다. **게임 안에 직접 그린다** — 게임을 켜면
플러그인이 저절로 올라오고, 따로 실행할 것이 없다.

TEAM HORAY와 무관한 팬 제작 도구이며, 비영리로 배포한다.

## 추천과 아이템 배치

추천은 아이템의 능력치·강화 단계·콤보와 사용자가 지정한 강화 우선·양보를 함께 고려한다.
화면의 점수는 배치를 비교하기 위한 평가값이며, 반영하지 못한 고유 효과는 추정값을 사용한다.
`F2`에서 콤보와 아티팩트의 우선순위를 지정하고 `F8`로 추천 배치를 적용한다.

- 대립의 천칭은 현재 놓인 쪽을 유지한다. 왼쪽은 1~3열, 오른쪽은 4열 이후이며 같은 쪽 안에서는 이동할 수 있다. 방향을 바꾸려면 직접 반대쪽으로 옮긴다.
- 마음의 짐처럼 자체 활성 효과가 없는 아이템은 감점 칸을 활용할 수 있다. 주변 효과와 명시한 사용 유지·고정은 계속 고려한다.
- 버릴 수 없는 아티팩트는 제외·교체 추천에서 보호한다. `F8`은 아이템을 버리지 않는다.
- 친타마니 돌이 발동한 뒤 남기는 칸 레벨 보너스는 원래 좌표에 적용한다. 그 칸의 아이템을 옮겨도 보너스는 따라가지 않는다.

현재 구현과 검증 범위는 [현재 상태](docs/STATUS.md), 버전별 수정 사항은 [변경 기록](CHANGELOG.md)을 참고한다.

## 구조

```
SephPlanner.Core      게임 상태 모델 + 솔버와 배치 계산 (netstandard2.1)
SephPlanner.Plugin    BepInEx 플러그인. 게임 상태를 읽어 배치를 풀고 게임 HUD 안에 직접
                      그린다. 멀티 세션의 자동 배치는 설정으로 연다(실험)
SephPlanner.DataTool  게임 없이 도는 CLI. 텍스트 추출, 스냅샷 대조, 콤보·아티팩트 값어치 측정
SephPlanner.Tests     Core 단위 테스트. 게임 없이 돈다
```

## 빌드

게임이 설치돼 있어야 한다. 기본 경로가 아니면 환경변수로 알려준다.

```powershell
$env:SEPHIRIA_DIR = "D:\SteamLibrary\steamapps\common\Sephiria"
dotnet build
```

일반 빌드는 게임 폴더를 변경하지 않는다. 빌드 결과를 설치된 게임에 복사하려면 명시적으로 배치한다.

```powershell
scripts/deploy-plugin.ps1
```

테스트는 게임 없이 돈다.

```powershell
dotnet test
```

밀기 전에는 이것 하나면 된다. 포맷·테스트에 더해 **플러그인 빌드까지** 세운다.

```powershell
scripts/check.ps1
```

마지막 항목이 따로 필요한 이유가 있다. CI 는 `SephPlanner.Core`, 진단 도구와 테스트를 검사한다. 플러그인은
게임 어셈블리를 참조하는데 그것을 저장소나 CI 에 둘 수 없기 때문이다(docs/LEGAL.md). 그래서
**플러그인만 깨지는 변경은 CI 를 초록으로 통과한다.** 릴리스 스크립트가 결국 잡아내지만, 그때는
이미 배포를 자르는 중이다.

게임 안에서 F10을 누르면 그 순간의 상태가 `%LOCALAPPDATA%\SephPlanner\inventory-snapshot.json`
으로 남는다. 그 스냅샷으로 우리 레벨 계산이 게임 값과 맞는지 게임 없이 다시 볼 수 있다. 어긋나는
칸이 있으면 아직 읽지 않는 효과(각인, 세트 효과, 배치 보너스)가 걸려 있다는 뜻이다. 제보를 받을
때 이 파일로 레벨을 대조할 수 있다. 당시 설정과 카탈로그까지 필요한 계획 재현에는 아래 재현 자료를 쓴다.

F10은 마지막으로 게시된 계획의 입력·빌드 설정·직전 목표·당시 카탈로그를
같은 데이터 폴더의 `reproductions/<시각>-<식별자>.replay`에 함께 저장한다.
계산 중이라면 마지막 게시 계획이므로 F10 순간의 새 스냅샷과 다를 수 있다.
아직 게시된 계획이 없으면 재현 자료는 만들지 않고 안내한다.

**진단 전송을 켰으면 F10이 메모 창을 먼저 연다.** 자료만으로는 무엇이 이상했는지 알 수 없기
때문이다. 증상을 골라 한 번 누르고 끝내도 되고 직접 적어도 된다. **`Enter` 가 보내기, `ESC` 가
취소다** - 취소해도 수집한 자료는 이 PC에 그대로 남고 서버로만 가지 않는다. 비워 둔 채 보내는
것이 곧 메모 없이 보내기다. 적은 그대로 가며 우리가 가리지 않으므로 아이디나 비밀번호 같은
것은 적지 않는다. 아직 전송에 동의하지 않았다면 동의를 먼저 묻고 그다음에 메모를 받으며,
로컬에만 저장하는 상태에서는 아예 묻지 않는다.

```powershell
dotnet run --project src/SephPlanner.DataTool -c Release -- --reproduce "<파일.replay>"
# 계산 코드를 바꾼 뒤 같은 입력으로 비교할 때
dotnet run --project src/SephPlanner.DataTool -c Release -- --reproduce "<파일.replay>" --allow-model-change
```

재현은 파일에 포함된 카탈로그만 사용하며 파일 손상·지원하지 않는 형식·빠진 설정은 실패로 알린다.
계산 빌드가 다르면 명시적인 비교 옵션이 필요하다. 종료 코드는 일치 0, 입력·실행 실패 1, 결과 차이 2다.
게임 데이터가 포함된 로컬 진단 자료이므로 저장소·릴리스·공개 제보에 첨부하지 않는다.
자세한 비교 범위는 [계획 재현](docs/REPRODUCTION.md), 현재 개발 상태는 [현재 상태](docs/STATUS.md)에 있다.

```powershell
dotnet run --project src/SephPlanner.DataTool -- --check %LOCALAPPDATA%\SephPlanner\inventory-snapshot.json
```

같은 스냅샷으로 `F8` 을 연달아 누르는 것을 흉내 낸다. 계획대로 옮기고, 게임이 다시 셀 레벨과
콤보 개수를 우리 셈으로 채운 뒤 다시 푼다. 적용한 뒤에도 계획이 또 바뀌면 그 이유가 여기서
드러난다 - 실제로 침 둘이 두 콤보 사이를 오가며 `F8` 마다 6~7수를 내던 판을 이것으로 잡았다.

```powershell
dotnet run --project src/SephPlanner.DataTool -- --churn %LOCALAPPDATA%\SephPlanner\inventory-snapshot.json
```

콤보 한 단계가 아티팩트 레벨 몇 개 값어치인지 잰다. `Worth`의 상수를 짐작으로 두지 않기 위한
것이며, 게임을 한 번 켜서 카탈로그를 다시 덤프한 뒤에 돌아간다(방법은 docs/RESEARCH.md 참고).

```powershell
dotnet run --project src/SephPlanner.DataTool -- --measure
```

아티팩트 하나하나의 값어치가 어디까지 측정됐는지 보고, 아직 레어도 어림값에 기대고 있는 것들을
손으로 채울 초안으로 뽑는다. 채우는 법은 [data/values/README.md](data/values/README.md) 참고.

**레벨이 올라도 값어치가 내려가는 아티팩트도 함께 적는다.** 그런 구간이 있으면 낮은 레벨 칸이
정답이 되어 "왜 이걸 낮은 자리에 두느냐"는 제보가 온다. 원인이 된 능력치와 그 수치 변화까지
적으므로 환산율을 어디서 다시 재야 하는지가 바로 나온다.

```powershell
dotnet run --project src/SephPlanner.DataTool -- --values
```

데이터 추출:

```powershell
dotnet run --project src/SephPlanner.DataTool
# -> data/generated/text.json  (석판 68종, 아티팩트 257종, 15개 언어)
```

`data/generated/`는 각자 PC에서 생성되며 저장소에 커밋하지 않는다. 이유는 [docs/LEGAL.md](docs/LEGAL.md) 참고.

## 배포

```powershell
scripts/make-release.ps1
# -> artifacts/SephPlanner-v{버전}.zip
```

배포물에는 플러그인 DLL 두 개와 BepInEx 5.4.23.5(win_x64, Mono), 설치 안내와 라이선스가
들어간다. 릴리스 전에 포맷, 테스트, 빌드를 검증하고 커밋과 파일 해시가 적힌 `manifest.json`을
만든다. 게임 파일은 넣지 않는다.

zip은 릴리스 전용 공개 저장소 [nyabi-gh/SephPlanner-Release](https://github.com/nyabi-gh/SephPlanner-Release)의
Releases에 올린다. 이 저장소는 비공개라 여기 Releases는 링크가 공개되지 않는다. 그쪽에는 소스
없이 zip과 Issues(제보 창구)만 둔다. 변경 기록은 이 저장소의 CHANGELOG.md가 정본이고, 릴리스
본문은 `make-release.ps1`이 그 절을 그대로 뽑아 `artifacts/release-notes-v{버전}.md`로 내준다 -
손으로 옮겨 적지 않는다. 두 벌이 되면 한쪽만 고친 채 나가기 때문이다. 커뮤니티 글에는 그
링크를 걸고 zip을 직접 첨부하지 않는다 - 첨부하면 옛 버전이 돌아다닌다.

**태그를 먼저 달고 zip을 만든다.** manifest에 적히는 커밋이 곧 태그가 가리켜야 할 커밋이라,
나중에 달면 zip을 만든 커밋과 태그가 갈라져 어느 소스에서 나온 zip인지 되짚을 수 없다.
`make-release.ps1`이 HEAD에 `v{버전}` 태그가 없으면 멈추고, `[BepInPlugin]`의 버전과
CHANGELOG의 해당 절도 함께 확인한다.

## 인게임 화면

**여기가 본체다.** 플러그인이 게임 HUD 캔버스 안에 직접 그린다. 별도 창이 아니라 게임 UI 의
일부라 전용 전체화면에서도 보이고, 글꼴과 아이콘을 게임에서 빌려 쓴다. 크기는 게임 HUD 글자
크기에 대한 비율이라 해상도와 UI 배율을 따라간다. 게임만 켜면 저절로 올라온다.

**마우스와 키보드를 하나도 가져가지 않는다.** 그리는 것마다 `raycastTarget` 이 꺼져 있고
컨트롤 스택에도 들어가지 않는다. 그래서 누를 것이 없고 조작은 전부 단축키다. 커서 위치는
읽지만(이동 모드와 쪽지) 읽기만 하는 것이라 게임에서 가져가는 입력은 없다.

| 키 | |
|---|---|
| `F1` | 후보 미리보기 (차례로 돌고, 마지막 다음은 미리보기 없음) |
| `F2` | 빌드 창 (프리셋 코드·콤보 지정·강화 우선) |
| `F3` | 설정 창 |
| `F4` | 통째로 숨기기 (숨어 있어도 계산은 계속 돈다) |
| `F5` | 불투명도 |
| `F6` | 이동 모드 (커서를 따라오고, 다시 누르면 고정) |
| `F7` | 접기/펼치기 |
| `F8` | 자동 배치 적용 (멀티는 설정에서 연 뒤) |
| `F9` | 석판·아티팩트 데이터 다시 만들기 (게임 패치 뒤에 한 번) |
| `F10` | 진단 덤프 — 인벤토리 상태와 재생용 스냅샷을 파일로. 전송을 켰으면 메모를 함께 남길 수 있다 |

**기본값은 게임이 쓰지 않는 키로 고른다.** 게임은 수정키를 보지 않아서 `Ctrl+Alt+P` 같은 조합도 글자
키가 게임 조작을 함께 발동시킨다. F 키는 게임이 하나도 쓰지 않는다
([docs/RESEARCH.md](docs/RESEARCH.md) 의 "게임 단축키").

### 접힘과 펼침

읽는 방식이 달라서 둘로 나눴다.

- **접힘.** 플레이 중에는 화면을 거의 가리지 않는다. 현재 점수와 탐색한 배치 점수, 그리고 지금
  옮길 것 하나만 보여준다.
- **펼침.** 상자나 상점이 열리거나 세피라이트를 여는 순간 저절로 펼쳐지고, 닫히면 되돌아간다.
  격자에 칸마다 놓일 아이템과 레벨이 나오고, 무엇을 어디로 옮길지와 지금 집을 수 있는 후보가
  줄 세워진다. 직접 접거나 펼친 상태는 상자·상점이 다시 열리거나 닫힐 때까지 유지된다.

**접으면 정말 한 줄만 남는다.** 점수와 지금 옮길 것 하나뿐이고, 폭도 제한되며,
단축키 안내도 사라진다. 안내는 화면이 처음 뜰 때와 키를 누른 뒤 잠깐만 보인다. 게임 화면을
가리지 않는 것이 접는 이유이므로 접힌 상태에 무엇을 더 남기지 않는다.

예외는 경고다. 점수를 믿을 수 없거나 멀티 세션이라는 것처럼 **모르고 넘어가면 안 되는 것**은
접혀 있어도 뜨고, 접힌 폭에 맞춰 여러 줄로 접힌다. 자동 배치가 도는 동안 뜨는 진행 표시도
그렇다.

### 배치를 따라가기

**이동 목록은 위에서부터 그대로 따라 하면 된다.** 목표 칸에 다른 물건이 있으면 `↔ 교환`으로
안내한다. 게임에서 두 칸을 드래그로 맞바꾸면 되므로 가방이 꽉 차 있어도 빈 칸은 필요 없다.
회전은 교환을 마친 최종 자리에서 안내한다. 옮길 때마다 현재 가방을 읽어 목록을 다시 계산한다.

**기본 배치는 아티팩트의 활성을 보존한다.** 이득과 패널티를 합친 점수가 음수여도 정상 칸을 두고
효과를 끄지 않는다. 주력 강화를 위해 효과를 꺼도 되는 아이템은 F2에서 `끄기 허용`으로 지정한다.
`양보`는 강화 칸만 양보하며, `사용 유지`는 끄기 허용보다 우선하고 빼기·교체 추천에서도 보호한다.

같은 필수 조건과 효과에서는 감점·비활성 효과가 없는 빈칸을 더 확보하고, 상한을 넘겨 낭비하는
강화와 이동을 차례로 줄인다. 경쟁의 감점을 밖으로 빼더라도 실제 강화가 줄어들면 무조건 옮기지 않는다.
화면 점수에는 이동 비용을 섞지 않으며 활성 복구는 `활성 보존 우선`, 같은 효과의 감점 정리는
`감점 칸 정리`로 알린다. 탐색한 후보 중 최선이며 모든 가방의 전역 최적해를 보장하지 않는다.
평가 순서와 검증 범위는 [배치 평가 설계](docs/PLACEMENT-OBJECTIVE.md)에 정리했다.

**옮겨야 하는 칸은 금색 테두리로 짚는다.** 효과가 꺼진 아티팩트는 `꺼짐`으로 표시하고, 칸에
커서를 올리면 왜 꺼졌는지(무기 불일치, 석판이 막은 칸, 음수 레벨, 배치 조건) 알려준다. 칸에
적히는 숫자는 그 칸의 레벨이 아니라 거기 놓인 아티팩트가 실제로 받는 레벨이고, 상한에 걸려
흘리는 레벨이 있으면 색으로 알린다.

**`F8`을 누르면 그 배치를 게임에 적용한다.** 게임이 수동 드래그에 쓰는 이동 경로를 그대로
타므로 손으로 옮긴 것과 결과가 같다. 계산 이후 인벤토리가 바뀌었으면 아무것도 건드리지 않고
물러선다. 회전 가능 여부까지 쓰기 전에 확인하고, 적용 도중 실패하면 반영이 확인된 걸음을 역순으로 되돌린다. 결과와 이유는 화면에 한 줄로
뜨고 BepInEx 로그에도 남는다.

참가자의 명령이 시간 안에 확인되지 않으면 거부된 것인지 늦게 도착할 것인지 알 수 없다. 이때는
추가 이동·되돌리기를 보내지 않고 자동 배치를 잠근다. 방에 재접속하면 다시 사용할 수 있다.
마지막 위치와 회전이 목표와 같은지도 확인하며, 도중에 사용자가 바꾼 칸에는 되돌리기를 강행하지 않는다.

**멀티 세션에서는 기본으로 잠긴다.** 설정에서 열 수 있지만 실험이고(`멀티 자동 배치(실험)`),
켜면 **방을 연 쪽이든 참가한 쪽이든 동작한다.** 참가자 세션에서는 게임이 클라이언트에게 열어 둔
길(이동은 `CmdSwap`, 회전은 우클릭이 타는 `DoClickAction`)로 서버에 보내는데, 왕복이라 곧바로
반영되지 않으므로 걸음마다 반영을 확인하고 나서 다음 걸음으로 간다. 그래서 옮길 것이 많으면
호스트보다 몇 초 더 걸리고, 반영이 확인되지 않으면 거기서 멈추고 재접속을 안내한다. **도는 동안에는 몇 번째
걸음인지가 안내 줄에 뜨고**, 앞으로 가는 데도 되돌리는 데도 각각 30초 상한이 있어 서버가 조용해도
거기서 끝난다. 개발사가 금지한 것은 아니고
인벤토리 동기화 구현을 바꾸는 중이라 잠가 두는 편이 안전하다고 답했으므로 기본을 꺼
두었다([docs/LEGAL.md](docs/LEGAL.md)). 공식 FAQ 가 멀티 모드를 "참가자 전원 동의" 조건으로
두므로, 켤 때는 같이 하는 사람의 동의를 받는다.

설정에서 모서리를 바꾸면 새 모서리의 기본 안전 여백으로 이동한다. `F6`으로 직접 옮긴 위치는
화면 밖으로 나가지 않는 범위에서 저장된다.

### 무엇을 집을지

**후보 순위는 참고용이다.** 목록 위에 그렇게 적어 둔다. 자리 배치와 점수 증가분은 게임이
계산해 둔 레벨에서 나오지만, 아티팩트가 실제로 얼마나 센가는 게임 데이터만으로 다 잴 수 없기
때문이다. 능력치를 주는 아티팩트는 레벨별 능력치 표에서 값어치를 재고, 고유 효과에만 값어치가
있는 아티팩트는 레어도로 어림잡는다. 지금 보이는 후보 중 몇 개가 어림값인지 함께 적고, 어느
쪽인지는 후보에 커서를 올리면 나온다. 남은 몫은 [docs/ROADMAP.md](docs/ROADMAP.md) 참고.

능력치 표가 있어도 전환·해금 같은 효과를 환산하지 못했다면 전체 가치로 취급하지 않는다.
이때는 측정값과 레어도 어림값 중 큰 쪽을 사용하고 툴팁에 일부만 측정됐다고 표시한다.
이는 누락된 효과를 0점으로 단정하지 않기 위한 추정이며, 실제 전투 효율을 측정한 값은 아니다.

**후보는 화면에 보일 때만 뜬다.** 상자는 연 뒤에, 상점은 상점 창을 연 뒤에 후보가 된다.
가까이 가기만 해도 재고가 보이면 손으로는 할 수 없는 일이 되기 때문이다
([docs/RESEARCH.md](docs/RESEARCH.md) 의 "선택지 감지").

**상점의 사파이어 보충 칸도 함께 읽는다.** 게임이 그것을 상점 재고가 아니라 상인의 별도 목록에
두기 때문에 전에는 통째로 빠져 있었다. 적히는 값은 상점 물건과 같은 골드다 — 사파이어는 칸을
굴리는 값이지 물건 값이 아니라서, 리롤을 더 돌릴지는 알려주지 않는다.

**후보에는 점수 증가분과 함께 그 석판이 미치는 범위를 적는다.** `6칸 +6` 처럼 읽으면 된다.
아티팩트가 적을 때는 서로 다른 석판이 똑같은 증가분으로 보이는데, 그때 무엇이 다른지는 범위가
알려준다. 증가분이 같으면 여력이 큰 쪽을 위로 올린다. 살 수 없는 것은 지우지 않고 아래로 내린다.

**아티팩트 후보에는 콤보 진행이 함께 뜬다.** `잉걸불 7/8`은 이걸 집으면 잉걸불 콤보가 7개가
되고 다음 발동까지 8개가 필요하다는 뜻이다. 임계값에 닿아 콤보가 발동하는 후보는 초록으로
표시되고 줄 세우기에서도 위로 올라간다. 콤보 개수는 게임이 세어 둔 값을 그대로 쓰므로
(위치·레벨과 무관) 유니크 페어 같은 특수 규칙도 반영돼 있다. 이 표시는 게임을 한 번 실행해
데이터를 새로 덤프(`F9`)한 뒤부터 나온다.

**가방이 차 있으면 무엇을 빼야 하는지 알려준다.** 후보의 증가분에는 자리를 내줄 아이템의
손해가 이미 계산돼 있고, 후보에 커서를 올리면 "집으면 빠지는 것"으로 그 이름이 나온다.

**새로 집을 것이 없어도 하나를 빼는 편이 나으면 검토 후보를 보여준다.** 펼친 화면의
`하나 빼기 검토`에 아티팩트·석판 하나를 제외한 뒤 재배치하는 추정 이득을 최대 세 개까지
표시한다. 콤보 단계가 유지되는 후보만 다루며, 개수가 줄면 툴팁에 알린다. F8은 아이템을
제거하지 않는다. 직접 가방에서 뺀 뒤 새 배치를 확인하고 적용한다. 후보 추천을 끄면 이 계산도
생략된다. 제한된 배치 후보에서 비교하므로 가능한 모든 제거 조합의 최적해는 아니다.

자물쇠처럼 양옆이 비어야 하는 아티팩트는 본체와 빈칸 두 곳을 함께 확보하는 배정도 탐색한다.
현재 가방에 빈칸이 부족하면 재배치만으로 켤 수 없으며, 제외 검토는 이 경우에도 도움이 된다.

**합성기가 있으면 어느 석판 둘을 합칠지도 권한다.** 합친 상태로 배치를 다시 풀어 증가분을
보므로, 재료 둘이 없어지는 것까지 들어가 있다. 합성기에 넣기 전에 맞춰 두어야 하는 회전도
함께 적는다.

### 후보 미리보기 (`F1`)

누를 때마다 다음 후보로 넘어가면서 그 후보를 집었을 때의 격자를 대신 그리고, 달라지는 칸을
금색 테두리로 짚는다. 마지막 다음은 미리보기 없음이라 한 키로 켜고 끈다. 솔버가 후보마다 이미
배치를 풀어 두므로 계산은 늘지 않는다. 점수에도 `미리보기`가 표시되고 현재 점수와 후보 배치의
점수를 비교한다. 현재 가방의 이동 안내는 숨긴다. 이 상태에서 `F8`은 미리보기를 종료하며,
돌아온 배치를 확인하고 다시 눌러야 자동 배치를 실행한다. 후보를 가리키는 것은 번호가 아니라 후보의
열쇠라서, 계획이 다시 풀려 순서가 달라져도 보던 것을 계속 본다.

### 쪽지 (커서를 올리면)

아티팩트가 무슨 일을 하는지, 값어치를 어떻게 정했는지, 왜 꺼졌는지, 집으면 무엇이 빠지는지가
거기 있다. 격자 칸과 후보·합성 줄에 뜬다. **여기서도 입력은 가져가지 않는다** — 커서 좌표를
읽어 우리가 그린 사각형과 겹치는지 직접 세므로 `raycastTarget` 을 켜지 않는다. 펼쳤을 때만
뜬다. 접힌 화면은 곁눈질용 한 줄이라 그때 쪽지가 뜨면 플레이를 가린다.

### 빌드 창 (`F2`)

밀고 있는 빌드를 여기서 고른다. 셋을 담는다.

상단 `빌드 초기화`는 가져온 빌드 코드와 직접 지정한 콤보·강화 우선·양보·사용 유지·고정을
한 번에 해제한다. 현재 가방에 없는 아이템의 지정도 지우며 F3의 단축키·화면 설정은 유지한다.
`지우기`는 가져온 빌드 코드만 제거할 때 사용한다.

- **프리셋 코드.** 게임에서 커스텀 로드아웃 코드를 복사한 뒤 "빌드 코드 붙여넣기"를 누르면
  클립보드에서 읽는다. 게임도 프리셋을 클립보드로 주고받으므로 입력 칸이 필요 없다. 그 빌드가
  즐겨찾기로 찍어 둔 아티팩트는 후보로 뜨기만 하면 맨 위로 올라가고(줄에 `빌드`라고 적힌다,
  살 수 있는 것 다음 순서), 과일 꼬치의 양수 카테고리는 콤보 우선순위에 포함한다.
  프리셋을 교체·삭제하면 그 프리셋의 우선순위도 바뀌며 수동 지정은 유지된다. 가져온 콤보도 눌러
  끌 수 있다. 회피 콤보는 추천에 미반영임을 표시한다. 구버전 설정은 출처를 구분할 수 없어
  기존 우선순위를 보존한다. 설정 저장 실패는 빌드 창에 표시하며 손상된 원본은 덮어쓰기 전에 백업한다.
- **콤보.** 지금 걸려 있는 콤보가 `3 / 5` 처럼 다음 발동까지 몇 개 남았는지와 함께 나온다.
  누르면 밀고 있는 빌드로 지정(●)되어 그 콤보의 아티팩트와 진행을 추천에서 크게 치고, 후보
  목록에서 민트색으로 표시한다. 지정한 것은 HUD 아래 콤보 줄에도 점으로 표시된다.
  **열쇠·하얀 종이·북향의 침 배치에도 적용된다.** 선택이 없으면 기존 가치 기준으로 배치하고, 선택하면
  지정 콤보를 제공하는 배치를 먼저 늘린다. 여러 콤보를 선택하면 콤보 진행·발동, 기존
  배치 가치 순으로 비교한다. 콤보를 이미 끝까지 채웠어도 선택은 유지되며, 후보 추천을 꺼도
  배치에는 적용된다. 가진 열쇠의 다른 행 콤보는 현재 0개여도 선택할 수 있다.
  종이는 양옆 아이템을 함께 옮기고 필요하면 석판과도 교환한다. 기존 제한 해제 칸 고정은
  우선 보존한다. 탐색에서 조건을 만족하는 배치를 찾지 못하면 가능한 배치를 제안하고 이유를
  안내한다. 지정 때문에 일반 점수가 낮아질 수 있으며 이때는 `지정 콤보 우선`으로 표시한다.
- **아티팩트.** 가방에 있는 아티팩트를 눌러 강화 우선으로 지정한다. **누를 때마다 세기가
  올라간다** — `★` 2배, `★★` 4배, `★★★` 10배, 한 번 더 누르면 풀린다. 지정하면 배치에서
  이득을 그 배수로 쳐 좋은 칸을 먼저 받고, 격자에 ★ 로 표시된다(몇 단계인지는 칸에 커서를
  올리면 나온다). **우클릭은 반대로 내린다** — `▽` 0.5배, `▽▽` 0.25배, `▽▽▽` 0.1배, 한 번 더
  누르면 풀린다. 가방이 좁을 때 "이건 양보해라"를 말하는 길이다. 어느 쪽이든 0 을 지나면 풀리므로
  ★ 에서 우클릭하면 해제이지 ▽ 가 아니다.

  배수는 능력치와 이웃 효과의 이득에 적용하며, 패널티는 배수와 무관하게 그대로 반영한다.
  ★는 선호도이므로 활성 상태를 보장하지 않는다. **`사용 유지`를 켜면 소유한 같은 종류의
  아티팩트 전부를 활성 상태로 유지하는 배치를 우선한다.** 빼기·교체 추천에서도 보호하며,
  다른 아이템이나 석판을 바꿔 간접적으로 꺼뜨리는 추천도 제외한다. 조건을 만족하는 배치를
  찾지 못하면 이유를 표시하고 자동 배치를 실행하지 않는다. 무기 연동 등은 배치로 풀 수 없다.
  빛나는 모래시계는 바로 오른쪽의 사용 가능한 마법과 연결된 상태까지 확인한다. 모래시계와
  마법을 함께 옮기는 배치를 검토하며, 연결이 없으면 강화 효과를 점수에 넣지 않는다.
  강화 가치는 대상 마법과 회복 속도를 기준으로 한 추정이며 실제 시전 빈도나 마나 상황과 다를 수 있다.

  **줄 오른쪽의 `고정`은 제한 해제 칸 고정이다.** 누르면 그 아티팩트를 배치 조건을 무시하는 칸
  (제한 해제 석판이 만드는 칸)에만 앉힌다. 자물쇠처럼 조건이 까다로운 아티팩트는 빈 칸이 많을 때
  양옆을 비우는 공짜 자리로 갔다가 가방이 차면 옮겨 다니는데, 고정하면 석판이 계속 제약을 풀어
  준다. 칸에 못 박는 것이 아니라 효과에 붙이는 것이라 석판을 옮겨도 따라간다. 그런 칸이 모자라면
  계획을 포기하지 않고 그 고정만 무시하며 경고 한 줄로 알린다.

  **줄 오른쪽의 `레벨 제한`은 그 레벨까지만 값으로 치라는 뜻이다.** 누르면 1, 2, 3… 으로 올라가고
  우클릭으로 내린다(상한과 같은 제한은 제한이 아니라 그 직전까지만 돈다). 제한을 걸면 **남는 높은
  칸이 다른 아티팩트에게 돌아간다** — "이건 3레벨이면 충분하다"를 ★ 로는 말할 수 없기 때문이다
  (★ 는 누가 좋은 칸을 먼저 갖느냐이지 얼마나 높은 칸이냐가 아니다). 게임에는 레벨을 직접
  올리는 행동이 없고 칸이 레벨을 정하므로, 이 제한은 실제로는 "그 레벨 넘는 칸은 나에게 값이
  없다"는 말이다. **막는 것이 아니다** — 아무도 원하지 않는 높은 칸이면 여전히 거기 놓일 수 있고,
  그래도 손해는 없다. ★ 와 마찬가지로 화면의 점수도 이 기준으로 바뀐다.

  **줄 오른쪽의 `대상`은 침과 모래시계가 이것을 강화하라는 뜻이다.** 북향의 침이나 빛나는
  모래시계를 들고 있고 그 대상이 될 수 있는 줄에만 뜬다. 누르면 그 아티팩트를 강화하는 배치를
  먼저 고르며, **점수보다 앞선다** — 우리 점수가 다른 대상을 더 좋게 보아도 지정한 쪽으로 간다.
  게임은 자리만 보고 대상을 정하므로 원래는 솔버에게 맡겼는데, 우리 점수가 대상을 갈라내지
  못하는 자리가 둘 있다. 마법서는 능력치 표가 없어 값어치가 전부 레어도 어림값이라 같은 레어도의
  마법끼리는 완전히 같은 값이고, 침이 주는 것은 대상의 피해량에 대한 백분율인데 그 피해량은
  우리가 재지 못한다. 어느 쪽도 ★ 로는 말할 수 없다. 침이나 모래시계가 여럿이면 하나씩 짝을
  찾으며, 닿을 수 없으면 계획을 포기하지 않고 그 지정만 무시하고 이유를 한 줄로 알린다.

  **석판 배치까지 함께 끌려간다.** 솔버는 총점이 가장 큰 배치를 고르므로, 무겁게 찍은 아티팩트가
  있으면 그 칸의 레벨을 올려 주는 석판 자리를 선호하게 된다. 다만 **레벨 상한 위로는 못 올린다** —
  상한에 닿은 뒤로 배수가 하는 일은 그 아티팩트가 꺼지거나 밀려나지 않게 버티는 것뿐이다.
  그 상한은 우리가 정한 것이 아니라 게임의 것이다: `Charm_Basic` 이 효과 레벨을
  `min(상한, 표시 레벨)` 로 자르고, 이웃 레벨로 피해를 올려 주는 조화의 수정 계열
  (`Charm_NearLevelDamage`)도 이웃의 기여를 **그 이웃의 상한**으로 자른다. 격자에 상한 위의
  숫자가 찍혀도 받는 것은 상한까지다.

  세기는 값어치 차이를 어디까지 밀어낼 수 있는지로 뜻이 정해진다. 2배는 비슷한 것들 사이에서
  앞서고, 4배는 웬만한 것보다 앞서고, 10배는 다른 아티팩트보다 이득을 크게 친다. 사용 유지가 우선하며 활성 상태를 보장하는 배수는 아니다. 점수도 그
  기준으로 계산되므로 지정을 바꾸면 점수가 달라질 수 있다. 조화의 수정처럼 효과가 이웃 칸에
  달린 아티팩트를 좋은 자리에 두고 싶을 때 쓴다. 가방에 없는데 지정돼 있는 것도 함께 나와서
  풀 수 있다.

  **배수는 값어치에 곱해진다.** 그래서 값어치를 아직 재지 못해 레어도로 어림잡는 아티팩트는
  ★★★ 를 걸어도 제대로 측정된 아티팩트를 못 이길 수 있다. 어느 쪽인지는 후보나 칸에 커서를
  올리면 나온다.

목록은 여덟 줄씩 쪽으로 넘긴다. 누른다고 목록을 다시 정렬하지는 않는다 — 그러면 방금 누른 줄이
다른 것으로 바뀌어 연달아 누르다 엉뚱한 것을 지정하게 된다. 선택은
`%LOCALAPPDATA%\SephPlanner\plugin-settings.json`에 남는다.

### 설정 창 (`F3`)

켜고 끄기, 모서리, 크기, 폭, 불투명도, 후보 추천과 추천 범위, 멀티 자동 배치, 갱신 주기,
단축키가 거기 있다. 같은 값이 BepInEx 설정 파일에도 있어 어느 쪽으로 고쳐도 같은 자리를 읽고 쓴다.

**단축키 탭에서 키 이름을 누른 뒤 원하는 키를 누르면 바뀐다.** 일반 키와 Ctrl·Alt·Shift 조합을
지원하며 수정키의 왼쪽·오른쪽을 구분한다. 입력을 시작한 키는 먼저 놓는다. ESC는 지정 취소이고,
각 줄의 `해제`는 미지정, `기본값`은 원래 F키로 복원한다. 데이터 재생성과 진단 덤프 키도 변경할 수 있다.
지정 중과 입력한 키를 놓을 때까지는 이 도구의 기존 단축키가 실행되지 않는다.

`!` 표시는 게임 기본 조작과의 충돌 가능성, 같은 단축키를 쓰는 기능 또는 설정 창 키의 해제를
알린다. 변경 결과의 자세한 안내는 아래에 나온다. 겹치는 지정도 허용하며 다른 기능의 키를
자동으로 바꾸지 않는다. 게임의 사용자 지정 키와 다른 모드의 단축키는 검사하지 않으므로 직접
확인한다. 조합키도 게임 입력을 차단하지 않는다. 설정 창 키를 해제했다면 닫기 전에 다시 지정하거나
`BepInEx/config/dev.nyabi.sephplanner.bridge.cfg`의 `SettingsKey`를 `F3`으로 복원한다.

**갱신 주기와 추천 범위는 게임이 무겁거나 후보가 안 잡힐 때 만지는 값이다.** 주기를 늘리면
인벤토리를 덜 자주 읽고, 범위를 넓히면 조금 더 멀리 있는 상자·상점까지 후보가 된다.

**추천은 여기서 끌 수 있다.** 배치(정렬)는 손으로도 할 수 있는 일의 대행이지만, 무엇을 집을지에
대한 조언은 판단을 빌려주는 것이라 난이도에 영향을 준다. 끄면 화면에서 가리는 게 아니라 계산
자체를 하지 않고, 상자·상점이 열려도 저절로 펼쳐지지 않는다. 점수·격자·이동 목록·자동 배치는
그대로 남는다. 강화 지정과 레어도 가중치는 "어디에 놓을지"의 취향이라 배치 쪽으로 분류해 남겼다.

### 창은 입력을 받는다

빌드 창과 설정 창은 **입력을 받는다.** HUD 의 무입력 원칙은 플레이 중 조작을 방해하지 않기
위한 것인데, 이 창들은 플레이어가 일부러 연 것이라 그 이유가 걸리지 않는다. 게임의 `UIBase`를
상속해 컨트롤 스택에 올라가므로 **여는 동안 캐릭터 조작이 멈추고 ESC 로도 닫힌다** — 게임의 다른
창과 똑같이 행동한다. 닫으면 그 자리에 아무것도 남지 않아 HUD 의 보장은 그대로다.

**여는 동안 시간도 멈춘다**(싱글 한정, 게임의 `GameTimeManager`가 멀티에서는 스스로 거부한다).
게임에서 설정을 만지는 길은 ESC 일시정지 창을 거치는 것이라 그때는 시간이 이미 멈춰 있다.
우리 창만 시간이 흐르면 만지는 사이에 얻어맞는다.

게임 자체의 설정 창에 탭으로 붙이는 길은 만들어 보고 접었다. 그 창이 탭 다섯 개에 딱 맞게 짜여
있어 우리 탭이 들어갈 자리가 없고, 선택 표시가 탭 그림마다 박혀 있어 버튼을 옮기면 게임 탭들이
어긋난다. 잰 값은 [docs/RESEARCH.md](docs/RESEARCH.md) 에 남겼다.

## 원칙

- **쓰기는 자동 배치 하나뿐이다.** 그 밖에는 게임 상태를 읽기만 한다. 멀티에서는 기본으로
  잠기고, 설정에서 여는 실험 옵션이 있다(켜면 방을 연 쪽과 참가한 쪽 모두에서 동작한다).
  싱글 자동 배치는 개발사에게 허락받았다. 근거와 경위는
  [docs/LEGAL.md](docs/LEGAL.md) 참고.
- **게임 저작물을 배포하지 않는다.** 데이터는 각자 PC의 게임 설치본에서 생성한다.
- **비영리.**

## 플러그인 설치

1. [BepInEx 5.4.23.5](https://github.com/BepInEx/BepInEx/releases) (win_x64, Mono)를 게임 폴더에 설치하고 한 번 실행한다.
2. `SephPlanner.Plugin.dll`과 `SephPlanner.Core.dll`을 `BepInEx/plugins/`에 넣는다.
3. 게임을 실행하면 석판/아티팩트 데이터가
   `%LOCALAPPDATA%\SephPlanner\catalog-generations\<generation>\`에 덤프된다. F9로 다시 덤프할
   수 있고, 데이터 루트의 `active-catalog.txt`가 현재 활성 세대를 가리킨다.

인식이 이상한 아이템이 있으면 게임 안에서 F10을 누른다. 인벤토리 내용과 주변 선택지의 상태가
그대로 `%LOCALAPPDATA%\SephPlanner\inventory-dump.txt`에 기록된다.

단축키는 게임 창에 포커스가 있어야 먹는다. 그래서 **왜 어떤 선택지가 추천에 안 들어왔는지는
BepInEx 로그에 저절로 남는다.** 상태가 바뀔 때만 한 줄씩이다.

```
세피라이트 [NORMAL d=1818.5 gen=True acq=False n=5 active=True] -> 후보 5개
```

활성 generation 폴더의 `query-verification.txt`에 질의 파서 검증 결과가 남는다. 불일치가 0이
아니면 솔버 결과를 믿을 수 없으므로 먼저 확인한다. 같은 폴더의 `manifest.txt`에는 카탈로그 파일의
크기와 SHA-256, 게임 버전과 게임 어셈블리 식별자가 기록된다.

# DPS 한계 후속 보완

남은 항목에는 미구현된 규칙, 진단 도구의 입력 누락, 실행 중 확인이 필요한 항목이 섞여 있었다. 게임 코드와 로컬 검사로 확인할 수 있는 부분을 추가로 보완했다.

## 해결한 항목

- `.replay` 기반 반복 배치 진단은 저장 당시의 설정 전체·카탈로그·직전 목표를 사용한다. 가상 이동 전에 F8과 공유하는 배치 보호 정책 및 이동 명령을 검사한다. 다음 반복에 능력치·활성·레벨과 콤보 변화량을 반영하며 인벤토리 밖 콤보 수량도 유지한다. 수렴·적용 제한·순환·반복 한도를 구분하고 제한·한도를 성공으로 반환하지 않는다.
- 관련 능력치 식으로 속성이 바뀌는 무기는 후보 배치마다 피해 속성과 대상 저항을 다시 계산한다. 최고/최저 능력치의 동률은 게임처럼 화염→냉기→번개→물리 순으로 정하며, 평균 식은 프리팹의 지정 속성을 유지한다.
- 혼돈은 네 속성 중 가장 높은 저항을, 화염/냉기·화염/번개·냉기/번개 복합 속성은 해당 두 속성 중 가장 높은 저항을 적용한다. 일반 속성에는 원소 저항을 적용하지 않는다.
- 대상 방어·저항은 게임의 `float` 덧셈·뺄셈 순서로 계산한다. 예를 들어 피해 200, 물리 저항 55에서 기존 계산은 89로 잘렸지만 게임 연산 순서는 90이다. 오차 허용치를 추가하거나 실패한 기대값을 낮추지 않고 연산을 수정했다.
- F10 성능 자료에 F2 내용 다시 그리기의 횟수·평균·최악·총 시간을 추가했다. 기록 기능을 추가한 것이며 실제 게임에서 측정한 결과는 아직 없다.

속성 선택 여부가 카탈로그와 재현 입력에 추가되어 카탈로그는 17, 재현 형식은 4로 갱신했다. 제품 버전과 의존성은 바꾸지 않았다. 형식 16/재현 3의 과거 기록은 당시 계산 빌드로 재생해야 한다.

## 근거와 검사

게임 1.0.30의 같은 로컬 `Assembly-CSharp.dll`에서 `WeaponSimple.GetRelatedStatMultiplier`, `NewWeaponFireData.CreateAttack`, `DamageInstance.IsSameElementalType`, `UnitAvatar.ApplyDamage/GetDamageReduction`을 대조했다. 가변 속성 플래그가 실제 공격 생성으로 전달되고, 복합 속성의 모든 해당 저항 중 최대를 고르는 분기를 확인했다.

SDK 10.0.401과 설치된 .NET 10.0.12 참조 문서에서 진단 도구의 API를 확인했다. `scripts/check.ps1`에서 전체 테스트 676개가 통과했다. 실패·건너뜀 0, 포맷·잠금 파일 복원·DataTool 및 Plugin Release 빌드 통과, 빌드 경고·오류 0이다. 로컬 로그는 `artifacts/dps-followup-check-20260910.log`다. 새 속성 선택 필드가 Newtonsoft.Json 저장과 System.Text.Json 읽기 사이에 보존되는 재현 검사도 수행했다.

## 실행 중 확인할 항목

1. 새 설치본으로 게임을 실행하고 카탈로그 자동 갱신이 끝나는지 확인한다. 실패하면 F9 수집을 시도하고 로그를 확인한다. 기대 카탈로그 형식은 17이다.
2. F2에서 비교 시간을 변경하고 창을 열어 둔 채 `DPS 내역`의 계산 대기→최신 결과 및 조건 변경을 확인한다. 전투 방식이 다른 경우 공격 순서와 마법 우선순위를 함께 맞춘다.
3. 싱글플레이에서 F8 적용 전후를 비교한다. 미지원 변경 제한은 이유를 표시해야 하며, 허용한 배치의 실제 레벨·활성·연결을 확인한다. 움직임 없는 상태에서 반복 적용이 수렴하는지 본다.
4. F2를 여러 번 갱신한 뒤 F10으로 자료를 저장한다. `.replay`를 `--reproduce`와 `--churn`에 입력하고 로그의 `F2 내용 다시 그리기`를 확인한다.
5. 실제 피해 대조는 같은 대상·무기·공격 방식·시작 자원·비교 시간으로 시행한다. 대상 사망·보호막·이동·피격 실패가 섞인 피해를 정지 표적의 예상 DPS와 그대로 비교하지 않는다.

현재 허용은 게임 종료 상태의 설치까지이며 이 환경에서는 게임 화면 직접 조작 도구를 사용할 수 없다. 따라서 게임 실행·F2/F8/F10 조작·실제 피해 측정은 수행하지 않았다. 사용자 조작으로 생성된 자료는 로컬에서 읽어 분석할 수 있다.

## 아직 남은 모델 작업

무기 상태 분기·실제 모션·무기 마나와 대시 충전, 소환물 행동, 상태 이상 중첩, 고유 공격·추가 발동, 임시 버프의 변화는 별도 구현이 필요하다. 소스에서 확정되는 규칙은 추가할 수 있지만 적의 이동·조준·AI 경로처럼 전투 상황에 따라 달라지는 결과는 시나리오와 실측이 필요하다. 현재 미지원 표시와 자동 적용 제한은 이 차이를 숨기지 않기 위한 기능이다.

실측 자료가 있어도 모든 상황의 실제 DPS 일치나 전역 최적 배치를 일괄 보장하지 않는다. 현재 추천은 제한된 시간의 탐색 결과이며, 지원 범위를 확장한 뒤에도 실제 피해 대조와 탐색 품질 검사는 각각 필요하다.

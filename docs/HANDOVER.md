# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-04 - 0.4.22 드래프트, 성능·안전·시험

**0.4.22 는 드래프트다(미공개).** 태그 `v0.4.22` = `610f1b2`, Windows ZIP 과 본문(CHANGELOG 절)이 올라가 있고 Mac ZIP 은
없다. 태그는 사용자가 옮긴다 - 에이전트의 태그 푸시는 권한 분류기가 막는다. 그 뒤 `main` 에는 결과를 바꾸지 않는
커밋만 있다(아래 "태그 뒤").

오전 세션은 제보 6건(0.4.21, 게임 1.0.33)과 단안경 제보를 처리했다 - 콤보 우선 채점 할당, 카탈로그 짓기를 데이터베이스
준비 신호 뒤로, 빔 확장 실체화 제거, `[perf]` cold/warm 계측, 자리 의존 콤보는 단계를 채울 때만, 꺼진 열쇠·종이·침도
콤보에, 치명타 100% 상한, 목표 레벨 `콤보만`. 보관 제보 42건의 종료 코드 기준이 0 스물아홉 / 2 열셋이 됐다.

오후 세션이 0.4.22 에 더한 것:

- **성능(결과 불변).** `Estimate` 배정의 상수(cold 배치 3~12%), 헝가리안·비용 행렬·카테고리 문자열의 할당(후보 6개
  warm 조언 537 → 202MB, 후보 없는 네 판 warm 조언 절반 안팎). 근거는 PERFORMANCE 1b·4번.
- **빼기·인챈트 추천의 문턱**을 점수 눈금으로(검토 3-3). 42건 재현 불변.
- **업데이트가 반쯤 걸렸을 때의 안내.** 되돌리기 실패를 `UpdateRollbackException` 으로 올리고, 시작할 때 플러그인과
  Core 의 판을 대조한다. 대조는 옛 Core 와 섞여도 돌도록 옛 API(`UpdateClient.Normalize`)만 쓴다.
- **시험·도구.** `PlacementQualityTests`(비교 단계 순서·허용 오차, 검토 3-4·3-6), `ItemIdentity` 시험과 `FrameCost`·
  `GameBinding` 링크(검토 6-1·6-3), `check.ps1` 의 판 대조·경고 0·PowerShell 7 요구, `make-release.ps1` 이
  `check.ps1` 을 부름, `--replay` 실패 종료 코드(검토 6-4).

**태그 뒤.** `8c04e19` - 콤보 우선 탐색의 칸 표(`ToDictionary`)가 던질 수 있다던 검토 3-5 는 결함이 아니었다. 칸이
겹치는 배치를 만드는 길이 없어 불변식을 주석으로 적고 못 박힌 아이템 시험을 붙였다. 결과 불변이라 드래프트를 다시
만들 필요는 없다.

**재 보니 작았던 것.** 폴링의 지문 계산은 Unity Mono 로 41칸 판에서 약 0.2ms 였고 중복도 이미 없었다. 코드는 두고
ROADMAP 을 지금 수치로 고쳤다. Mono 측정법은 PERFORMANCE "재는 법".

검증: `scripts/check.ps1` 929개 통과, 경고 0. 결과를 바꾸지 않는 수정은 전부 42건 `--reproduce --allow-model-change`
출력이 같았다. 마지막 커밋까지 `origin/main` 에 푸시했다.

## 다음 세션

0. **실기.** STATUS 표 맨 위 여섯 줄(0.4.22). 치명타 바탕은 게임 값을 처음 읽는 경로이고, 업데이트 안내는
   `SephPlanner.Core.dll` 만 0.4.21 것으로 두고 켜서 본다. 확인한 줄은 지운다.
1. **0.4.22 공개.** Mac 에서 태그 `610f1b2` 로 `make-release.ps1`(PowerShell 7) → `gh release upload` →
   `publish-release.ps1`. 공개는 사용자가 정한다.
2. **cold 빈도.** 0.4.22 제보의 `[perf]` 에서 "각도" 가 "구성" 보다 크면 빔 열쇠에서 각도를 빼는 일을 사용자와
   정한다 - 추천이 바뀌고 `--churn` 확인이 필요하다. 빔의 확장·묶음 수도 같이 본다.
3. **게임 없이 할 수 있는 것**(제안 순): 진단 자료(`inventory-snapshot.json`·`plan.replay`)의 개인정보 가림과 `?token=`
   꼴, 자동 진단 수집의 `[perf]` 구간(검토 4-3), `Update`·`OnDestroy` 의 `Guarded`, `CharmCriteria.ReadsNeighbors` 시험.
4. **남은 할당**(`Describe`·`OccupancyFrom`·`Clone`)은 다음 제보의 0세대 수집 횟수를 보고 정한다.
5. **요청 둘**(F1 선호도, 고사양 모드)과 운영 문서(검토 7-4~7-7)는 사용자 결정을 기다린다.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

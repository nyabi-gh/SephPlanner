# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-02 둘째 - 0.4.27 이후 커밋 검토와 수정 넷

0.5.0 은 2026-10-30 에 공개됐다. `v0.4.27..64d00a9` 열다섯 커밋(1.1.0 대응, 진단의 게임 경고·오류, 화면 번역)을 검토했고,
나온 결함 중 넷을 고쳐 `main` 에 푸시했다. 다음 판은 열지 않았다(버전·CHANGELOG 그대로).

- **로비 참가 코드 가림**(`f62e177`). 게임은 스팀 `LobbyData.ToString()`(16진 `HexId`)과 EOS `lobbyId` 로 참가 코드를 경고 줄에
  찍는데 숫자 규칙에 걸리지 않았다. 두 판 디컴파일의 경고·오류 호출을 다시 훑어 넷을 더했다([진단 전송](DIAGNOSTIC-UPLOAD.md)).
- **나침반 지정 대상**(`97d62b2`). 몫이 없는 분배·돌파 나침반도 지정 대상 일치로 세어, 솔버가 점수를 깎아 그 나침반을 대상
  옆에 붙였다. 0.5.0 에 공개된 결함이다([배치 목적](PLACEMENT-OBJECTIVE.md)의 "지정한 강화 대상").
- **판 섞임 방어**(`b8cfb81`). 플러그인 클래스의 `Core.Text.Language` 필드 하나로 옛 Core 옆에서 클래스가 아예 올라가지 않았다.
  유니티 에디터의 Mono 로 0.5.0 Core 옆에 올려 재현하고 고친 뒤 다시 확인했다([백로그](ROADMAP.md) "판이 섞이면").
- **로그·진단 한국어**(`f9864b3`). 화면과 로그에 함께 가는 문장이 화면 언어로 로그에 남았다. 사용자가 고른 방식으로
  `Phrase`(쓸 때 옮기는 문장)를 두었다 - 규칙은 [개발 문서](DEVELOPMENT.md)의 "번역" 과 AGENTS.md.

검증한 것: 두 설치본(1.1.1, 1.0.33 사본 `C:\Users\Nyabi\Documents\Sephiria-1.0.33`)에서 `check.ps1` 통과(1015개, 경고 0),
중간 커밋 셋도 각각 통과. `reports/` 넷의 `--reproduce --allow-model-change` 가 모두 일치. 판 섞임은 Mono 에서 플러그인 형식
전부를 옛 Core 옆에 올려 봤다 - 플러그인 클래스·`Awake`·`FinishPreviousUpdate` 는 되고, 못 올라가는 것은 폴링·자동 배치에서만
쓰는 형식이다(이전에도 그 길은 새 Core 멤버를 불러 실패했다). 그 뒤 이 PC 의 게임 폴더에 BepInEx 와 `main` 빌드를 설치해, 로그로 판 섞임(0.5.1 로 지은 플러그인 + 0.5.0 Core)과
패드 기본값 이전을 확인했다. 화면 조작이 필요한 줄은 아직이다. 이 PC 의 설치본은 기본 경로(`D:`)가 아니라 `SEPHIRIA_DIR` 을 줘야 빌드된다.

검토에서 남은 작은 것은 [백로그](ROADMAP.md)의 "화면"·"솔버" 끝에 적었다(언어 바꾼 뒤 HUD 불투명도, Auto 언어 구독, 계산 중
언어 변경, 첫 검증 안내 미번역, 돌파 몫 길 순서, 콤보 능력치 주석).

## 다음 세션

1. **0.5.1 마무리.** 2026-11-02 에 0.5.1 을 열고 Windows ZIP 만 담은 드래프트를 올렸다(태그 `v0.5.1`). Mac 에서
   `make-release.ps1` 로 지어 ZIP 을 더하고 `scripts/publish-release.ps1` 로 공개한다. 공개는 사용자가 정한다.
2. **실기.** STATUS 표 맨 위 네 줄 - 로그·진단 한국어, 나침반 지정, 번역(글꼴·폭·언어 전환), 진단 게임 로그(동의 창·가림).
   영어 폭은 F2 의 `Needle/Hourglass/Star first`, 후보 안내 줄, F3 단축키 줄이 가장 빠듯하다.
3. **조건 칸이 낡은 석판**(ROADMAP). `AppliedRangeStale` 이 조건 질의도 게임 `ParseQuery` 와 견주게 한다.
4. 검토에서 남은 작은 것(ROADMAP). 고치기 쉬운 순서는 HUD 불투명도 → Auto 언어 구독 → 첫 검증 안내.
5. STATUS 표의 0.5.0·0.4.27·0.4.26 실기 줄.
6. 이전 인계에서 남은 것: `[perf]` 로 정할 빔 열쇠 둘, 진단 자료 가림, 자동 진단 수집 계측, `Guarded`, `CharmCriteria.ReadsNeighbors` 시험.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-16 - 창이 크기 설정을 따르게 (Mac)

건의: "배치 버튼이나 클릭 상호작용 크기 조절이 되나, 스팀덱에서 쓰는데 애매하다". 건의자가 터치로 누르는지 스틱으로
고르는지는 모른다.

- **원인.** F3 의 `크기`(80~150%)는 구석 화면(`NativeHud`)에만 먹었다. 누를 것이 있는 창(`PlannerWindow` - 설정·빌드·제보·
  업데이트)은 `Skin.BaseSize` 를 그대로 기준으로 써서 늘 100% 였다. 패드에서 자동 배치는 설정 창 `동작` 탭의 버튼뿐이라
  스팀덱에서는 그 버튼 크기를 바꿀 길이 없었다.
- **고친 것.** 창의 기준 크기에 같은 배율을 곱한다(`PlannerWindow.Scale`). 배율이 바뀌면 언어를 바꿀 때와 같은 길로
  창을 버리고 다시 짓는다 - 열린 설정 창은 닫았다 다시 연다(`RebuildWindows`). 창이 화면보다 크면 `PlannerPanel.LateUpdate`
  가 들어갈 만큼 `localScale` 로 줄인다. 높이가 탭·쪽마다 달라 열려 있는 동안 계속 본다. `UIBase` 에는 `Update`·`LateUpdate`
  도 크기 애니메이션도 없다(1.1.x 디컴파일).
- **하지 않은 것.** 버튼의 눌리는 영역(글자 한 줄 높이 1.5배)은 그대로다. 크기를 올려도 모자라다는 답이 오면 줄 높이와
  여백을 키운다. 크기를 바꾸면 설정 창이 다시 열리면서 초점이 탭 줄로 돌아가, 패드로 여러 단계를 올리려면 매번 `크기`
  줄까지 다시 내려가야 한다(언어를 바꿀 때와 같다).
- **검증.** `check.ps1` 통과(경고 0, 창작마당 판 빌드까지, 1.1.x 설치본). 화면 코드라 시험은 더하지 않았고 게임 화면으로는
  보지 못했다 - STATUS 표 "창이 크기 설정을 따름".

   받으면 좋다.
2. **F9 로 새 측정 덤프**(게임, 사용자). 카탈로그 판 29 라 덤프가 없으면 재현 대조가 옛 표로 돈다.
3. **0.6.4 창작마당.** GitHub 은 11-16 에 공개했다(Mac ZIP 을 `v0.6.4` 에서 지어 더했다). 남은 것은 창작마당 승인 확인
   (`[ModGuardReviewStatus]`)과 올린 뒤 설명 다시 붙여 넣기다.
4. **게임 실기.** 날개와 천 갑옷(탐욕 20레벨 특전이나 패시브 오브젝트로 `ARRANGEMENT_BONUS` 를 얻은 판)에서 추천이 둘을 떼어
   두는지와 안내 줄, 걸으면서 누른 단축키, 다시 뜨는 동의 창, 금반지의 성장 표시, 상인 금고 재고의 가격(3-2), 조언 실패 문구,
   STATUS 표의 0.6.1·0.6.0 줄. 멀티 둘은 `winhttp.dll.off` 를 `winhttp.dll` 로 돌려 BepInEx 판으로 본다.
5. **창 크기 실기**(게임, 사용자). STATUS 표 "창이 크기 설정을 따름". 건의자에게 터치인지 스틱인지와, 올린 크기로
   충분한지를 묻는다. 본 뒤 0.6.5 를 배포한다.
6. **검토 10절 5·6단계**(화면 7-x, 성능 6-3·6-4, 구조 9-x, 배포 8-2·8-3)와 낮음 항목(4-7~ 등)은 그 뒤다. 4-3 의 "못 박힌
   아티팩트도 빔의 `Items` 에 들어가 빈 칸 하나를 차지한다" 는 이번에 고치지 않았다.

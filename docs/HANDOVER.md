# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-13 둘째 - 0.4.25 성능(결과 불변)

**0.4.24 는 2026-10-13 에 공개됐다.** 이 세션은 0.4.25 를 열었고 릴리스는 만들지 않았다.

0.4.23 제보(`46fe8f23`·`1047183d`·`008cffa4`)의 `[perf]` 와 단계별 임시 계측으로 원인을 갈랐다. 판마다 달랐다 -
빔 cold(`46fe8f23`), 지원 짝 옮기기의 할당(`1047183d`), 양옆 빈칸 시도의 중첩(`008cffa4`). 인게임 cold 의 까닭은
각도보다 구성이 두 배였고, 배치 풀이는 2할·조언은 4할을 버리고 있었다. 추천이 바뀔 수 있는 것은 빼고 넷을 했다.

- **지원 짝 옮기기의 증분**(`2ce2f78`). `PolishSupportPairs` 가 다듬기의 작업 공간을 쓰고, 침 사슬·종이 카테고리·
  채점 목록이 호출마다 짓던 것을 걷었다. `1047183d` warm 할당 배치 319 → 24 MB, 조언 912 → 67 MB.
- **취소된 빔 탐색 잇기**(`0161b0e`). 마친 석판 단계를 같은 열쇠 아래 따로 두고 잇는다. 끝난 빔과 섞지 않는다.
- **조언 부분 기억**(`6c22c4c`). 같은 판이면 합성·후보·버리기·인챈트를 각자의 입력으로 기억한다(`AdviceMemo`).
- **고사양 모드가 채점도 나눔**(`a1b60d0`). 판의 지연 값을 스레드 안전하게 게시하고 후보 채점을 나눈다. 8 스레드
  warm 배치 `008cffa4` 545 → 143 ms.
- **`[perf]` 의 "활성"**(`5d179bd`). 구성 재탐색 중 지금 활성만 바뀐 것을 따로 센다.

검증: `scripts/check.ps1` 통과(956개, 경고 0). 보관 제보 47건의 재현 출력이 0.4.24 와 같다(1·8 스레드 모두). 47건에
후보를 얹어 열기 → 닫기 → 열기로 푼 조언이 한 번에 푼 것과 같다. 시간·할당은 [성능](PERFORMANCE.md) "끝난 것".

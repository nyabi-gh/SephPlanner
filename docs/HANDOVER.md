# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-19 (2) - 외부 감사 보고서 검증과 수정 (Mac)

사용자가 붙여 준 외부 감사 보고서(19항목)를 검증하고, 맞는 것을 사용자가 고른 순서대로 모두 고쳤다. 모두 `main` 에
푸시했다. 같은 날 앞 세션의 일(진단 서버 1차 수정, 제보 `eeb4f2ad` 재현, 1.0.33 지원 종료 예고)은 STATUS 와 커밋에 있다.

- **검증 결과.** 진단 서버 둘은 로컬 서버로 재현했다 - 소문자 `post` 업로드가 모든 한도를 비켜 갔고(201×4), 압축 16KB 설명
  하나가 320MB 를 썼다(보고서는 180~250MB 로 봤다). 나머지는 코드·이력으로 확인했다. 틀린 지적은 `WriteAtomic`·`ㄹ` 받침
  둘이고, `GrowthWorth` 의 근거 강등은 주석 의도와 맞았다. 보고서의 "목록에서 OOM" 은 과장(순서대로 읽어 지연뿐)이었다.
- **고친 것.** 서버 - 메서드 대소문자, 설명의 머리 칸만 읽기(320MB → 16MB, 크기 상한은 짐작이 필요해 두지 않음), 목록을
  잠금 밖에서 읽기, 정리 실패가 요청을 막지 않기, 묶음의 `.dockerignore`. 모드 - 꺼진 나침반의 우선 콤보, 후보 칸 안내와
  조언 실패, F3 에서 끌 때의 저장 실패, 적용 잠금(`ApplyLease`, 아래), 쓰러진 동안의 F8 안내, 돌파의 경고 문구, 런 밖의 확장
  호출, 거절한 자동 진단의 매 프레임 `ToString`, 낡은 창 정리 순서, F3 이 F10 진단을 버리던 것, 메모의 CRLF, 가림 정규식의
  줄 넘기, F9 의 레시피 캐시, `Strings` 표의 게시(PERFORMANCE 규칙대로 `Volatile`·`Interlocked`). 도구 - DataTool 의 점수
  눈금·`--churn` 의 활성 여부·재측정, `make-release.ps1` 의 절 누락 가드. 문서 - STATUS·RESEARCH·INSTALL-macos 의 낡은 곳.
- **적용 잠금.** 시각으로 재면 한 프레임 안에서 `Update` 가 코루틴 재개보다 먼저 돌아, 반복자의 대기 시한과 같은 시각을 넘긴
  첫 프레임에 아직 도는 적용이 풀렸다. 시한을 늘리지 않고 "앞 프레임에 재개됐는가" 로 바꿨고, 반복자의 `AbandonAt` 은 걷었다.
  게임에서는 못 봤다.
- **고치지 않은 것.** `CombinesInTransit` 계획의 금색 테두리(손 이동을 부추긴다 - 사용자에게 Claude 판단을 알렸다), 느린 연결
  여덟 개의 슬롯 점유(전체 상한의 대가), 꺼진 확장이 저장된 판에서 다시 켜지지 않는 것(계약대로). 셋 다 ROADMAP "판단이
  필요한 것" 에 적었다.
- **못 한 확인.** 나침반 수정은 점수를 바꿀 수 있는데 Windows 재현 대조(53건)를 못 했다. DataTool 수정은 이 Mac 에 덤프
  폴더(`~/Library/Application Support/SephPlanner`)가 없어 빌드만 봤다. 화면 수정은 모두 게임에서 못 봤다.
- **Mac `check.ps1`**(1.1.4)은 마지막 트리에서 통과했다(1141개).

## 다음 세션

1. **Windows 재현 대조**(53건). 감사의 나침반 수정이 점수를 바꾸는지 본다. 고친 DataTool(`--churn`·`--replay`·`--check`)을
   덤프로 한 번 돌려, 눈금을 잰다는 줄이 나오고 `--churn` 이 둘째 판부터 검증에 실패하지 않는지 본다.
2. **이번 판의 실기**(게임, 사용자). STATUS 표의 0.6.6 줄 다섯(감사 뒤 화면, 적용 잠금, 도중 합치기, 쓰러진 동안, 돌파).
   돌파 줄은 유일한 확인이다.
3. **0.6.6 배포.** 2 를 본 뒤 사용자가 말하면 `v0.6.6` 태그, 두 기계의 `make-release.ps1`, `publish-release.ps1`, 창작마당 업로드 순이다.
4. **진단 서버 배포**(사용자, 0.6.6 과 함께). 템플릿이 있는 기계에서 `package-diagnostics.ps1`(이제 PowerShell 7 필요)로 묶는다.
   리버스 프록시가 요청 본문을 흘려 넘기는지와 메서드를 고쳐 넘기는지, 배포가 `UploadsPerMinute` 를 환경 변수로 덮는지(덮으면
   그 값이 곳마다 한도가 된다), 재시작 정책을 본다.
5. **1.0.33 지원 내리기**(0.6.7). ROADMAP 의 순서대로 - 자가 업데이트부터.
6. **모드 창을 닫으면 시간이 흐르는 줄**(게임). 게임 `GameTimeManager` 에 멈춤 횟수가 없고 `UI_PausePanel` 도 닫을 때
   `ResetTimeScaleTo1` 을 부른다(1.1.4 디컴파일) - 모드 창 위에 ESC 창이 열리는지부터 본다.
7. **F9 로 새 측정 덤프**(게임, 사용자). 카탈로그 판 29 라 덤프가 없으면 재현 대조가 옛 표로 돈다.
8. **0.6.5 배포 기록.** STATUS 의 배포 상태에 창작마당에 올린 날짜·접수 번호와 Windows ZIP 여부가 비어 있다(사용자).
9. **게임 실기.** 걸으면서 누른 단축키, 다시 뜨는 동의 창, 금반지의 성장 표시, 상인 금고 재고의 가격(3-2), STATUS 표의
   0.6.1·0.6.0 줄. 멀티 둘은 `winhttp.dll.off` 를 `winhttp.dll` 로 돌려 BepInEx 판으로 본다.
10. **창 크기 실기**(게임, 사용자). STATUS 표 "창이 크기 설정을 따름". 건의자에게 터치인지 스틱인지와, 올린 크기로

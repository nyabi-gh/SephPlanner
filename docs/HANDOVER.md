# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-02 넷째 - 창작마당 판 짓기 (Windows, 1.1.1)

커밋 다섯으로 `main` 에 푸시했다 - `ab586eb` 호스트 층·네트워크 분리(새 입력 시스템 포함), `662af9a` 설정 창 단축키 복원,
`31d1b57` 창작마당 판, `9589914` 언어를 바꾸면 설정 창 다시 열기, 그리고 이 문서 커밋. 각 커밋에서 `check.ps1` 을 돌렸다.
**다음 판은 열지 않았다**(버전 0.5.1 그대로, CHANGELOG 절 없음). 사용자가 정한 것: 한 코드에서 진입점 둘(BepInEx·창작마당), 창작마당 설정은 게임의 ModOptions,
TEAM HORAY 답이 오기 전까지 창작마당 판에는 네트워크 코드를 넣지 않음, modId `nyabi.sephplanner`, 설정 창 단축키를 해제한
채 두면 다음 실행에 기본값으로 되돌림(두 판 모두).

- **1.1.1 디컴파일 대조**는 [게임 내부 조사](RESEARCH.md)의 "공식 모드 API" 에 적었다. 가이드와 다른 것은 없었다.
- **구조**는 [개발 문서](DEVELOPMENT.md)의 "구조"·"창작마당 판". 플러그인 본체는 그대로 두고 BepInEx 에 묶인 것(설정 45곳,
  단축키, 로그, 경로, `BaseUnityPlugin`)을 `Host/` 층으로 갈음했다. 진단 전송·게임 안 업데이트는 Core 에서 빼 BepInEx 판
  플러그인 DLL 에만 넣었다(`BepInExHost/`) - 별도 어셈블리로 빼면 0.5.1 까지의 게임 안 업데이트가 DLL 둘만 받아 깨진다.
- **실기에서 잡은 결함**: 1.1.1 은 구식 `Input` 을 꺼 두었다. 처음에 게임 코드의 구식 호출만 보고 켜져 있다고 판단했다가 틀렸고,
  단축키를 새 입력 시스템으로 읽게 고쳤다. 그 판단으로 잘못 쓴 주석·RESEARCH 문장도 바로잡았다.
- **사용자 제보로 고친 것**: F3 에서 언어를 바꿔도 열린 설정 창 글자가 그대로였다(0.5.1 부터, 창을 닫을 때까지 미룸). 이제
  게임의 길로 닫았다 새 언어로 다시 연다. 실기 전이다.
- 화면 문구 다섯을 로더에 맞게 고쳤다("BepInEx 로그" → 로그 파일 이름). 번역 넷 포함.

검증한 것: 1.1.1 설치본과 1.0.33 사본 양쪽에서 `check.ps1` 통과(1019개, 경고 0, 1.0.33 에서는 창작마당 판을 건너뜀).
창작마당 DLL 을 디컴파일해 `HttpClient`·`System.Net`·BepInEx 참조가 없는 것. 게임에서 BepInEx 를 끄고 `WorkshopLocal` 로
켜 활성화·HUD·카탈로그·F3·F4·F10·설정 가져오기(STATUS "실기에서 확인한 것"). 못 본 것은 STATUS 표 맨 위 네 줄이다.

이 PC 의 게임 폴더 상태: `BepInEx/plugins` 와 `WorkshopLocal/sephplanner` 에 이번 작업의 빌드가 들어 있고 `winhttp.dll` 은
원래 이름이다(BepInEx 켜짐). 그대로 켜면 공존 시험이 된다. **사용자가 에이전트의 게임 실행을 막았다** - 게임은 사용자가 켠다.

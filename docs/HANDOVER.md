# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-04 - 성능·UI/UX 전체 검토 (Windows, 코드 변경 없음)

사용자 요청으로 문서·메모리·코드를 성능과 UI/UX 두 갈래로 검토했다. 코드는 바꾸지 않았고 게임도 켜지 않았다. 결론은
해당 문서의 절에 "검토 2026-11-04" 로 넣었다.

- 성능: [성능과 응답성](PERFORMANCE.md)의 1b(콤보 셈의 열거자 상자), 1c(제거·인챈트 후보 나누기, 취소된 제거 조언),
  4번(고르기 정렬), 5번(등록부 수치). [백로그](ROADMAP.md) "매 프레임 / 폴링마다 도는 것" 에는 진단 리플레이 두 번 직렬화,
  HUD 다시 그리기, 프레임마다 짓는 대리자, 쪽지 경로를 넣었다. `OfferReader` 항목은 0.4.26 제보 넷의 `[perf]` 로 작다는
  것을 보고 지웠다.
- 화면: 백로그 "화면" 끝의 새 항목들, "판단이 필요한 것" 의 단축키 규칙, "창작마당 이전" 셋째의 문서 빈틈.
- 측정은 `reports/` 의 0.4.26 제보 넷(`9fac8a07`·`6c1abf75`·`6d50beb6`·`990421e4`)을 .NET 10 하니스와 `DataTool --bench`
  로 돌린 것이다. Mono 값은 추정이다. 콤보 셈 수정을 scratch 사본에 넣어 네 판의 배치 지문이 같은 것은 봤지만, 그 넷에는
  화면에 낼 제거·인챈트 조언이 없었다. 보관 제보 47건은 이 PC 에 없다.
- 창작마당 글 `3832790875` 은 11-03 에 목록에 없음으로 올린 뒤 검수 결과를 확인하지 않았다. 이 PC 의 BepInEx 는
  `winhttp.dll.off` 로 꺼진 채다.
- `f3813b2`(적용 도중 가방이 넓어지면 다시 계산)가 이번 푸시로 함께 올라갔다. CHANGELOG·STATUS 는 다음 판 번호를 정한 뒤 적는다.

## 다음 세션

1. **검수 결과 확인.** 승인되면 구독한 사본으로 켜 보고(로컬 사본과 함께 있을 때 어느 쪽이 실리는지는 `Player.log` 의
   `[WorkshopModManager]` 로 본다) 멀티도 본 뒤 공개로 바꾼다. 다른 언어 설명을 글에 넣을 수 있는지 본다.
2. **STATUS 표 맨 위 여덟 줄의 실기.** 특히 저주 둘(해골로 새 판), 별칭 키 단축키, BepInEx 판 회귀.
3. **검토 2026-11-04 의 작은 수정 묶음.** 추천을 바꾸지 않고 각각 15분~1시간이다. 새 문구는 네 언어를 함께 넣는다.
   - 화면: 이동 안내 좌표·회전, F2 빈 목록 문구, 안내문 빈 줄, 멀티 거절 사유.
   - 성능: 콤보 셈 열거자, 프레임마다 짓는 대리자, 진단 리플레이를 한 번만 직렬화.
4. **제거·인챈트 조언의 후보 나누기**(PERFORMANCE 1c, 반나절). 큰 가방의 조언 지연이 가장 큰 자리다.
5. README·INSTALL·USAGE 를 창작마당 기준으로. 검토의 문서 빈틈도 함께 메운다(ROADMAP "창작마당 이전" 셋째).
6. **CI 의 가끔 실패하는 테스트 둘**(STATUS "원인을 모르는 채", 단서 하나를 적었다). 사용자가 미뤘다.
7. 직전 인계에서 남은 것: 조건 칸이 낡은 석판(ROADMAP), HUD 불투명도 → Auto 언어 구독 → 첫 검증 안내.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-19 - 진단 서버, 돌파 재현, 0.6.6 마무리 (Mac)

- **진단 서버의 남은 항목을 고쳤다**(사용자: 0.6.6 과 함께). 저장소 밖 검토 문서의 4·5·6·9 를 고치기 전에 로컬 서버로 모두
  재현했다 - 한 IP 가 몫을 채우자 다른 IP 가 507, 100만 자 메모가 201, 저장 폴더가 사라지면 정리 예외로 호스트가 종료 코드 0,
  UTF-8 이 아닌 자료 하나로 목록 500. 지금 모양은 이렇다(기본값은 모두 추정값).
  - 보관 몫(곳마다 50건·64MB)과 분당 빈도(곳마다 10건)는 보낸 곳(IPv4 하나, IPv6 /64 하나)마다 센다. 동시 처리는 곳마다 2,
    서버 전체 8. 서버 전체 분당 상한은 두지 않는다 - 몇 곳의 값싼 잘못된 요청으로 다 써진다. 보낸 곳은 메모리에만 둔다.
  - 최소 본문 속도는 초당 4KB(유예 5초)다. 프록시가 본문을 모아 넘기면 이 검사는 프록시 뒤에서만 걸린다.
  - 메모는 서버도 500자를 지키고 목록에서도 자르며 제어문자를 지운다. 정리 실패는 로그와 `/health` 503 으로 알린다.
  - 푸시 뒤 자동 보안 검토가 두 번 짚은 것(서버 전체 상한이 사라짐, 그 상한이 굶겨질 수 있음)을 반영한 결과다.
  - 서버만 바뀐다. 클라이언트는 200·201 밖을 모두 실패로 다뤄 옛 모드와 맞는다. 배포 템플릿이 이 Mac 에 없어 묶음은 못 지었다.
- **제보 `eeb4f2ad` 원본 재현.** 수정 전(`bc45bf7`)은 종료 0 으로 저장 결과와 같다 - 대상 (2,4) → 돌파 (2,5) → 침 (2,6)~(2,9).
  `main` 은 종료 2(123곳) - 대상 (1,0) → 돌파 (1,1) → 침 (1,2)~(1,5), 지정 대상 지원 4 → 5. 수정 전도 사슬을 지켜 이 자료는
  증상을 담지 않는다. `main` 의 최선 점수가 1.05 낮은 이유는 안 봤다.
- **백로그 둘을 0.6.6 에 넣었다**(사용자 결정). 참가자의 마지막 레벨 확인이 적용 시한을 넘어 `PlanApplier.InProgress` 가 먼저
  풀리던 것은 확인 동안 시한을 늘렸다 - 가짜 격자 시험으로만 봤고 게임에서는 못 봤다. `ReplayResult` 는 인스턴스 번호를 문화권과
  무관하게 적는다(개발 쪽 재생만). 그 전에 sv-SE 같은 문화권에서 저장된 자료는 여전히 다르게 보인다.
- **1.0.33 지원은 0.6.6 이 마지막**(사용자 결정). 0.6.6 변경 기록의 `### Upcoming` 에 예고했고, 내리는 일과 순서는 ROADMAP
  "1.0.33 지원 내리기" 에 있다. 자가 업데이트가 1.0.33 사용자에게 0.6.7 을 내밀지 않게 하는 것이 먼저다.
- **모드 창을 닫으면 시간이 흐르는 줄은** 게임 `GameTimeManager` 에 멈춤 횟수가 없고 `UI_PausePanel` 도 닫을 때
  `ResetTimeScaleTo1` 을 부른다(1.1.4 디컴파일) - 모드 창 위에 ESC 창이 열리는지부터 게임에서 본다.
- **Mac `check.ps1`**(1.1.4)은 마지막 트리에서 통과했다(1120개). 모두 `main` 에 푸시했다.

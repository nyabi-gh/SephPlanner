# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-30 - 게임 1.1.0 베타 대조(코드 변경 없음)

0.4.27(태그 `v0.4.27` = `b4cc98f`)은 2026-10-26 에 두 ZIP 으로 공개됐다(Latest). 그 뒤 "1.1.0 에서 모드가 안 돈다"는
제보로 게임 1.1.0 베타(`workshop-beta` 브랜치, 2026-10-29)를 대조했다. 코드는 고치지 않았고 문서만 고쳤다.

- 원인은 북향의 침 클래스 교체 하나다. `Charm_UpCharmDamage` 가 `Charm_Compass`·`Charm_CompassDamageUp`·
  `Charm_CompassBreakthrough` 로 바뀌어 `ItemCatalog.Dependency` 가 `TypeLoadException` 을 내고 카탈로그가 영영 안
  지어진다. 화면에는 "데이터 생성 실패" 만 뜬다.
- 0.4.27 zip 의 DLL 을 Mono.Cecil 로 1.1.0 에 대 보니 깨진 참조는 그 타입과 필드 여섯뿐이다. 문자열로 잡는 멤버도
  다 있다. 엔진·질의 문법·활성 조건·쓰기 경로는 그대로다([개발 문서](DEVELOPMENT.md)의 "게임이 패치되면" 6번이 방법).
- 고친 뒤에도 맞출 것은 [게임 내부 조사](RESEARCH.md)에 `1.1.0` 으로 적었다 - 나침반 규칙, `ReleasePermission` 의
  재계산 반복, 배치 보너스 합치기, 개인 합성기, `UNLIMITEDCOMBO`·`COMBOBONUSDAMAGE`.

이 PC 의 게임은 1.1.0 베타라 `scripts/check.ps1` 의 플러그인 빌드가 `ItemCatalog.cs` 에서 실패한다. 게임 폴더에
BepInEx 는 깔려 있지 않다. 1.0.33 디컴파일이 없어 "1.1.0 에서 새로 생겼다" 는 RESEARCH 대비 판단이다.

## 다음 세션

1. **1.1.0 대응.** 지원 범위는 사용자 결정 대기다 - 1.1.0 이 베타라 기본 브랜치는 1.0.33 일 것이고, 게임 안 업데이트는
   `releases/latest` 만 보므로 한쪽만 도는 판을 내면 반대쪽이 깨진다. 두 버전을 함께 지원한다면:
   - 플러그인은 침 계열을 타입·필드 이름으로 읽는다. 어느 클래스도 컴파일 시점에 참조하지 않는다.
   - Core 는 카탈로그의 `Behavior` 로 옛 규칙(`Charm_UpCharmDamage`)과 새 규칙(`Charm_Compass*`)을 가른다. 새 쪽은
     부모 칸 여럿, 뿌리 합집합, 꺼지면 카테고리 없음과 사슬 끊김, 돌파의 희귀도 무시다.
   - 시뮬레이터·콤보 셈이 재계산 반복을 따라가는지 본다(나침반 활성 → 카테고리 → 신비 각인 수).
   - 검증은 두 설치본으로 `check.ps1`, `reports/` 넷의 `--reproduce` 전후 동일, 실기(1.1.0 에서 카탈로그·질의 검증 통과,
     `Player.log` 의 `[ModEnvironment] 동봉 Harmony` 줄이 HarmonyX 인지).
2. **1.1.0 의 나머지.** 배치 보너스 합치기(자동 배치가 재료를 붙이면 아이템이 사라진다), 멀티에서 남의 개인 합성기,
   점수 밖의 콤보 능력치. 각각 무엇이 그 능력치를 주는지부터 본다.
3. **실기.** STATUS 표 맨 위 두 줄(0.4.27)과 그 아래 0.4.26·0.4.25 줄. 1.0.33 브랜치에서 본다.
4. **다음 제보의 `[perf]` 로 정할 것 둘**(추천이 바뀔 수 있어 사용자와 정한다). "활성" 이 구성의 큰 몫이면 빔 열쇠에서
   지금 활성 빼기, 각도가 크면 각도 빼기([성능](PERFORMANCE.md) 4번).
5. 이전 인계에서 남은 것: 진단 자료 가림, 자동 진단 수집 계측, `Guarded`, `CharmCriteria.ReadsNeighbors` 시험.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

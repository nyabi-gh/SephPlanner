# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-13 셋째 - 양옆 빈칸 시도를 한 번만(0.4.26 열림)

0.4.25(태그 `v0.4.25` = `d5b2e4a`)가 공개된 뒤 `main` 에서 0.4.26 을 열었다. 아직 공개하지 않았다.

- **양옆 빈칸 시도와 콤보 지정을 석판 다듬기 뒤 한 번만**(`da8ecf6`). `ImproveTablets` 가 후보마다 부르던
  `EvaluateLayouts` 두 번이 각각 빈칸 시도 192회와 `PriorityPlacement.Improve` 를 다시 돌렸다. 이제 다듬기는 채점만
  하고(`RefineLayouts` → `Choose`), `Solve` 가 끝에서 한 번 돌린다. 조언이 부르는 공개 `EvaluateLayouts` 는 그대로다.
- 그냥 한 번만 돌리면 `008cffa4` 가 같은 점수에 지금 자리를 지키는 아이템이 29 → 24 로 줄었다. 빈칸 시도가 이긴
  배치는 다듬지 않은 배정이고, 겹쳐 돌던 다듬기가 그것을 우연히 되돌려 놓고 있었다. `Solve` 에서 빈칸 시도가 이기면
  한 번 다듬게 했다. 같은 다듬기를 조언에도 걸면 47건은 같지만 `008cffa4` 조언이 440 → 505 ms 라 넣지 않았다.
- 버린 변형: 처음 채점은 예전처럼 마무리하고 끝에서 한 번 더 - `008cffa4` 목적값 217.9 → 211.1.

검증: `scripts/check.ps1` 통과(956개, 경고 0). 보관 제보 47건의 Q 비교(Settled 끄고 최선 배치) 개선 0 / 악화 0,
재현 출력 47건 동일. warm 배치 `008cffa4` 약 510 → 140 ms, 179 → 38 MB. 다른 세 판과 조언은 같다.

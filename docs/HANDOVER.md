# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의
길잡이다.** 둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 덮어쓴다 - 날짜별로 쌓지 않는다.

## 2026-09-16

**표기 수정을 담은 0.4.5가 정식 공개됐다.** 요청받은 커밋·푸시와 드래프트 작성을 마친 뒤,
사용자가 릴리스 제목을 `SephPlanner 0.4.5`로 바로잡았다. 현재 최신 정식 버전도 0.4.5다.
드래프트 제목도 `SephPlanner {버전}`으로 쓰며 태그 `v{버전}`과 구분한다([배포 지침](DEVELOPMENT.md#배포)).
카탈로그 형식 23과 기존 설정 키는 유지하므로 이번 표기 변경으로 데이터를 다시 만들 필요는 없다.

### 화면 표기를 검수했다

`대상` → `침·모래시계·별조각 우선`, `고정` → `조건 무시 칸`, `레벨 제한` → `목표 레벨`.
강화칸 양보가 효과 끄기·침 연결 금지가 아니라는 점과 지원 대상 지정 > 콤보 지정 > 일반 점수의
관계를 창·쪽지·경고·사용법에 맞췄다. 레이에 별조각도 대상 지정을 따르므로 이름에서 빼지 않았다.
버튼이 이름을 밀어내지 않도록 두 줄로 나눴고, 긴 배치 이유가 잘리던 네 글자 폭을 없앴다.
게임이 실행 중이지 않아 실제 화면·패드 탐색은 다음 확인 항목이다.

붉은 이슬 제보는 0.4.2이며 양보 -3이 맞았다. 정밀 우선이 침 5개를 이슬에 붙이는 직접 원인이다.
정밀만 풀면 볼트 3·이슬 2, 볼트를 지원 대상으로 지정하면 볼트 5가 된다. 구버전과 현재의 원본
재생 차이는 0건이었다. 앞서 작은 가방에서 찾은 양보 가중치의 부분 적용은 별도 한계이며 이번
표기 작업에서 계산을 바꾸지 않았다. 자세한 검수는 [기록](notes/UI-COPY-2026-09-16.md)을 본다.

### 게임 파일과 다시 대조했다

1.0.33 디컴파일(어셈블리 SHA-256 `c57a0dae…`)로 0.4.2 이후 변경을 다시 봤다.
망원경·인챈트 쪽은 아래 표와 일치했다. 추가로 자동 배치 판정과 패드 입력에서 세 문제를 찾아 고쳤다.

- 예상과 실제 칸 레벨이 모두 0인 정상 배치를 실패로 처리하던 것을 고쳤다. 착취 석판(2005)을 열린 7칸 격자에서 `(0,0)/1`에서 `(0,1)/0`으로 옮기는 사례가 수정 후 `Settled=True`다. 실제 소실과 되돌리기 실패 경고는 유지한다.
- View의 게임 입력 처리 전후를 대조하도록 바꿨다. 같은 입력에서 지도가 열리거나 닫힐 때는 우리 창이 반응하지 않고, 다른 창 아래의 열린 지도도 제외한다. `InputState.updateCount`로 같은 입력의 중복 처리를 막는다.
- start로 잘못 적힌 닫기 안내를 B(취소)로 고쳤다. 게임의 입력 자산과 `UIInputModule.Update`에서 확인했다.

| 본 것 | 결과 |
|---|---|
| `SearchPlanet` 의 두 조건과 여덟 방향 | 코드와 같다. `SetEnhancement` 을 부르는 곳은 `Charm_PlanetModule` 하나뿐 |
| 거대화가 마지막에 곱으로 걸리는 것 | `GreenBat.CreateBullet` 의 `num += num * 0.5f` 가 피해량 합산·`PLANETDAMAGE` 뒤에 있다 |
| 표를 읽는 자리 | `LevelToIdx` 가 `[0, maxLevel]`, `SafeRandomAccess` 가 `Clamp` - `EnlargeSteps` 의 `top` 과 같다 |
| RESEARCH 의 행성 표 일곱 줄 | 카탈로그 `EffectLines`(게임이 표의 양 끝으로 만든 툴팁)로 독립 재계산해 전부 일치 |
| 카테고리를 정의에서 보는 것 | `ItemEntity.categories` 를 런타임에 바꾸는 코드가 없다. 하얀 종이는 `Charm_StatusInstance` |
| 인챈트 관문(0.4.2) | `UI_CharacterStatusPanel` 의 세 관문과 `EnchantAdvisor.Enchantable` 이 같다 |
| `AltarOfEnchant.localRemaining` | private int 로 실재 - 리플렉션 대상이 유효하다 |

**덤으로 알아낸 것.** 무너진 가방이 터지는 줄을 못 박을 수 있다 - `ReleasePermission` 이
`charm.Item.InstanceID` 를 널 검사 없이 읽고 그 루프가 `try` 밖이다. 그리고 `Charm_Basic.Item`
은 계산 프로퍼티라 "`Item` 이 끊겼다" 는 `charms` 와 `inventoryMatrix` 가 어긋났다는 뜻이다.
[게임 내부 조사](RESEARCH.md)의 "회전" 절 끝에 적었다.

**짚은 것 둘.** 하나, 카탈로그 311종에 `Charm_SummonRedPlanet` 을 쓰는 아이템이 없다 - 이름
비교를 `is` 로 바꾼 리뷰 수정은 앞을 막아 주는 것이지 지금 답을 바꾸는 것이 아니다. 둘,
`EnlargeSteps` 에 위쪽 한계가 없어 피해량 표의 기울기에 그대로 눌린다 - [백로그](ROADMAP.md)에
다시 열 조건과 함께 적었다.

### 패드로 창을 열 수 있게 했다 (실기 확인 안 함)

"단축키를 키보드로만 지정할 수 있는데 패드 사용자도 쓰게 하고 싶다"는 요청이다. 조사부터
했더니 **게임이 패드 버튼을 하나도 남기지 않고 쓴다** - `sharedassets0.assets` 의 `GameControls`
에서 뽑은 전수 표가 RESEARCH 의 "패드 단축키" 에 있다. 키보드의 F 키 같은 빈자리가 없으니
"패드 단축키 지정" 은 만들어도 누를 때마다 게임 동작이 함께 나는 기능이 된다.

`select`(View)는 UI 액션 맵에 없고 지도 열기는 스택이 비었을 때만 되지만, 열린 지도의 닫기는
스택을 검사하지 않는다(`HandleOnOpenMapPanel`). 그래서 **입력 전후에 지도가 닫혀 있고 같은
게임 창이 유지되는 View**만 받는다(`PadShortcut`·`PadInput`). 창 안은 이미 컨트롤러로 되던 것이라
(`PlannerPanel` 이 컨트롤 스택에 올라가고 버튼이 전부 `Selectable`) 새로 만든 것이 없고,
단축키로만 되던 일들이 닿도록 설정 창에 **`바로 실행` 탭**을 붙였다 - 자동 배치·미리보기·접기·
숨기기·빌드 창이고, 누르면 창을 닫고 실행한다.

**패드를 연결해 보지 않았다. 0.4.4는 공개됐지만 이 검증 공백은 남아 있다.** 볼 것 넷은 STATUS 의
"패드로 창 열기" 절에 있다. 안 한 것
(버튼 지정 UI, 안내 줄 글리프, 이동 모드와 빌드 창 우클릭의 대체)은 다시 열 조건과 함께
ROADMAP 2번에, 플레이 중 패드 단축키를 안 하는 이유는 5번에 적었다.

### 재현과 검사

`scripts/check.ps1`이 통과한다(**시험 770개**, 실패·건너뜀 0, 진단 도구와 플러그인 빌드 경고 0).

**이전 0.4.4 검토에서 `reports/` 열셋을 0.4.2와 견주어 점수·배치·추천 결과가 모두 같았다.**
양쪽 모두 `PlanReplay.Rebuild(true)`로 내장 데이터를 사용해 `ReplayResult` 전체를 대조했다.
검토 자료는 로컬 `reports/review-0.4.2/`에 있고 게임 데이터가 포함돼 커밋하지 않는다.
다만 **열셋 어디에도 `PLANET` 아티팩트가 없다** - 망원경 실기 검증을 대신하지 않는다.

**견줄 때 함정 하나를 밟았다.** 카탈로그를 23 으로 올린 뒤로 로컬 덤프(22)가 형식이 안 맞아
`--reproduce` 가 값어치를 다시 재지 못한다. 그대로 돌리면 솔버를 건드리지 않았는데도 열셋 중
여덟이 달라 **보인다.** CLI의 재측정을 포함해 견주려면 **F9로 로컬 덤프를 새로 만든 뒤에 견주며**, 그 규칙은
[계획 재현](REPRODUCTION.md)에 적어 두었다.

## 다음 일감

**0. 표기 화면과 패드 조작을 본다.** 빌드 창의 여섯 항목·두 줄 버튼, 작은 화면에서 도움말 높이, 패드로 각 버튼 이동, 접은 HUD의 줄바꿈을 확인한다.

**1. 망원경·행성을 실기에서 본다.** 이번 판의 핵심인데 재현 자료도 진단 스냅샷도 하나가 없다.
행성 빌드 판에서 볼 것 셋 - 망원경 둘레로 행성이 모이는지, 혜성·악보 '은하'·붉은행성 관찰일지가
이제 그 자리를 안 가져가는지, 그리고 **망원경이 다른 것을 밀어내지 않는지.** 셋째가 새 걱정이다 -
이웃 하나의 몫이 레벨 한 칸에서 1.25~2.5칸으로 커져 "잰 값을 못 뒤집는다" 던 옛 안전장치가
망원경 쪽에서는 사라졌다.

**2. 제단 실기 확인.** 0.4.2 부터 나가 있는데 제단을 진단 스냅샷으로 한 번도 못 봤다. 볼 것 셋은
STATUS 의 "인챈트 제단 추천" 절에 있다.

**3. 앞보기를 실기에서 본다.** 제보 열셋에 상점·상자를 연 것이 하나도 없어 **후보 추천 경로가
실제 판으로 확인되지 않았다.** 상점을 열고 아래·오른쪽으로 뻗는 석판이 있는 판에서 `다음 칸 +N`
이 붙는지, 그리고 `[perf]` 로 조언 시간이 개발 PC 의 +8~27% 와 폭이 맞는지를 본다.

**4. 침·모래시계·상점 사파이어 보충도 아직 실기 전이다.** 0.4.0 부터 나가 있다. STATUS 의
"배포했지만 실기에서 보지 않은 것".

**5. 패드를 꽂고 View 를 눌러 본다.** 이번에 넣은 것이고 실기로 한 번도 안 봤다. 볼 것 넷은
STATUS 의 "패드로 창 열기".

**6. `5915982c` 의 원인.** 왜 `charm.Item` 이 끊겼는지는 아직 모른다. 다음 제보의
`[끊긴 charms 항목]` 이 답을 줄 자리다.

**7. 성능 - [성능과 응답성](PERFORMANCE.md).** 다음 걸음은 고치는 것이 아니라 재는 것이다.

**8. 1.0.32·1.0.33 을 훑은 대조는 아무도 안 했다.** 위 표는 0.4.3 이 건드린 자리만 본 것이고,
STATUS 의 "게임 1.0.31 대조" 절은 1.0.31 까지의 기록이다.

## 알아 둘 것

**CI 가 `v0.3.9` 태그에서 빨간 것은 정상이다.** `.editorconfig` 의 LF 수정(`f42f07b`)이 0.3.9 컷
뒤에 들어가서 그 태그의 트리는 여전히 포맷 검사에 걸린다. `main` 은 초록이다.

**옛 태그가 로컬과 원격에서 갈라져 있다.** `git fetch --tags` 의 "would clobber existing tag" 는
정상이며 **`--force` 로 맞추지 않는다** - 릴리스 자산이 원격의 그 태그에 붙어 있다.

**`AGENTS.md` 가 커밋 트레일러를 금지한다.** 커밋 전에 메시지에서 그 줄들을 지운다.

**사용자용은 둘이다.** 대문 `README.md` 는 설치하고 첫 30분까지고, 빌드 지정·배치 판정 규칙·제보
절차처럼 쓰던 사람이 찾아오는 것은 [자세한 사용법](USAGE.md)에 둔다. **기능이 늘 때 붙일 자리는
대문이 아니라 USAGE 다** - 대문이 다시 불어난 것이 이 분리의 이유였다. 개발 쪽은
[개발 문서](DEVELOPMENT.md)다.

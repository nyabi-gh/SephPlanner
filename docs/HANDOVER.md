# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-19 - 제보 eeb4f2ad (Mac)

0.6.5 창작마당 판, 게임 1.1.4, 멀티 참가자의 F10 제보다. 메모는 둘이었다: 멀티에서 죽으면 탐험 중이 아니라고 한다,
돌파의 나침반이 우선하지 않은 곳에 꽂힌다. 사용자가 둘 다 고치라고 했다.

- **돌파.** 재현 자료의 직전 목표가, 이미 대상 → 돌파 → 침으로 놓인 가방에서 돌파를 빼내라고 한 계획이었다. 그 출발 배치를
  되살려 풀면 돌파가 쿠나이 밑으로 가서 정밀 개수를 하나 채운다(점수 230.2 → 210.7, 콤보 진행 1.09 → 8.71). 비교 3단계가
  돌파를 세지 않아 4단계(지정 콤보)가 6단계(값어치)를 이긴 것이다. 이제 돌파가 지정 대상의 희귀도 조건을 실제로 풀어 주면
  3단계에 센다(`DirectedCharmSupport.LiftsDesignatedTarget`, 채점·배정 비용·설명 세 곳). 결론은 PLACEMENT-OBJECTIVE 의
  "제 몫을 주는 지원만 센다" 에 있다.
- **멀티 사망.** `GameReader` 가 죽으면 가방을 읽지 않았다(2026-08-30 `d444c07`, 끝난 런의 배치를 지우려던 것). 게임 1.1.4
  디컴파일로는 멀티에서 죽어도 동료가 살릴 수 있고, 가방 열기와 `GridInventory` 에 사망 검사가 없다. 이제 죽었고 게임 오버
  창(`UI_GameOverLabel`)이 열렸을 때만 런이 끝난 것으로 본다. 죽은 동안의 F8 은 새 문구로 거절한다 - 서버가 죽은 플레이어의
  쓰기를 어떻게 다루는지 못 봤다.
- **검증.** 회귀 시험 둘(`BreakthroughAdversarialTests`)은 수정 전에 실패하고 뒤에 통과한다. 되살린 출발 배치에서 돌파가
  제자리에 남는다. 제보의 F10 재현 자료는 수정 전 코드로 저장 결과와 일치했고, 수정 뒤에는 제안이 달라진다(사슬을 2열 대신
  1열에 두고 점수 267.68 → 266.62, 옮기는 수가 줄어든다 - 대상 → 돌파 → 침 넷은 그대로다). `check.ps1` 통과(테스트
  1099개, 게임 1.1.4 로 두 판 빌드까지). 돌파를 세지 않던 때의 기대값 하나(`CompassTests` 의 지원 수 1)를 2 로 고쳤다.
- **하지 않은 것.** 점수가 바뀌는 변경인데 Windows 의 47개 재현 대조를 못 했다. 플러그인 쪽은 시험이 없고 게임에서 못 봤다 -
  STATUS 표의 0.6.6 두 줄.
- **0.6.6.** 사용자가 0.6.6 으로 정해 버전을 올리고 [변경 기록](CHANGELOG.md)에 옮겼다. 태그와 릴리스는 만들지 않았다.
- **게임 판.** 1.1 계열이 정식이 됐고 Mac 설치본이 1.1.4 다. STATUS 의 "게임 버전" 에 적었다.

## 다음 세션

### 먼저: 전체 검증 (사용자 요청, 2026-11-19)

사용자가 다음 세션에서 **프로젝트 전체에 버그나 회귀가 없는지 검증**해 달라고 했다. 조건은 하나다: **문서와 주석을
맹신하지 말고 스스로 판단한다.**

- 문서(이 파일과 STATUS·RESEARCH·PLACEMENT-OBJECTIVE 포함), 주석, 커밋 메시지, 시험 이름은 누군가의 주장이다. 무엇을 볼지
  고르는 실마리로만 쓰고, 판정은 코드를 읽고 돌려 본 결과와 게임 어셈블리 디컴파일(지금 설치본은 1.1.4)로 내린다. 문서와
  코드가 어긋나면 어느 쪽이 맞는지를 직접 확인한 뒤에 말한다.
- 통과하는 시험도 증거로 치기 전에 무엇을 단언하는지 본다. 기대값이 구현을 따라 적힌 시험은 회귀를 못 잡는다. 이번 세션도
  `CompassTests` 의 기대값 하나를 규칙 변경에 맞춰 고쳤다 - 그 판단이 옳았는지도 검증 대상이다.
- 이번 세션의 수정 둘(`DirectedCharmSupport.LiftsDesignatedTarget` 과 그것을 부르는 세 곳, `GameReader.RunEnded`)을 남의 코드처럼
  다시 본다. 특히 돌파를 세는 조건이 채점·배정 비용·설명 세 곳에서 같은 뜻인지, 증분 채점(`PolishScoring`)과 어긋나지 않는지,
  게임 오버 창이 뜨기 전후의 틈과 1.0.33 에서 `UI_GameOverLabel` 참조가 풀리는지.
- 게임 1.1.3·1.1.4 에서 바뀐 것이 우리 모델(질의·회전·레벨 계산·나침반·합성·배치 보너스)과 플러그인의 게임 참조를 깨지
  않았는지 디컴파일로 본다. 지금까지 1.1.4 에서 본 것은 사망·부활·게임 오버 경로와 제보 한 건의 로그뿐이다.
- 확인하지 않은 단서 하나: `PlanReplay.SupportedCatalogVersions` 가 `{ 29, 26, 25, … }` 라 27·28 이 빠져 있다.
  `PlannerData.CatalogVersion` 이 27 이던 커밋은 `v0.5.0` 부터 태그에 들어 있다. REPRODUCTION 은 형식을 올릴 때 바로 아래 번호를
  더하라고 한다. 그 판들의 제보가 재생되는지 직접 돌려 본다.
- 찾은 것은 재현(실패하는 시험이나 돌린 명령의 출력)과 함께 보고한다. 재현하지 못한 의심은 의심이라고 적는다. 이 Mac 에는
  `reports/` 와 47개 재현 자료가 없다 - 못 돌린 검사는 못 돌렸다고 적는다.
- 고치는 것은 사용자에게 보고한 뒤다. 0.6.6 은 아직 태그가 없어 수정이 이 판에 들어갈 수 있다.

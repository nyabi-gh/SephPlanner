# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-04 밤 - 문서·메모리 전체 정리 (Windows)

사용자 요청은 "문서 및 메모리 전체 갱신, 전체적으로 검토해서 가독성 좋게, 불필요한 내용은 빼 달라" 였다. 사용자가 정한 것은
셋이다 - README·INSTALL·USAGE 는 창작마당(1.1 베타)과 ZIP(BepInEx) **둘 다 안내**, STATUS 실기 표는 **볼 수 없는 줄만 지움**,
용어는 **과도한 로컬라이징 금지**("내려받기" 가 아니라 "다운로드").

- **사용자 문서.**
  - README 다섯 벌: 받는 곳 표와 설치 절을 두 길로 나누고, F7 로 펼치기, 단축키가 안 듣는 두 경우, 구독 취소를 넣었다.
  - INSTALL.txt: "아직 공식 모드 지원을 하지 않으며" 를 고쳤다.
  - USAGE: 점수 옆 사유 여섯, 창작마당 판의 `Player.log`, 제보 번호 다시 찾기(`upload-result.txt`)를 넣고 빌드 지정·제보 절을
    다시 묶었다.
- **개발 문서.** 파일마다 경위·끝난 일감·중복을 걷고 코드와 다른 사실을 고쳤다.
  - 가장 큰 것은 PLACEMENT-OBJECTIVE 의 이동 비용(`MoveCost` 0.3점)이다. 2026-09-09 `3cb54aa` 에서 코드에서 빠졌는데 문서에
    남아 있었다. 지금은 비교 순서 9단계의 자리 유지 몫만 있어, 점수가 한 눈금이라도 높으면 이동이 많아도 이긴다.
  - STATUS 실기 표는 보관 제보 51건과 이 PC 로그로 줄마다 따져 열여섯 줄을 지웠다. 확인된 것은 표 아래 목록으로 옮겼다.
  - 전체 크기는 거의 그대로다(HANDOVER 빼고 454KB → 451KB). README 가 두 길을 안내하며 늘었고, DIAGNOSTIC-UPLOAD·LEGAL 은
    한 줄짜리 긴 문단을 풀고 코드에서 확인한 사실을 더해 늘었다. RESEARCH·PERFORMANCE·PLACEMENT-OBJECTIVE·STATUS 는 2~9% 줄었다.
- **게임 사실 하나 추가.** 처음 한 번 뒤에 구독한 창작마당 모드는 저절로 켜지지 않는다 - 타이틀의 창작마당 창에서 켜야 한다
  (1.1.1 디컴파일, [게임 내부 조사](RESEARCH.md) "공식 모드 API"). README 는 "켜져 있는지 확인" 으로 적었다.
- **메모리.** 44개를 27개로 줄였다. 이미 고쳐 문서에 기록된 제보별 메모는 "불일치 제보 진단법"·"측정 방법" 둘로 합쳤다.
- **확인.** `scripts/check.ps1` 이 통과했다(테스트 1,029개, 경고 0). 문서 사이 링크·앵커와, 코드가 따옴표로 가리키는 절 이름을
  스크립트로 대조해 깨진 곳이 없었다. 게임 실기는 아직 하나도 안 했다.

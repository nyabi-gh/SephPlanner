# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의
길잡이다.** 둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 덮어쓴다 - 날짜별로 쌓지 않는다.

## 2026-09-13 (둘째 세션)

저장소를 합치고, 공개되면 안 될 것을 걷어내고, 문서를 정리했다. 코드는 한 줄
(`DiagnosticServerOptions.TrustedProxies` 기본값)만 바뀌었다.

### 1. 저장소를 합쳤다

**`nyabi-gh/SephPlanner` 가 이제 소스와 배포본을 함께 담은 공개 저장소**다. 옛 소스 저장소는
`SephPlanner-archive`(비공개·아카이브)다. 릴리스 스물둘·자산·다운로드는 건드리지 않았고 드래프트
`v0.3.9` 도 그대로다. 절차와 그때 정한 것들은 STATUS 의 **"저장소 공개와 합치기"** 에 있다.

**알아 둘 것 하나.** 옛 태그가 로컬과 원격에서 갈라져 있다. `git fetch --tags` 가 스물하나를
"would clobber existing tag" 로 거절하는 것이 정상이며 **`--force` 로 맞추지 않는다** - 릴리스
자산이 원격의 그 태그에 붙어 있다.

### 2. 공개 전에 걷어낸 것

- **`deploy/diagnostics`** — 진단 서버 인계 문서가 VPS 공인 주소·WireGuard 쌍·서버 경로와, 같은
  홈서버에서 도는 다른 서비스 이름까지 적고 있었다. 추적만 끊었고 파일은 배포 담당자 디스크에
  그대로 있다(`deploy/` 가 `.gitignore`).
- **`DiagnosticServerOptions.TrustedProxies` 기본값** — `["10.77.0.1"]` 이 박혀 있었다. 지금은 빈
  배열이고 `Validate` 가 그것을 막는다. **배포가 프록시를 지정하지 않으면 서버가 뜨지 않는다** -
  `compose.yaml` 이 이미 지정하므로 실제 운영은 그대로다.
- **개발사 담당자 실명** — `LEGAL.md` 연락처 표에서 이름을 빼고 역할만 남겼다. 히스토리에는 남아
  있다(파일 내용이라 메시지 재작성으로는 안 지워진다).

### 3. 히스토리를 한 번 다시 썼다

전 세션들이 커밋 메시지에 붙여 온 `Co-Authored-By: Claude …` / `Claude-Session:` 트레일러가
열여덟 개 있었고 저장소가 공개되면서 그대로 드러났다. `git filter-repo --message-callback` 으로
그 두 줄만 지웠다 - **트리는 한 바이트도 안 바뀌었다.**

`cf8b3f9` 이후 185개 커밋의 해시가 바뀌었고, 로컬 태그 스물하나는 filter-repo 가 옮겼으며, 문서가
인용하던 커밋 해시 예순 자리는 `commit-map` 으로 새 번호에 맞췄다. **공개된 릴리스 노트와 zip
manifest 가 적은 옛 커밋 번호는 되돌리지 못한다.**

`AGENTS.md` 가 트레일러 금지를 이미 적고 있다. **커밋 전에 메시지에서 그 두 줄을 지운다.**

## 다음 일감

**1. 0.3.9 실기 확인 — Publish 의 조건이다.** 드래프트에 든 셋을 게임 화면에서 아직 하나도 못
봤다. 볼 것은 STATUS 의 **"아직 배포하지 않은 것"** 에 있다 - 침의 강화 대상 선택, 모래시계 지정,
상점 사파이어 보충 칸이 후보로 뜨는지와 사고 나면 사라지는지. **Publish 는 사용자 몫이다.**

**2. 성능 — [성능과 응답성](PERFORMANCE.md).** 인게임에서 조언 918ms 가 가장 큰 덩어리이고 배치
800ms 는 사용자가 기다리는 시간이다. **다음 걸음은 재는 것이다** - 2번(갈래 견줄 때 다듬지 않기)은
갈래 하나의 절대 시간을, 3번(`Polish` 작업 공간)은 후보 8개짜리 할당을 다시 재야 하며 둘 다
조용한 기계를 요구한다.

**3. 인게임에서 못 본 것 둘이 성능 쪽에도 있다.** 합성 추천 거리 문턱은 합성기가 있는 층에서
F10 한 번이 필요하고, 동행 증표는 시나리오 퀘스트가 지나가 재현할 수 없다.

## 알아 둘 것

**CI 가 `v0.3.9` 태그에서 빨간 것은 정상이다.** `.editorconfig` 의 LF 수정(`f42f07b`)이 0.3.9 컷
뒤에 들어가서 그 태그의 트리는 여전히 포맷 검사에 걸린다. `main` 은 초록이다.

**`.gitattributes` 가 `eol=lf` 인데 `.editorconfig` 가 줄바꿈을 말하지 않으면** 윈도우의
`dotnet format` 이 자기가 다시 들여쓰는 줄에만 CRLF 를 쓴다. 로컬은 초록, CI 는 영원히 빨강,
`git status` 에는 아무것도 안 보인다. **파일을 통째로 다시 쓰는 편집을 한 뒤 포맷 검사가
이상하면 여기부터 본다.**

**대문 `README.md` 는 사용자용이고 개발 쪽은 [개발 문서](DEVELOPMENT.md)다.**

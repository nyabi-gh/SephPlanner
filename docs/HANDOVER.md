# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의
길잡이다.** 둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 덮어쓴다 - 날짜별로 쌓지 않는다.

## 2026-09-23

**0.4.12 는 2026-09-22 에 공개됐다.** 직전 인계와 STATUS 는 둘 다 드래프트라고 적고 있었고
STATUS 는 그보다 두 판 밀린 0.4.10 을 최신이라고 말했다. 이번에 바로잡고, 그 뒤의 수정을
**0.4.13** 으로 열었다(`Directory.Build.props`·`Plugin.cs`·`CHANGELOG.md`).

이번 세션은 [2026-09-22 전체 검토](notes/REVIEW-2026-09-22.md) 8절 우선순위표의 위쪽을 처리했다.
같은 날 두 번째 세션이 0.4.12 자동 제보를 받아 아래 "자동 배치 직후의 가짜 불일치" 를 고쳤다.

**0.4.13 은 2026-09-23 에 공개됐고 0.4.14 드래프트가 올라가 있다.** 0.4.14 는 석판 합성 추천의
회전 안내다. 합성 창은 돌릴 수 있는 석판을 가방에 놓인 방향으로 받아 우클릭마다 90° 돌리고, 돌릴
수 없는 석판은 0 으로 되돌린다(디컴파일, `docs/RESEARCH.md` 합성 절). 화면은 이제 절대 각도 대신
누를 횟수를 말하고, 같은 석판 둘로 만든 같은 합성은 한 줄로 합친다. 새 시험 6개로 고정했고 보관
제보 23건은 재생 결과가 같다(합성 추천이 든 둘은 해당 경우가 없다). **합성 창에서 실제로 눌러 보지
않았다.**

0.4.14 에는 **새 판에서 지난 판 지정 정리**도 들어간다. 판을 넘어 남은 ★ 가 꼬인다는 제보가 여러 번
와서, `HorayModAPI.OnStartSessionClientside(false)` 뒤 가방이 처음 읽힐 때 가방에 없는 아이템의
직접 지정을 지운다(`PluginPreferences.ForgetAbsent`). 빌드 코드와 콤보 우선은 남고 F3 에서 끌 수
있다. 신호의 근거는 `docs/RESEARCH.md` "공식 모드 API". 사망 직후 옛 아바타가 남아 있는 동안
가방이 읽히면 지난 판 아이템이 "있음"으로 잡혀 덜 지워질 수 있는데, 이것도 실기로 봐야 한다.

같은 판에 **가방에서 바로 ★/▽ 바꾸는 단축키 둘**(`PinUpKey`·`PinDownKey`)도 들어간다. 게임이
선택으로 보는 칸(`EventSystem.currentSelectedGameObject` 의 `UI_NewInventoryIcon`)이 내 가방의
아티팩트일 때 `StepPin` 을 부른다. 기본 키는 비워 두었다 - 남은 F 키는 F11·F12 뿐이고 창 모드 전환과
Steam 스크린샷에 걸린다. 빈 키에서 BepInEx `IsDown` 이 거짓인 것은 BepInEx.dll 로 확인했다.

### 자동 배치 직후의 가짜 불일치 (두 번째 세션)

0.4.12 자동 제보 5건(`298610ac`·`6706612d`·`71aa435f`·`8ca30079`·`bbb6e850`, 사람 셋)이 전부
단일 플레이 호스트의 `시뮬레이션 불일치` 였고, 모두 "자동 배치 완료" 와 같은 밀리초에 찍혔다.
한 세션에서 26번 났고 다음 폴링에서는 다시 통과했다. 지목된 석판은 매번 그 배치에서 옮겨진
것이다(재현 파일의 `PreviousTargets`).

원인은 0.4.12 에서 들어온 `FixedEffectLayer.Get` 의 프레임 캐시다. 호스트의 자동 배치는 키를
누른 프레임 안에 통째로 끝나므로(`PlanApplier.Apply`), `AutoPlace` 가 적용 전에 만든 뷰를
같은 `Update` 의 `PollGameState` 가 다시 꺼내 게임의 새 `EffectRange`·행렬과 견줬다. 배치
자체는 맞았다 - 적용 루틴의 레벨 확인은 통과했다. 0.4.11 은 검사마다 뷰를 새로 지어 없었다.

`31fc519`: 적용기가 끝나면 `FixedEffectLayer.Invalidate()` 로 캐시만 버린다. `Forget()` 은
고정 효과 추적 기록까지 지우므로 쓰지 않는다. 플러그인이 게임 상태를 바꾸는 새 경로를 만들면
같은 캐시를 비워야 한다. `check.ps1` 통과, 5건은 `reports/` 에 보관했고(메모 없음, 이제 23건)
현재 빌드로 전부 종료 코드 0 으로 재생된다. **게임에서는 확인하지 않았다.**

0.4.13 변경 기록은 비개발자가 읽는다는 사용자 지적에 따라 내부 용어를 빼고 다시 썼다.
태그 `v0.4.13` 은 이 세션의 마지막 커밋으로 옮겼고 드래프트 zip 도 다시 올렸다.

### 코드

- **후보 조언의 콤보 가치가 배치 점수와 다른 눈금이었다**(검토 3-1). `ComboValue` 가
  `WorthScale.Default`(콤보 2.59)로 재는데 배치 점수는 카탈로그가 잰 `problem.Scale`(제보에서
  2.1768)로 재고, `Rank` 가 둘을 더해 줄을 세웠다. 콤보 가치가 약 19% 부풀어 후보 순위가
  뒤집힐 수 있었다. `problem.Scale` 을 넘기고, `Worth` 에 "표시용이며 채점에 쓰지 않는다"를 적었다.
- **기준 배치 캐시가 앞보기와 번갈아 서로를 밀어냈다**(검토 3-2). 자리가 하나이고 적중이
  `ReferenceEquals` 라, `BestTrial`(지금 판)과 `GainOf`(늘어난 판)가 후보마다 상대를 밀어냈다.
  자리를 넷으로 넓히고 `BaselineSolves` 계측을 붙여 `SolverCostTests` 로 고정했다.
  합성 가방(칸 34, 후보 8)에서 **기준 배치 16번 → 2번, 벽시계 712ms → 613ms**(개발 PC, 5회 평균).
  인게임 값은 아니다 - 제보의 `[perf]` 로 다시 봐야 한다.
- **진단 동의 저장이 실패해도 메모리 상태는 동의로 남았다**(검토 4-1). "이번 진단은 로컬에
  보관합니다"라고 알리고도 다음 F10 부터 전송됐다. 자동 쪽과 같은 복원을 넣었다.
- **`LookupMatrix` 가 SyncDictionary 를 선형으로 훑었다**(검토 4-2). `ItemPosition` 은
  `Equals`/`GetHashCode` 를 갖췄고(게임 어셈블리 디컴파일로 확인) 같은 자료를 다른 두 곳은
  이미 `TryGetValue` 로 읽는다. 폴링당 약 2,268회 비교가 없어졌다.
- **리플렉션 실패가 조용했다**(검토 4-4). `GameBinding` 이 세 자리를 잡고 못 잡으면 한 번
  알린다. 유니티가 아니라 플러그인 로거로 보내야 진단 묶음(`sephplanner.log`)에 들어간다.
- **자동 배치 거절 문구의 내부 용어**(검토 5-6). `generation`·`상태 지문` 둘을 바꿨다.

### 문서·도구

- **README 단축키 표가 2026-09-16 표기 검수 이전이었다**(검토 5-1). 폐기된 이름 다섯과
  `F9` 의 옛 이름을 화면 라벨로 맞췄다. 빌드 창 안내문의 `프리셋 코드` 도 버튼과 같은
  `빌드 코드` 로 고쳤다.
- **`deploy-plugin.ps1` 이 아무것도 배치하지 않아도 성공했다**(검토 6-2). `DeployToGame` 의
  `Exists` 조건을 `Error` 로 바꾸고, 스크립트가 MSBuild 에서 경로를 받아 배치된 DLL 둘의
  해시를 방금 빌드한 것과 대조한 뒤 목적지를 알린다. 실패 경로와 성공 경로를 모두 돌려 봤다.
- **STATUS 의 배포 상태를 한 줄로 줄이고 `make-release.ps1` 이 대조한다**(검토 7-1).
  버전·날짜가 붙은 과거 절은 `## 지난 릴리스 기록` 아래로 옮겼고, 완료 기준에서 `형식 22`
  와 `0.3.7 드래프트` 를 걷어냈다. 시험 개수는 STATUS 에서 뺐다 - 갱신을 강제하는 것이 없는
  자리에 숫자를 두면 곧 틀린 수가 된다(721 대 809 였다).
- **ROADMAP 의 "씬 탐색이 메인 스레드의 78%"** 는 같은 불릿의 본문이 "이미 걷어냈다"라고
  말하는데도 제목이 남아 있었고, 직전 인계가 그 제목을 읽고 최우선으로 추천했다(검토 7-2).
  제목을 본문에 맞추고, 지금 열려 있는 것이 `OfferReader.Fill` 뿐임을 적었다.

### 검증

- `scripts/check.ps1`: 시험 809개(새로 둘), 포맷 검사, 진단 도구와 게임 플러그인 빌드 통과.
  경고 0개.
- 새 시험 둘은 고치기 전 코드에서 실제로 실패하는 것을 확인했다.
- 보관 제보 18개를 변경 전(`d33afcd`) 작업 트리와 나란히
  `--reproduce --allow-model-change` 로 돌렸다. 출력이 어셈블리 식별자를 적는
  `계산 코드 차이` 줄 하나만 빼고 18개 모두 바이트까지 같다. 콤보 눈금 수정은 후보 순위를
  바꿀 수 있는 변경이라 이 확인이 필요했다.
- **게임에서는 아무것도 확인하지 않았다.** 거절 문구, README 표, 리플렉션 경고는 화면에서
  보지 않았다.

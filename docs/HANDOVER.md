# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

0.6.0 은 이미 GitHub 에 공개돼 있었다(04:09 UTC, 두 zip 모두 `47f1487`). 게임의 `WorkshopLocal/sephplanner` 는 11-02 빌드라
태그에서 다시 지었고(DLL 둘에 `47f1487` 이 박힌 것을 확인), BepInEx 는 게임 폴더의 `winhttp.dll` 을 `winhttp.dll.off` 로

- 첫 시도는 썸네일이 없어 게임이 거절했다. 도형만으로 그린 512×512 썸네일을 넣었다(`bb89fc0`). 스크린샷은 게임 업로더가
  한 장만 올리므로 Steam 글 페이지에 추가 이미지로 넣는다(사용자).
- 사용자가 게임에서 올렸다. 글 `3832790875`(목록에 없음), 검수 접수 `75NXoDoEzIKa`, 서버 상태 `checking`. 올라간 설명은
  영어 한 벌이다.
- `uploadticket.json` 은 저장소에 두지 않는다(ROADMAP "창작마당 이전").

## 다음 세션

1. **검수 결과 확인.** 승인되면 구독한 사본으로 켜 보고(로컬 사본과 함께 있을 때 어느 쪽이 실리는지는 `Player.log` 의
   `[WorkshopModManager]` 로 본다) 멀티도 본 뒤 공개로 바꾼다. 다른 언어 설명을 글에 넣을 수 있는지 본다.
2. **STATUS 표 맨 위 여덟 줄의 실기.** 특히 저주 둘(해골로 새 판), 별칭 키 단축키, BepInEx 판 회귀.
3. README·INSTALL·USAGE 를 창작마당 기준으로(BepInEx 판에서 넘어오는 안내, 창작마당 글 주소 포함).
4. **CI 의 가끔 실패하는 테스트 둘**(STATUS "원인을 모르는 채"). 사용자가 미뤘다.
5. 직전 인계에서 남은 것: 조건 칸이 낡은 석판(ROADMAP), HUD 불투명도 → Auto 언어 구독 → 첫 검증 안내.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의
길잡이다.** 둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 덮어쓴다 - 날짜별로 쌓지 않는다.

## 2026-09-22

최신 정식 버전은 원격에서 확인한 **0.4.11**이다. 이번 고정 각인 수정을 **0.4.12 드래프트용**으로
준비한다. 제목은 `SephPlanner 0.4.12`, 태그는 `v0.4.12`이며 사용자 요청에 따라 공개하지 않고
드래프트로 둔다. 릴리스 본문은 [변경 기록](CHANGELOG.md)의 해당 절에서 배포 스크립트가 추출한다.

### 참가자는 각인된 석판의 효과를 볼 수 없었다

자동 제보 `c44e9d2e`가 `시뮬레이션 불일치`로 반복해서 올라왔다. 20분 동안 8번 경고하고 5건이
전송됐으며 어긋난 칸이 매번 달랐다.

`tabletEngravingCount > 0`이면 `UI_CharacterStatusPanel.OnItemLongClicked`가 석판 각인을 보낸다.
서버는 효과를 칸별 표로 굽고 `ForceRemoveItem`으로 석판을 가방에서 지운다. 그 표가 들어가는
`fixedEngravingsOnServer`는 `InitSyncObject` 목록에 없고 SyncVar도 Rpc도 없다. 세피라이트 보상을
바로 각인하는 길은 석판이 가방에 들어오지도 않는다. 참가자에게는 출처를 되짚을 단서가 없다.

참가자는 게임의 네 행렬에서 보이는 석판·각인과 인챈트로 설명되는 몫을 빼 고정 효과를 되뺀다
(`FixedEffectResidual`). 되뺀 값은 정의상 행렬과 맞으므로 `FixedEffectTracker`가 성질로 가른다 -
고정 각인은 구워진 표라 아이템을 옮겨도 변하지 않는다. 석판이 그대로인데 배치를 따라 값이
변하면 시뮬레이터의 오차로 보고 연속 두 번부터 알린다. 호스트는 원본 목록을 쓰면서 같은 순간의
되뺀 값과 대조해 되빼기 자체를 검증한다.

2026-09-05에 넣은 신비 전용 복원(`MysticEngravings`)은 이 경로가 대신하므로 지웠다.

### 함께 고친 둘

자동 진단의 중복 제거가 문장을 그대로 열쇠로 써서, 좌표만 다른 같은 오류가 한 세션에서 열 번까지
올라갔다. 숫자를 지운 모양으로 묶는다(`AutomaticDiagnosticPolicy.Shape`).

진단 덤프가 끊긴 석판·각인 참조를 조용히 건너뛰어 "0개"와 "전부 null"이 파일에서 구분되지
않았다. 이번 규명이 오래 걸린 이유다. 총 개수와 끊긴 수, 석판 각인권, 서버·참가자 구분,
적용 중인 고정 효과를 적는다.

### 검증과 남은 확인

- 첨부 자료의 실제 숫자로 되빼기 전 어긋난 칸 7개, 되뺀 층을 넣으면 0개를 확인했다.
- 보관 제보 18개를 HEAD 작업 트리와 나란히 `--reproduce --allow-model-change`로 돌려 전후 결과가
  모두 같았다. 일부 자료의 기존 차이는 이번 변경 이전부터 있던 것이다.
- `scripts/check.ps1`: 테스트 807개, 포맷 검사, 진단 도구와 게임 플러그인 빌드 통과.
- 실제 게임에서 참가자가 석판을 각인하는 세션은 확인하지 않았다. 호스트의 원본 대조도 실기
  자료로는 아직 받지 못했다. 배포하면 호스트 제보가 이 대조를 대신 돌려 준다.

### 다음 세션

**0.4.12 공개가 먼저다.** 디스코드로 오던 자동 제보가 멎고, 호스트 제보가 되빼기 대조를 대신
돌려 준다. 드래프트와 설치 ZIP 은 준비돼 있고 원격 자산 해시·manifest 커밋·태그를 대조해 뒀다.

그 뒤의 순서는 [남은 작업](ROADMAP.md)에 항목으로 넣어 두었다. 이번 수정에서 나온 것은 다섯이다.

1. **참가자 각인 세션의 실기 확인과 호스트 대조 발생 여부** (ROADMAP 1번). 공개해야 돌아간다.
2. **배치 불변성 검사를 자동 배치 이동에 붙이기** (ROADMAP 2번 "검증·도구·빌드"). 참가자 자리의
   검증이 약해진 것을 되돌리는 길이고, 자동 배치가 이미 만드는 이동을 쓰면 된다.
3. **되빼기 비용 확인** (ROADMAP 2번 "매 프레임"). 다음 제보 `[perf]` 의 `시뮬` 항목만 보면 된다.
4. **어긋남 상태의 점수를 어떻게 보일지** (ROADMAP 2번 "판단이 필요한 것"). 지금은 경고만 띄우고
   추천은 그대로 나간다.
5. **`GameReader.LookupMatrix` 선형 탐색 정리** (ROADMAP 2번 "매 프레임"). 작은 것이다.

저장소가 전부터 열어 둔 것 중 근거가 가장 단단한 것은 **씬 탐색이 메인 스레드의 78%** 다
(ROADMAP 2번). 제보 `[perf]` 근거가 이미 있고 세션이 길수록 나빠진다.

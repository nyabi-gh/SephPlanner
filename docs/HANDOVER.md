# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-05 - 0.4.22 Mac ZIP, 문서 정리

**0.4.22 는 드래프트다(미공개).** 태그 `v0.4.22` = `f8e177b`. Windows ZIP 과 Mac ZIP 이 둘 다 올라가 있고 두
manifest 의 커밋이 태그와 같다. 본문은 CHANGELOG 절 그대로다. 태그 뒤 `main` 에는 문서와 주석만 바뀐 커밋이 있다.

**두 ZIP 의 `설치안내.txt` 끝에 낡은 "0.2.8 기반 후속 패치 안내" 절이 실려 있다.** `main` 의 INSTALL.txt 에서는
지웠다. 0.4.22 를 다시 자르지 않고 다음 판부터 빠지게 두었다 - 천칭 규칙 설명이라 틀린 내용은 아니고, 다시
자르려면 태그를 옮기고 두 ZIP 을 새로 만들어야 한다.

문서 정리. 정보를 지우기보다 맡은 문서로 옮겼다.

- **RESEARCH 는 게임 규칙만.** 탐색 구조·옮기는 순서·제안 안정화·레벨 상한은 PLACEMENT-OBJECTIVE 로, 스레드와
  GC 는 PERFORMANCE "왜 할당을 재는가" 로, 성장 아티팩트의 게임 규칙은 ROADMAP 에서 RESEARCH 로 왔다.
  `WorthScale` 이 다시 재는 콤보·값어치 눈금은 문서에 숫자로 적지 않는다.
- **ROADMAP 은 백로그와 고치지 않기로 한 것만.** 측정 기준선은 PERFORMANCE 로 갔다. "ROADMAP 5번" 같은 번호
  참조는 절 이름("알려진 한계")으로 바꿨다 - 코드 주석 하나 포함.
- 낡은 사실을 고쳤다: REPRODUCTION 의 형식 번호(정본은 `PlanReplay`)와 `--replay` 종료 코드, DIAGNOSTIC-UPLOAD
  의 0.2.7 머리말, DEVELOPMENT 구조도의 `SephPlanner.Diagnostics`, RESEARCH 의 옛 F2 이름과 `Retire` 위치,
  "콤보는 후보 추천에만" 이라던 문장(`ComboDefinition` 주석도).
- LEGAL 은 문의 원문 대신 그때 개발사에 말한 것과 지금 다른 점(BepInEx 동봉, 멀티 자동 배치, 소스 공개)을
  목록으로 남겼다.
- PERFORMANCE 의 "아직 인게임에서 못 본 것 둘" 은 STATUS 표로 옮겼다.

손대지 않은 것: CHANGELOG 0.3.7~0.4.2 는 형식 규칙(0.4.3 부터) 이전의 공개 본문이라 두었다. 0.4.22 의 치명타
상한 줄은 Changed 쪽이 맞다는 의견이 있었지만 드래프트 본문과 갈라지므로 두었다. PERFORMANCE 의 2026-09-12
측정 표들은 다른 절이 가리키고 있어 남겼다.

검증: `scripts/check.ps1` 통과(커밋마다).

## 다음 세션

0. **실기.** STATUS 표 맨 위 여섯 줄(0.4.22). 업데이트 안내는 `SephPlanner.Core.dll` 만 0.4.21 것으로 두고
   켜서 본다. 확인한 줄은 지운다.
1. **0.4.22 공개.** `scripts/publish-release.ps1`. 공개는 사용자가 정한다.
2. **cold 빈도.** 0.4.22 제보의 `[perf]` 에서 "각도" 가 "구성" 보다 크면 빔 열쇠에서 각도를 빼는 일을 사용자와
   정한다 - 추천이 바뀌고 `--churn` 확인이 필요하다.
3. **게임 없이 할 수 있는 것**(제안 순): 진단 자료(`inventory-snapshot.json`·`plan.replay`)의 개인정보 가림과 `?token=`
   꼴, 자동 진단 수집의 `[perf]` 구간(검토 4-3), `Update`·`OnDestroy` 의 `Guarded`, `CharmCriteria.ReadsNeighbors` 시험.
4. **요청 둘**(F1 선호도, 고사양 모드)과 운영 문서(검토 7-4~7-7)는 사용자 결정을 기다린다.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

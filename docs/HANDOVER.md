# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-03 - 0.6.0 검토와 수정 셋 (macOS)

0.6.0 전체를 검토했다(지난 일주일 커밋, 솔버·계획, 적용·게임 읽기, 호스트 분리·창작마당 판). 잘못 쓰거나 점수를 틀리게
내는 경로는 없었다. 고친 것 셋을 0.6.0 에 넣었다(사용자 결정). `check.ps1` 통과(1026개, 경고 0, 창작마당 판 빌드 포함).
이 Mac 에서 테스트를 여러 번 돌려도 CI 의 가끔 실패는 재현되지 않았다.

- **별칭 키 단축키**(`2f0fdfe`): RightAlt·AltGr, LeftCommand·LeftWindows 가 한 물리 키라 하나만 적힌 단축키가 듣지 않았다.
  판정을 물리 키로(`Host/ShortcutMatch.cs`, 테스트 있음), 지정은 물리 키마다 이름 하나(값이 작은 쪽)로.
- **창작마당 판 동의 저장 실패**(`3cfe7a0`): `ISettingStore.Commit()` 은 못 적으면 예외. 진단 동의 두 곳만 쓴다. 다른
  `Save()` 는 시작 때 창작마당 판이 죽지 않게 그대로 두었다. 동의는 처음 나오는 판이라 CHANGELOG 에 넣지 않았다.
- **여러 칸 아이템 거절 이유**(`47f1487`): `PlanApplier` 가 칸이 아니라 원점으로 번호를 지어 `GameReader` 와 같아졌다.
- 영향이 낮아 고치지 않은 검토 결과는 ROADMAP 의 솔버·런타임 절에 "검토 2026-11-03" 으로 적었다.
- **릴리스**: 태그 `v0.6.0` 을 사용자 허락으로 `47f1487` 로 강제로 옮겨 밀었다. 드래프트의 zip 둘과 본문은 옛 커밋 그대로다.

## 다음 세션

1. **드래프트를 `47f1487` 로 다시 채운다.** Windows·Mac 에서 각각 이 태그만 다시 받고(`git fetch origin +refs/tags/v0.6.0:refs/tags/v0.6.0`.
   옛 태그가 갈려 있어 `--tags --force` 는 쓰지 않는다, DEVELOPMENT)
   `git checkout v0.6.0` 에서 `make-release.ps1`(HEAD 에 태그가 있어야 돈다) 후 `gh release upload ... --clobber`, 본문은 새 `artifacts/release-notes-v0.6.0.md` 로. 두 zip 의
   manifest 커밋이 `47f1487` 인지 본다.
2. **창작마당 등록**(사용자, 게임 안 "창작마당에 올리기")과 썸네일·설명글 검토. 등록 뒤에 공개(`publish-release.ps1`).
3. **STATUS 표 맨 위 여덟 줄의 실기.** 특히 저주 둘(해골로 새 판), 별칭 키 단축키, BepInEx 판 회귀.
4. **CI 의 가끔 실패하는 테스트 둘**(STATUS "원인을 모르는 채"). 사용자가 미뤘다.
5. README·INSTALL·USAGE 를 창작마당 기준으로(BepInEx 판에서 넘어오는 안내 포함).
6. 직전 인계에서 남은 것: 조건 칸이 낡은 석판(ROADMAP), HUD 불투명도 → Auto 언어 구독 → 첫 검증 안내.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

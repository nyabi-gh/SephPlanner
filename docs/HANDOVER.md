# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-16 - 외부 확장 통로 (Mac)

외부 기여자(마못)가 정령융합봉 일로니카(볼트 빌드) 보조 모드를 만들면서, 그 모드가 세피 플래너에 아티팩트 값어치를 넘길
통로를 제안했다. 모양을 좁혀 달라고 답했고, 그 모양대로 온 패치를 받아 0.6.5 에 넣었다(`d74c131`).

- **들어간 것.** `SephPlanner.Core.Extensions.IPlanExtension`(`Id` + `CharmValueFile? Values(GameSnapshot)`)과
  `PlanExtensions.Register`, `CharmValueEntry.ByLevel`. 폴링마다 확장 표를 기본 표 위에 덮어 계획·HUD·진단이 같이 쓴다.
  확장이 예외를 던지거나 쓸 수 없는 표를 주면 그 확장만 새 판까지 끈다. 진단 `report.json` 과 재현 자료에 `Extensions` 가
  남는다. 실험적이라고 DEVELOPMENT 의 "확장 모드" 에 적었다.
- **받지 않은 것.** `PlanPreferences.Scale`(눈금은 카탈로그가 재는 하나뿐이다)과 `IgnoreCriticalCap` 플래그.
- **우리가 고친 것.** F10 수동 진단의 `CurrentPreferences` 가 덮인 표를 빠뜨리던 것(`0303682`), 꺼짐 표시 주석(`b1f4786`).
- **로더 조사.** 확장이 우리 DLL 을 참조할 때의 규칙(의존 선언 필수, `version` 비우기, 우리 DLL 동봉 금지, `data` 모듈)은
  1.1.2 디컴파일로 확인해 [게임 내부 조사](RESEARCH.md)의 "모드 사이의 의존" 에 적었다.
- **약속한 것.** 치명 상한 감점(`CriticalCap.Penalty`·`CriticalModel.Of`)이 값어치 출처를 보지 않아, 손값(Curated) 아티팩트도
  게임 표의 치명타량으로 감점한다. 확장 전용 플래그 대신 Core 에서 고치겠다고 기여자에게 답했다. 지금 `charms.json` 에 실제로
  걸리는 아티팩트가 있는지는 아직 안 봤다.
- **검증.** `check.ps1` 통과(테스트 1095개, 창작마당 판 빌드까지). 확장 모드가 아직 없어 두 모드를 함께 띄운 실기는 없다 -
  STATUS 표 "외부 확장 통로".

## 2026-11-16 - 창이 크기 설정을 따르게 (Mac)

건의: "배치 버튼이나 클릭 상호작용 크기 조절이 되나, 스팀덱에서 쓰는데 애매하다". 건의자가 터치로 누르는지 스틱으로
고르는지는 모른다.

- **원인.** F3 의 `크기`(80~150%)는 구석 화면(`NativeHud`)에만 먹었다. 누를 것이 있는 창(`PlannerWindow` - 설정·빌드·제보·
  업데이트)은 `Skin.BaseSize` 를 그대로 기준으로 써서 늘 100% 였다. 패드에서 자동 배치는 설정 창 `동작` 탭의 버튼뿐이라
  스팀덱에서는 그 버튼 크기를 바꿀 길이 없었다.
- **고친 것.** 창의 기준 크기에 같은 배율을 곱한다(`PlannerWindow.Scale`). 배율이 바뀌면 언어를 바꿀 때와 같은 길로
  창을 버리고 다시 짓는다 - 열린 설정 창은 닫았다 다시 연다(`RebuildWindows`). 창이 화면보다 크면 `PlannerPanel.LateUpdate`
  가 들어갈 만큼 `localScale` 로 줄인다. 높이가 탭·쪽마다 달라 열려 있는 동안 계속 본다. `UIBase` 에는 `Update`·`LateUpdate`
  도 크기 애니메이션도 없다(1.1.x 디컴파일).
- **하지 않은 것.** 버튼의 눌리는 영역(글자 한 줄 높이 1.5배)은 그대로다. 크기를 올려도 모자라다는 답이 오면 줄 높이와
  여백을 키운다. 크기를 바꾸면 설정 창이 다시 열리면서 초점이 탭 줄로 돌아가, 패드로 여러 단계를 올리려면 매번 `크기`
  줄까지 다시 내려가야 한다(언어를 바꿀 때와 같다).
- **검증.** `check.ps1` 통과(경고 0, 창작마당 판 빌드까지, 1.1.x 설치본). 화면 코드라 시험은 더하지 않았고 게임 화면으로는
  보지 못했다 - STATUS 표 "창이 크기 설정을 따름".

사용자가 0.6.5 로 정해 버전을 올리고 [변경 기록](CHANGELOG.md)에 옮겼다. 태그·GitHub 릴리스·창작마당 업로드는 아직이다.

## 다음 세션

1. **돌파 실기**(게임, 사용자). STATUS 표 "돌파의 나침반 끼워 넣기". 제보자에게 남은 항목("1." 뒤)을 런 도중 F10 으로 다시
   받으면 좋다.
2. **F9 로 새 측정 덤프**(게임, 사용자). 카탈로그 판 29 라 덤프가 없으면 재현 대조가 옛 표로 돈다.
3. **0.6.4 창작마당.** GitHub 은 11-16 에 공개했다(Mac ZIP 을 `v0.6.4` 에서 지어 더했다). 남은 것은 창작마당 승인 확인
   (`[ModGuardReviewStatus]`)과 올린 뒤 설명 다시 붙여 넣기다.
4. **게임 실기.** 날개와 천 갑옷(탐욕 20레벨 특전이나 패시브 오브젝트로 `ARRANGEMENT_BONUS` 를 얻은 판)에서 추천이 둘을 떼어
   두는지와 안내 줄, 걸으면서 누른 단축키, 다시 뜨는 동의 창, 금반지의 성장 표시, 상인 금고 재고의 가격(3-2), 조언 실패 문구,
   STATUS 표의 0.6.1·0.6.0 줄. 멀티 둘은 `winhttp.dll.off` 를 `winhttp.dll` 로 돌려 BepInEx 판으로 본다.
5. **창 크기 실기**(게임, 사용자). STATUS 표 "창이 크기 설정을 따름". 건의자에게 터치인지 스틱인지와, 올린 크기로
   충분한지를 묻는다. 본 뒤 0.6.5 를 배포한다.
6. **치명 상한과 손값.** 위 "약속한 것". 손값 아티팩트에 상한 감점을 어떻게 볼지 정하고 고친다. 솔버 점수가 바뀌므로
   Windows 에서 47개 재현 대조가 필요하다.
7. **외부 확장 통로 실기.** 기여자의 확장 모드가 나오면 STATUS 표 "외부 확장 통로" 를 본다. 0.6.5 가 창작마당에 올라가야
   기여자도 실제로 붙여 볼 수 있다.
8. **검토 10절 5·6단계**(화면 7-x, 성능 6-3·6-4, 구조 9-x, 배포 8-2·8-3)와 낮음 항목(4-7~ 등)은 그 뒤다. 4-3 의 "못 박힌
   아티팩트도 빔의 `Items` 에 들어가 빈 칸 하나를 차지한다" 는 이번에 고치지 않았다.
9. 이전 인계에서 남은 것.
   - 창작마당 설명을 어디에 둘지(사용자). 검토 8-4 는 `metadata.json` 의 다섯 언어 `info.description` 으로 이미 정해진 것으로
     봤다 - 확인만 하면 된다.
   - 구독한 사본 실기(`[WorkshopModManager]` 로 어느 쪽이 실리는지).
   - 제거·인챈트 조언의 후보 나누기(PERFORMANCE 1c).
   - RESEARCH 의 솔버 정책·구현 설명을 PLACEMENT-OBJECTIVE·PERFORMANCE·DEVELOPMENT 로 옮길지(사용자).
   - 코드 쪽에서 틀린 것: `check.ps1` 주석의 "멀티 로비가 metadata 판을 견준다", `OfferReader.cs` 주석의 `FindObjectsByType`,
     번체 `配置異常`, `LayoutCache.cs`·`SolverCostTests.cs` 의 "48GB" 대 PERFORMANCE "40GB".
   - 조건 칸이 낡은 석판(ROADMAP), HUD 불투명도 → Auto 언어 구독 → 첫 검증 안내.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-19 - 전체 검증 (Mac, 게임 1.1.4)

사용자가 요청한 "문서와 주석을 믿지 말고 전체를 검증" 을 했다. 판정은 코드를 읽고 돌린 결과와 1.1.4 디컴파일로 내렸다.
찾은 것 가운데 둘을 고쳤고 나머지는 [백로그](ROADMAP.md) "런타임·업데이트" 에 옮겼다.

- **직전 수정 둘은 문제없다.** 돌파(`LiftsDesignatedTarget`)는 채점·배정 비용·설명 세 곳이 같은 조건이고, 게임
  `RequestCharmDamageBonusOnRoot` 를 그대로 옮긴 오라클과 무작위 6000판에서 어긋남이 없었다. 증분 채점은 나침반을 늘 다시
  재고 지원 수는 캐시 밖에서 센다. `CompassTests` 의 지원 수 1 → 2 는 규칙과 맞다. `RunEnded` 는 1.1.4 의 게임 오버 경로와 맞다 -
  창은 접속자 전원이 죽고 `dieIsGameOver` 일 때만 열리고, 죽음과 창 사이의 틈에는 `PlanApplier` 가 쓰기를 거절한다.
- **고친 것 1: 옮기는 도중의 합치기**(`6d2707b`). 합치기 검사가 끝 배치에만 있어, 참가자의 자동 배치나 손 이동 도중에 재료가
  맞붙으면 게임이 합쳐 버릴 수 있었다. 이제 도중에도 새 덩어리가 생기지 않는 순서로 옮기고, 그런 순서가 없으면 적용을 막는다.
  결론은 RESEARCH "배치 보너스는 레벨을 바꾸지 않는다" 에 있다. 게임에서는 못 봤다.
- **고친 것 2: 카탈로그 형식 27·28 재생**(`bca6c52`). 0.5.0~0.6.2 가 쓴 형식 27 이 목록에서 빠져 그 판들의 재현 자료가
  거절됐다. 20 부터 지금 형식까지 전부 재생되는지 보는 시험을 더했다. 합성 입력으로만 확인했다.
- **1.1.4 대조.** 석판 질의·회전·조건·레벨 식·합성기·합치기·나침반·배치 조건과 플러그인의 리플렉션·Harmony 대상이 맞다.
  STATUS "게임 버전" 에 적었다.
- **하지 않은 것.** Windows 의 47개 재현 대조, 1.0.33(어셈블리가 없다), `DataTool --solve`·`--check`·`--replay`(로컬 덤프가 없다),
  게임 실기 전부.
- `check.ps1` 통과(테스트 1104개, 게임 1.1.4 로 두 판 빌드까지).

## 다음 세션

1. **47개 재현 대조**(Windows). 돌파 수정 전후로 돌린다. 돌파가 없는 판은 그대로여야 하고, 달라지는 판은 돌파가 지정
   대상의 사슬에 남는 쪽인지 본다. 합치기 수정은 레시피가 없는 판의 이동 순서를 바꾸지 않으므로 달라지면 안 된다.
   0.5.0~0.6.2 의 자료가 이제 재생되는지도 함께 본다.
2. **이번 판의 실기**(게임, 사용자). STATUS 표의 0.6.6 세 줄 - "옮기는 도중의 합치기", "멀티에서 쓰러진 동안의 화면",
   "돌파가 지정 대상의 사슬에 남는지". "돌파의 나침반 끼워 넣기"(0.6.4)도 함께 본다.
3. **0.6.6 배포.** 1·2 를 본 뒤 `v0.6.6` 태그, 두 기계의 `make-release.ps1`, `publish-release.ps1`, 창작마당 업로드 순이다.
4. **검증에서 남은 것**(백로그 "런타임·업데이트" 의 "검증 2026-11-19" 줄들). 먼저 볼 것은 긴 토큰 하나가 진단을 막는 정규식이고,
   그다음이 진단 서버의 남은 항목(저장소 밖 보안 검토 파일)이다. 0.6.6 에 넣을지는 사용자가 정한다.
5. **1.0.33 지원을 내릴지**(사용자). 1.1 이 정식이 됐다(11-02 에 "1.1 이 베타를 벗어나면" 으로 정했다). 남긴다면 Windows 에서
   1.0.33 에 `UI_GameOverLabel` 이 있는지 본다 - 없으면 런 중에 가방 읽기가 매번 실패할 것이다(추정).
6. **F9 로 새 측정 덤프**(게임, 사용자). 카탈로그 판 29 라 덤프가 없으면 재현 대조가 옛 표로 돈다.
7. **0.6.5 배포 기록.** STATUS 의 배포 상태에 창작마당에 올린 날짜·접수 번호와 Windows ZIP 여부가 비어 있다(사용자).
8. **게임 실기.** 날개와 천 갑옷(탐욕 20레벨 특전이나 패시브 오브젝트로 `ARRANGEMENT_BONUS` 를 얻은 판)에서 추천이 둘을 떼어
   두는지와 안내 줄, 걸으면서 누른 단축키, 다시 뜨는 동의 창, 금반지의 성장 표시, 상인 금고 재고의 가격(3-2), 조언 실패 문구,
   STATUS 표의 0.6.1·0.6.0 줄. 멀티 둘은 `winhttp.dll.off` 를 `winhttp.dll` 로 돌려 BepInEx 판으로 본다.
9. **창 크기 실기**(게임, 사용자). STATUS 표 "창이 크기 설정을 따름". 건의자에게 터치인지 스틱인지와, 올린 크기로
   충분한지를 묻는다.
10. **외부 확장 통로 실기.** 기여자의 확장 모드가 나오면 STATUS 표 "외부 확장 통로" 를 본다.
11. **기여자 답장**(사용자). 패치를 합친 것, 우리가 덧붙인 둘(F10 수동 진단, 꺼짐 주석), 치명 상한을 Core 에서 고친 것,
    0.6.5 배포 전에는 플레이어 쪽에 통로가 없다는 것을 알리는 초안을 11-16 세션에서 드렸다. 아직 보내지 않았다.

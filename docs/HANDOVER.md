# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-02 셋째 - 창작마당에 올릴 수 있는지 판단

코드는 바꾸지 않았다. 게임 1.1.0 의 공식 창작마당에 세피 플래너를 올릴 수 있는지 보았고, **올릴 수 있지만 창작마당용으로
고쳐야 한다**고 판단했다. 근거는 공식 [모드 제작 가이드](https://github.com/team-horay/sephiria_modding)(`be58e1e`)와
이 Mac 의 기본 브랜치 디컴파일이다. 1.1.1 은 디컴파일하지 않았다.

- 규칙과 우리에게 걸리는 것: [약관](LEGAL.md)의 "창작마당 모드 규칙". 막히는 것은 BepInEx 의존, 게임 안 업데이트, 진단
  전송(규칙 5)이다.
- DLL 모드의 형식과 기본 브랜치 macOS 빌드의 로더: [게임 내부 조사](RESEARCH.md)의 "공식 모드 API".
- 정한 것과 할 일: [백로그](ROADMAP.md)의 "창작마당 이전". 창작마당 하나로 배포(1.1 정식 출시 때 GitHub 릴리스를 닫음),
  BepInEx 마지막 판, 멀티 자동 배치는 기본 꺼짐, 진단은 개발사 답을 보고 정한다.
- **TEAM HORAY 에 진단 전송이 규칙 5 에 걸리는지 이메일로 물었다(2026-11-02 발송).** 물은 것: [약관](LEGAL.md)의 "진단 전송 문의".

이 Mac 에는 `ilspycmd` 가 없어 세션 스크래치에 설치해 썼다(`dotnet tool install ilspycmd --tool-path …`, .NET 10 에서는
`DOTNET_ROLL_FORWARD=Major`).

## 다음 세션 (Windows)

1. **TEAM HORAY 답을 [약관](LEGAL.md)의 "진단 전송 문의" 에 적는다.** 답에 따라 백로그 "창작마당 이전" 의 진단 항목을 정한다.
2. **1.1.1 디컴파일 대조**(백로그 "창작마당 이전" 1번). `WorkshopModBase`·로딩 순서·검수 조회·`local_only` 의 로비 처리.
   가이드와 다르면 [게임 내부 조사](RESEARCH.md)의 "공식 모드 API" 를 고친다.
3. 백로그 "창작마당 이전" 2번부터. 제보 코드로 가게 되면 `reports/` 의 실제 제보로 카탈로그를 뺀 크기를 먼저 잰다.
4. 직전 인계에서 남은 것: STATUS 표 맨 위 네 줄의 실기, 조건 칸이 낡은 석판(ROADMAP), 검토에서 남은 작은 것(HUD 불투명도 →
   Auto 언어 구독 → 첫 검증 안내).

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-26 - 0.4.26 자동 제보 다섯(0.4.27 열림)

0.4.26(태그 `v0.4.26` = `6f9af82`)은 2026-10-17 에 공개됐다. 그 뒤 들어온 자동 제보 다섯을 보고 `main` 에서
0.4.27 을 열었다. 푸시하지 않았고 공개하지 않았다.

- **참가자 친타마니**(`9fac8a07`). 참가자가 `dungeonTempLevels` 를 안 써서 발동 순간을 "배치를 따라 바뀜" 으로 셌다.
  이제 양쪽이 되빼기 전에 빼고 고정 칸에 다시 더한다(`FixedEffectLayer.Temporary`).
- **모드 석판 수치**(`6c1abf75`). 모드가 `None` 칸 수치에 석판 번호를 심었다. 효과 비교를 Core
  `TabletEffectComparison` 으로 옮기고, 수치는 게임이 읽는 레벨 더하기·배수에서만 견준다.
- **자동 제보 묶음**(`6d50beb6`·`fa581f2a`·`990421e4`). 칸 목록 길이만 달라 한 원인이 세 번 나갔다.
  `AutomaticDiagnosticPolicy.Shape` 가 되풀이 조각을 접는다.
- 그 세 제보의 원인은 우리 결함이 아니다. `RestartGameCoroutine` 이 `ForceRemoveAll` 의 예외를 삼킨 뒤 인챈트 표만
  비워 옛 인챈트가 칸에 남았다([게임 내부 조사](RESEARCH.md)의 "고정 각인은 서버에만 있다"). 사용자가 준 QoL 1.12.6
  소스는 행렬·인챈트 표를 건드리지 않는다. 예외를 낸 아이템은 모른다.

검증: `scripts/check.ps1` 통과(961개, 경고 0), Core `--no-incremental` 경고 0. 이 PC 의 저장소에는 옛 보관 제보
47건이 없어 `reports/` 에 이번 넷(fa581f2a 는 재현 자료가 없어 뺌)만 두었고, 넷의 재현 출력이 고치기 전후로 같다.
이 PC 는 게임이 `C:\Program Files (x86)\Steam\steamapps\common\Sephiria` 라 `SEPHIRIA_DIR` 이 필요하다.

## 다음 세션

1. **실기.** STATUS 표 맨 위 두 줄(0.4.27)과 그 아래 0.4.26·0.4.25 줄. 친타마니는 참가자 자리에서만 의미가 있다.
2. **다음 제보의 `[perf]` 로 정할 것 둘**(추천이 바뀔 수 있어 사용자와 정한다). "활성" 이 구성의 큰 몫이면 빔 열쇠에서
   지금 활성 빼기, 각도가 크면 각도 빼기([성능](PERFORMANCE.md) 4번).
3. 이전 인계에서 남은 것: 진단 자료 가림, 자동 진단 수집 계측, `Guarded`, `CharmCriteria.ReadsNeighbors` 시험.

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

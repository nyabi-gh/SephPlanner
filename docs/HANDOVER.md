# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-10-01 - 문서 정리

**0.4.21 은 2026-10-01 07:36 UTC 에 두 ZIP 과 함께 공개됐다(Latest, 태그 `v0.4.21` → `d7f0437`).** 그 뒤 커밋은
README 손질과 이 문서 정리뿐이라 다음 판은 아직 열지 않았다.

문서가 다시 불어나 있었다(39개 약 8,000줄). 원인은 셋이었다 - STATUS 가 릴리스 기록을 CHANGELOG·HANDOVER 와 세 벌로
들고 있었고, HANDOVER 가 롤링 규칙을 어기고 열흘 치를 쌓았고, `docs/notes/` 가 "고치지 않고 남긴다" 는 규칙 아래
17개 2,500줄로 자랐다. 사용자와 정한 대로 이렇게 했다.

- **`docs/notes/` 를 지웠다.** 아직 살아 있는 결론만 옮겼다 - 앞보기·탐색 보강·천칭 규칙은
  [배치 평가](PLACEMENT-OBJECTIVE.md), 효과 감사·예측 가능성·친타마니·교환 중 선택 상세는 [게임 내부 조사](RESEARCH.md)의
  "아직 모델 밖인 효과" 와 해당 절, 0.2.8 기준 결정은 STATUS "기준 버전". 두 전체 검토(09-05, 09-22)는 항목마다 지금
  코드와 대조해, 열려 있는 것만 [백로그](ROADMAP.md) 2번에 "검토 N-N" 번호로 옮겼다. 원문은 git 로그에 있다.
- **STATUS 를 정본 역할만 남겼다.** 지난 릴리스 기록·저장소 합치기·문서 총정리 경위를 걷고, 여러 문서에 흩어져
  있던 "게임에서 아직 못 본 것" 을 표 하나로 모았다. 문서 지도도 거기 있다.
- **ROADMAP 에서 닫힌 항목을 걷었다.** §1 은 정말 남의 손이 필요한 넷만 남았다.
- RESEARCH 는 게임 사실을 하나도 버리지 않고 "그때는 틀렸다" 식 경위만 걷었다.

검증: `scripts/check.ps1` 882개 통과, 경고 0. 코드에서 바뀐 것은 주석의 문서 경로 셋과 `audit-effects.py` 의 안내
문구뿐이다. 문서 사이의 상대 링크는 전부 살아 있다.

## 다음 세션

0. **실기.** [현재 상태](STATUS.md)의 "게임에서 아직 못 본 것" 표를 위에서부터. 확인한 줄은 표에서 지운다.
1. **멈춤 제보**(STATUS "원인을 모르는 채 남은 것"). 먼저 F8 경로에 시간 계측을 붙일지 사용자와 정한다.
2. **유니티 무의존 플러그인 파일을 테스트에 링크하고 `ItemIdentity` 시험**(백로그 "검증·도구·빌드", 검토 6-1·6-3).
3. **첫 실행 안내 소모, 경고 상한, 정보 알림, 패드 안내**(백로그 "화면", 검토 5-2~5-5).
4. **인계·중단 절차, 프라이버시 고지, 로컬 제보 사본 정책**(백로그 "운영·공개", 검토 7-4~7-6).

성능 쪽에서 근거가 가장 굳은 자리는 여전히 `PlanRunner.Submit` 의 지문 중복과 그 최악값이다(백로그 "매 프레임").

**문서를 새로 만들기 전에** STATUS 의 문서 지도에 들어갈 자리가 있는지 먼저 본다. 날짜가 붙은 보고서 파일은
만들지 않는다.

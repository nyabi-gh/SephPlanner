# 인계

직전 세션이 무엇을 했고 다음에 무엇을 할지. **[현재 상태](STATUS.md)가 정본이고 이 문서는 그날의 길잡이다.**
둘이 어긋나면 STATUS 를 믿는다. 세션마다 이 파일을 통째로 덮어쓴다 - 날짜별로 쌓지 않고, 제보별 조사 경위도
여기 남기지 않는다(결론은 해당 문서에, 경위는 커밋 메시지에).

## 2026-11-10 - 2026-11-09 검토의 정할 것과 작은 수정 (Mac)

[검토 2026-11-09](notes/REVIEW-2026-11-09.md) 10절 순서대로 했다. 항목마다 커밋을 나눴고(`56d7604`~`3338d6e`, 아홉 개)
푸시했다. 아홉 커밋 각각에서 `scripts/check.ps1` 이 통과했다.

- **정한 것**(사용자). 3-1 합치기형 배치 보너스는 배치에서 재료 인접을 금지하고 안내한다, 7-2 단축키는 수정키만 배타로 본다 -
  둘 다 [백로그](ROADMAP.md)의 "게임 1.1.2 에서 정한 것" 에 적었고 구현은 아직이다. 보안 문서 1 은 노출면 점검을 먼저,
  2 는 동의문에 보관 사실을 적기로 했다. 보안 문서는 저장소 밖 Mac 의 `deploy/review-2026-11-09-security.md` 에만 있어
  Windows 에서는 못 읽는다. 할 일만 옮기면 이렇다.
  - 1(공개 이력의 서버 배치 파일): 서버 노출면 점검은 사용자가 직접 한다. 이력 재작성은 점검 뒤에 따로 정한다.
  - 2(14일 삭제 약속과 개발 PC 의 `reports/` 보관): 동의문 다섯 언어(`DiagnosticConsentWindow.cs`)·`USAGE.md`·
    DIAGNOSTIC-UPLOAD 에 "계산 재현용 사본을 개발자 PC 에 둔다" 를 적고 `DisclosureVersion` 을 올려 다시 묻는다. 보관 기간은
    사용자가 아직 안 정했다.
- **고친 것.** 4-1(버릴 수 없는 석판을 제거·후보 조언에서 뺌), 3-2(금고 상인의 가격을 상점 창의 `ShopCharacter` 로 잼),
  3-3(성장 진행도는 `n/목표` 꼴만 읽음), 5-1(실행기가 없을 때 "최신 게임 상태를 읽는 중" 이 데이터 안내를 가리지 않음),
  5-2·5-3(조언 실패를 화면에 알리고 같은 판에서 물러섰다 다시 풂, 재시도 동안 실패 표시를 지우지 않음, 간격은 1초에서 두
  배씩 60초까지), 6-6(동의 열쇠·주소를 한 번만 지음), 6-7(같은 예외는 자동 진단 큐도 처음 한 번만), 8-1 셋(시험 어셈블리의
  최소 풀 작업자 수, `Expect100ContinueTimeout`, 게시 전 `IsCurrent` 읽기).
- **8-1 의 확인.** 이 Mac(10코어)에서는 `DOTNET_PROCESSOR_COUNT=4` 로 세 클래스를 세 번 돌려도 재현되지 않았다. 대신 작업자를
  CPU 로 채운 풀에 넣은 작업의 대기를 따로 재니 7,795ms(최소 수를 올리면 0ms)였다. CI 로그와 맞는지는 다음 CI 실패가 없을 때로
  확인한다. STATUS 의 "원인을 모르는 채" 에서 이 줄을 지웠다.
- **문서.** STATUS 게임 버전 표에 1.1.2, RESEARCH 의 배치 보너스 레시피 다섯과 상인 금고 재고의 주인.
- **확인.** `scripts/check.ps1` 통과(테스트 1,038개, 경고 0, 플러그인·창작마당 판 빌드). 새 시험은 고치기 전 코드에서 실패하는 것을
  봤다. 게임 실기는 안 했다 - 상인 가격(3-2)과 조언 실패 문구는 게임에서 봐야 한다.

### 아직 못 정한 둘

사용자가 직접 만든 동작이 아니라 의도를 모른다고 했다. 이력으로 찾은 것은 이렇다.

- **이동 수보다 점수가 앞선다.** `e720477`(2026-09-04)이 이동 비용 `MoveCost`(자리 하나당 0.3점)를 넣었다 - 실제 판에서 +3.35 를
  위해 열두 개를 옮기던 것을 막으려고였다. `3cb54aa`(2026-09-09, 본문 없는 큰 커밋)가 그것을 빼고 자리 유지를 비교 순서 9단계,
  점수 눈금 다음으로 옮겼다. 같은 커밋의 CHANGELOG 가 "이동은 그다음에 줄입니다" 라고 썼고 PLACEMENT-OBJECTIVE 도 그렇게
  적는다. 바꾼 것은 의도적이지만 왜 바꿨는지는 남지 않았고, `e720477` 이 막던 일이 다시 날 수 있다.
- **추천을 꺼도 프리셋의 콤보 우선이 남는다(검토 5-12).** 처음(`0db9142`, 2026-08-31)에는 프리셋을 가져올 때 양수 콤보를 사용자의
  `PriorityCategories` 에 복사했다. 그래서 주석의 "함께 쉰다" 는 처음부터 즐겨찾기(`PresetCharms`)만 가리켰고, 그것은 지금도
  추천을 끄면 빈다. `a5aecbf`(2026-09-05)가 복사를 `EffectivePriorityCategories` 로 바꾸며 동작은 그대로 두었다. 지금 동작이
  처음 의도와 같고 검토가 주석을 넓게 읽은 것으로 보인다.

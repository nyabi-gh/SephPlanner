# 현재 구현과 검증 상태

2026-09-11. `v0.2.8`을 기준으로 필요한 수정만 가져온 결과가 `main`에 있다. 카탈로그 형식은 21이며
DPS 중심 추천과 0.3.x 설정 화면은 포함하지 않는다.
0.3.5가 성장 아티팩트 지원과 석판 회전 잔상 수정을 담아 배포됐고 Latest다. 실기에서 `ESC`
취소와, 회전 알림이 가방을 닫은 채로도 석판 툴팁을 띄우던 회귀의 수정을 확인했다(RESEARCH.md 의
"회전"). 커서를 올려 둔 채 돌렸을 때의 테두리와 성장 아티팩트는 아직이다.
0.3.6은 강화 우선(★)의 점수가 뒤집혀 있던 것을 고쳐 준비 중이며 실기 확인은 아직이다 -
제보에서 시작한 경위는 [선호도 가중치](PLACEMENT-OBJECTIVE.md)에 있다. 여기에 점수 비교의
눈금(0.1레벨)과, 레벨을 올리면 손해가 커지는 아티팩트의 칸 설명을 함께 담았다.
게임은 1.0.31이며 아래 "게임 1.0.31 대조"에 이번 패치의 영향과 확인 범위를 적는다.
[기준과 패치 계획](BASELINE.md)에 범위와 검증 결과를 기록한다.
아래 표는 0.2.8의 구현 범위이며 이후 버전의 감사 문서와 혼동하지 않는다.

## 구현 범위

| 영역 | 현재 지원 | 남은 범위 |
|---|---|---|
| 석판·활성 | 질의·회전·인챈트·각인·친타마니 칸 효과와 현재 상태 대조 | 합성 인스턴스 질의의 게임 원본 전수 대조, 새 활성 조건 진단 |

| 사용자 지정 | 강화·양보는 이득에만 가중치, 끄기 허용 분리, 사용 유지·고정·열쇠와 종이의 콤보 우선 | 최소 레벨·좌표/회전 고정·프로필 |

| 수량·행 | 벨트·비늘·열쇠의 추가 능력치 환산 | 전체 증폭·전환·전투 효율 |

| 특수 콤보 | 게임 공통 데이터의 발동 단계 수집과 실패 처리 | 새 프리팹 실기 대조, 콤보별 전투 가치 |
| 망원경·휘장 | 이웃·행에 따른 추정 가치 | 대상의 실제 사용 가능 상태·타입·강화 중첩과 효과량 |
| 능력치 전환 | 진단 자료와 별도 상태 재현 실험 | 실제 기여·콜백 어댑터와 자동 배치 통합 |
| 자동 적용 | 상태·지문·회전·최종 위치 검사, 안전한 범위의 되돌리기, 불확실한 서버 쓰기 차단 | 최신 DLL의 참가자 회전·실패·복구 실기 |
| 재현 | F10의 게시 계획 입력·설정·카탈로그·직전 목표 보존과 독립 재생 | 인게임 저장·재생 및 저장 비용 실측 |
| 성장 아티팩트 | 목표 횟수와 바뀔 대상을 카탈로그에 수집, 싱글·호스트·참가자 모두 진행도를 읽어 진행한 만큼 바뀔 아티팩트 쪽으로 값어치를 끌어올림(다섯 칸) | 게임이 아직 한 번도 표시값을 보내지 않은 아이템은 비워 둠, 바뀔 대상의 값어치도 능력치 환산이라 전투 가치 측정은 아님 |

F2 콤보는 추천 OFF에서도 배치에 영향을 준다. `끄기 허용` 변경도 재계산과 오래된 계획의
적용 차단에 반영한다. 획득·제거·합성 추천은 원래 가방의 활성 보호를 함께 적용한다.

## 정확도와 측정

게임의 레벨 계산이 일치한다는 것, 모델의 점수가 재현된다는 것, 전투에서 좋은 선택이라는
것은 서로 다른 검증이다. `FullHP`는 배치 계산에서 만족으로 취급하며 미지 조건은 현재
`None`으로 해석한다. 레어도·공통 콤보 가치·일부 연결 효과는 추정이 남아 있다.

게임 1.0.31의 카탈로그는 아티팩트 311종, 석판 68종, 콤보 20종이다(형식 21). 능력치 표가 있는 것이
167종(잰 값이 값어치 전부 107종, 측정과 어림값 병용 60종), 레어도 어림값뿐인 것이 143종,
자체 활성 효과가 없어 값어치 0 이 답인 것이 1종이다. 이 숫자는 현재 전투 효과 지원율이 아니라
능력치 환산 여부일 뿐이며, 수동 가치 자료는 여전히 빈 배열이다. 과거 성능 수치도 최신 빌드의
측정값으로 재사용하지 않는다.

**레벨이 올라도 값어치가 내려가는 아티팩트가 네 종 있다.** 그런 구간에서는 낮은 레벨 칸이 정답이
되므로 "왜 낮은 자리에 두느냐"는 제보가 온다. 목록과 원인 능력치는 `DataTool --values` 가 적어
주며, 무엇이 걸려 있는지는 [백로그](ROADMAP.md)의 가치 데이터 절에 있다. 비단조 자체는
금지하지 않는다([배치 평가](PLACEMENT-OBJECTIVE.md)의 "탐색과 최적성"). 0.3.6 부터는 그 자리를
칸 설명이 밝힌다 - 한 칸 더 올리면 값어치가 내려간다는 것을 적어, 높은 칸을 비워 둔 것이 실수로
보이지 않게 한다.

**환산율을 2026-09-11 에 다시 쟀고 결과는 [백로그](ROADMAP.md)의 가치 데이터 절에 있다.** 능력치가
묶여 나오는 것을 이중으로 세고 있어 척도 전체가 한 번 부풀어 있다(잰 값의 레벨당 중앙값이 1.00
이어야 할 자리에서 1.50). 다시 재면 네 종이 한 종으로 줄지만 `CharmWorth.Tiers` 를 같이 다시
뽑아야 하고, 도마뱀 판금 갑옷은 어떤 환산율로도 단조가 되지 않는다. **아직 적용하지 않았다.**

## 다음 작업과 완료 기준

1. 배포될 DLL과 형식 21 카탈로그를 게임에서 대조한다. 활성 보호·감점 칸 정리·콤보·연결·수량 효과,
   성장 진행도와 F10 재현을 확인하고 사용한 빌드·카탈로그·싱글/호스트/참가자를 기록한다.
   회전은 두 가지를 같이 본다 - 가방을 닫은 채 `F8` 로 돌렸을 때 석판 툴팁이 뜨지 않는 것과,
   그 석판에 커서를 올려 둔 채 `F8` 로 돌렸을 때 옛 각도의 테두리가 남지 않는 것이다.
   이 확인이 드래프트를 Publish 로 넘기는 조건이다.
2. 실제 교환·효과 콜백 전후를 수집한다. 출처별 능력치의 제거·재적용과 호출 순서를 진단
   모델로 재현하고 같은 입력·결과가 확인된 범위만 자동 배치에 연결한다.
3. 큰 가방·후보·연결 묶음이 있는 고정 사례에서 시간과 할당량을 측정한다. 그 결과로 탐색
   비용과 후보 제거 갈래의 편향을 개선할 순서를 정한다.

현재 `main`에서 `scripts/check.ps1`이 잠금 파일 기준 복원, 포맷 검사, 테스트 629개,
DataTool·Plugin Release 빌드까지 통과한다. 실패·건너뛴 테스트와 빌드 오류는 없다. 남은 경고
4개는 전부 `NU1900`으로, 취약성 조회 서버에 접근하지 못한 것이며 취약성 목록의 최신 여부는
확인하지 못했다. 전체 검사 로그는 로컬 `artifacts/check-final-035.log`에 보관한다.

게임 폴더에는 0.3.5 zip 의 DLL(`09c06ac`)이 깔려 있고 두 파일의 SHA-256 이 zip 의 manifest 와
맞다. 그 전 바이트(`8a801f1`)로 확인한 것은 F10 메모의 `ESC` 취소와, 가방을 닫은 채 `F8` 로
석판을 돌리면 석판 설명이 화면 오른쪽에 남는다는 것이다. 뒤쪽은 우리 회전 알림이 원인이어서
고쳤고, 이 바이트로 **가방을 닫은 채 `F8` 을 눌러도 석판 설명이 뜨지 않는 것을 확인했다**.
같은 수정의 나머지 절반 - 그 석판에 커서를 올려 둔 채 돌렸을 때 옛 각도의 테두리가 남지
않는지 - 는 아직 보지 않았다. 성장 아티팩트 관련 변경은 어느 빌드로도 게임에서 확인하지
않았다. **0.3.6의 점수 수정도 게임에서 확인하지 않았다** - 배치가 실제로 달라지는 변경이므로
다음 실기에서 ★ 를 건 아티팩트가 높은 레벨 칸으로 가는지 먼저 본다. 위 검사는 자동
배치·멀티플레이·게임 내 대기 시간 검증을 대신하지 않는다.

## 게임 1.0.31 대조

2026-09-11에 게임이 1.0.31로 올라갔다. 어셈블리 SHA-256은 `51ad0bb6…`, MVID는
`47a5a5e553bb438a9a51e234b117c9f3`으로 1.0.30(`18f82577…`)과 다르다. 카탈로그는 버전·어셈블리가
어긋나면 스스로 다시 짓는 경로를 그대로 탔고, 질의 검증은 35,616건 중 불일치 0건이었다.

우리 쪽에서 고쳐야 했던 것은 없다. 확인한 범위는 다음과 같다.

- 플러그인이 1.0.31 어셈블리로 경고 없이 빌드된다.
- 쓰기 경로 셋이 그대로다. `GridInventory.Swap` → `LocalSwap`/`CmdSwap`,
  `DoClickAction` → `LocalDoClickAction`/`CmdDoClickAction`, `StoneTablet.Networkrotation`.
  우리가 부르는 것은 이 셋뿐이며 게임 내장 자동 정리는 부르지 않는다.
- 아티팩트 번호가 밀리지 않았다. 양쪽에 있는 298종의 식별자가 모두 같다.
  `FrostMP`(플리트비체의 물방울)만 1261에서 1248로 옮겨졌는데, 1.0.30에 두 번호로 중복
  등록돼 있던 것을 하나로 정리한 것이라 사라진 아이템은 아니다. 이 때문에
  [가치 평가 점검](notes/VALUE-AUDIT-2026-09-06.md)이 적은 1261은 지금 1248이다.
- 아티팩트가 299종에서 311종이 됐다. 새로 들어온 13종 중 10종은 능력치가 측정돼 기존 경로로
  값어치가 잡히고, 셋(결투가의 견장 둘, 대장장이 집게)은 레어도 어림값이다.
- 새 능력치 종류 `FLAME_SWORD_ADDITIONAL_ATTACK_FROM_WEAPON`, `FLAME_SWORD_PICK_BONUS`,
  `HPDAMAGERESTORE`도 환산율이 잡혔다. 무기 이름은 늘지 않았고 조건 토큰도 그대로다.

남은 것은 성장 아티팩트다. 위 구현 범위 표와 [백로그](ROADMAP.md)의 "성장(변화) 아티팩트"를 본다.
게임 화면에서 새 아티팩트를 실제로 놓아 본 확인은 아직 없다.

## 공통 수정 이식

버리기 금지, 자체 활성 효과 없음 판정, 합성 음수 표시, F10 수치 지문 수정을 이식했다.
대립의 천칭은 보유 인스턴스마다 현재 좌우를 유지한다. 같은 쪽 안의 이동은 허용하며 사용자가
직접 반대쪽으로 옮기면 다음 계획부터 새 방향을 따른다. 아직 줍지 않은 천칭의 방향은 고정하지 않는다.
좌우 능력치의 실전 기여를 비교하는 기능은 아니다.
카탈로그 형식은 21, 재현 형식은 9다. 이미 사용된 0.3.x 형식 번호를 재사용하지 않는다.
형식 1·카탈로그 15의 구형 자료는 숫자 지문을 검증한 뒤 변경 전후 비교로 읽는다.
구형 카탈로그에는 새 판정 속성이 없으므로 당시 관측 범위 안에서 재생한다.

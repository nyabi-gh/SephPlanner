# 0.2.6 회귀 검토

2026-09-09에 직전 공개 버전 `v0.2.5`부터 릴리스 문서 커밋 `70d09c3`까지의 변경 58개 파일을
검토했다. 효과 계산, 카탈로그 생성, 스냅샷·설정 지문, 계획 재현, 진단 명령과 관련 테스트를
확인하고 아래 수정과 재검증을 추가했다.

## 발견한 문제와 수정

침·마법 지원의 연결 묶음을 옮기는 탐색에서, 현재 배치가 바뀌지 않았는데도 목적지마다
같은 이웃 맵과 연결 묶음을 다시 만들고 있었다. 이 정보를 현재 배치 동안 재사용하고,
더 나은 배치를 채택하면 즉시 갱신하도록 수정했다. 탐색 후보·탐색 예산·점수 계산은 유지했다.

36칸에 아티팩트 32개와 석판 4개를 넣은 합성 입력을 종류별 3개씩 실행했다. 다음은
`GC.GetTotalAllocatedBytes`로 잰 풀이 한 번당 평균 누적 할당량이며, 최대 상주 메모리나
인게임 프레임 비용이 아니다. 일반·모래시계·침·혼합은 아래 검토 도구의 고정 시드 입력이다.

| 입력 | 수정 전 MiB | 수정 후 MiB |
|---|---:|---:|
| 일반 | 203.4 | 203.3 |
| 모래시계 | 216.3 | 214.2 |
| 침 사슬 | 264.8 | 252.1 |
| 침·모래시계·별조각·벨트·종이 혼합 | 643.6 | 534.6 |

혼합 입력에서도 계산 비용은 여전히 크다. 이 표는 이번 중복 제거의 효과만 보여주며,
0.2.5와 같은 비용으로 새 효과를 계산한다는 뜻은 아니다. 실행 시간은 표본과 실행 환경의
영향이 커서 이번 비교로 속도 개선을 단정하지 않았다.

## 재검증

- `scripts/check.ps1`: 테스트 476개, 포맷 검사, DataTool·Plugin Release 빌드 통과.
  실패·건너뛴 테스트와 제품 빌드 경고·오류는 없다.
- 작은 합성 입력 48개는 각각 두 번 풀어 결과 일치, 아이템 보존, 좌표 중복·격자 이탈 없음,
  최종 점수 재평가 일치를 확인했다. 일반·모래시계·침·혼합 각각 고정 시드 12개다.
- 위 48개와 큰 입력 12개 모두 중복 제거 전후의 좌표·점수·선택 기준·사용 유지 실패 수가
  같았다. 큰 입력은 제품 기본 탐색 설정으로 실행했다.
- 0.2.5와의 큰 입력 비교에서 새 효과가 없는 일반·모래시계 6개 사례의 좌표와 점수가 같았다.
  새 효과가 추가된 침·혼합 입력은 이전 버전과 같은 점수를 요구하지 않았다.
- 모래시계·별조각·마법과 침 두 개가 연결된 상태로 함께 이동하고, 적용한 좌표에서 다시
  풀어도 이동하지 않는 검사를 기존 단위 테스트에 추가했다.
- F10 재현의 설정·카탈로그·직전 목표 보존, 계산 중·실패한 요청, 손상 파일, 다른 빌드,
  추천 OFF에서의 콤보 변경과 오래된 자동 배치 차단을 기존 회귀 테스트로 확인했다.

추가 비교 도구와 원시 결과는 로컬 `artifacts/regression-review/`에 있다. 실행할 어셈블리의
SHA-256을 대조해 이전·현재 빌드를 구분했다. 별도 0.2.5 복원에서는 네트워크 제한으로
취약성 정보 조회 경고가 있었으며, 이를 의존성 보안 검증 결과로 사용하지 않았다.

## 게임 코드 대조와 한계

게임 DLL의 SHA-256은
`c3939a7d431f1362daca655938480569e11f501f7d0820a989873765555a7c39`다.
해당 로컬 디컴파일에서 별조각의 방향과 마나 반올림, 벨트의 빠른 슬롯 범위, 비늘의 석판 수,
열쇠의 행 카테고리, 종이의 일치 수, 특수 콤보 데이터 요청, 진단에 사용하는 전환·타이머 필드를
대조했다. 이 범위에서 추가로 확인된 게임 규칙 불일치는 없었다.

최신 형식 14 카탈로그의 인게임 재수집, Unity에서 F10 저장·재생, 실제 자동 배치와
멀티플레이 실기는 이번 검토에서 수행하지 않았다. 종이 중첩과 능력치 전환의 이벤트 순서,
전투 가치 추정, 기존 진단 명령의 제한은 [현재 상태](STATUS.md)와 [계획 재현](REPRODUCTION.md)을
따른다. 위 결과는 확인한 범위의 회귀 검사이며 실제 플레이 전체의 무결성을 보증하지 않는다.

## 1. 종합 판단

**구조를 바꿀 이유는 없다.** 게임 규칙 재현은 1.1.2 에서도 맞고, 시험과 문서는 이 규모의 개인 프로젝트로는 드물게
촘촘하다. 약한 곳은 넷이다.

1. **조언이 배치와 다른 입력으로 풀린다.** 후보·제거 조언이 배치가 지키는 규칙 몇 개를 빠뜨린다 - 버릴 수 없는 석판
   (4-1), 강화 양보 기준·콤보만·조건 무시 칸·강화 대상 지정(4-2), 후보 자신의 콤보 몫(4-5). 배치 쪽은 촘촘한 시험이
   지키는데 조언 쪽에는 "같은 판을 배치로 풀면 같은 답인가" 를 보는 대조가 없다.
2. **게임이 연 규칙 하나가 자동 배치의 전제를 깼다.** 합치기형 배치 보너스다(3-1). ROADMAP 4절 표가 미리 적어 둔 다시
   여는 조건이 1.1.2 에서 충족됐다.
3. **실패했을 때 화면이 말을 하지 않는다.** 조언 실패, 첫 실행의 데이터 실패, 반복 재시도가 사용자에게는 "계산 중"
   이나 깜빡임으로만 보인다(5-1~5-3).
4. **큰 판의 조언이 실제 Mono 에서 수십 초다.** 게임에 든 Mono 를 직접 띄워 재 보니 꽉 찬 42칸 합성 판의 후보 8개
   조언이 약 19초이고, 고사양 모드는 조언에 듣지 않는다(6-1~6-3).

## 2. 강점

지켜야 할 것을 먼저 적는다.

- **게임 규칙 재현.** 위 표대로 질의·회전·셈 순서·합성·배치 조건 10종·활성 판정(`Charm_Basic.RefreshCharm`)이 1.1.2 와
  같다. 고정 각인·신비 각인(2→1칸, 4→2칸, 석판 12002, `O MUL/2`)·친타마니 순서도 프리팹 값까지 맞다.
- **문자열로 잡는 게임 멤버가 전부 있다**(부록 A). 없는 것은 1.0.33 전용 셋뿐이고 그 갈래에 닿지 않는다.
- **쓰기 경로가 전제와 같다.** `Swap`(게임 `GridInventory.cs:2401`)·`LocalSwap`(:2426), 서버 핸들러(:6263, :6348),
  `DoClickAction`(:3456) → `StoneTablet.Rotate`(:2411), hook 없는 `Networkrotation`, `Get/ReleasePermission`(:2609/:2774).
- **실행기·적용기의 동시성.** `PlanRunner` 의 공유 상태가 전부 `_gate` 아래이고 취소와 세대의 이중 검사로 낡은 게시 경로가
  없다. 조언은 새 `Plan` 으로 게시한다. 세션 누적 컬렉션은 전부 상한이 있거나 재설정된다.
- **지문.** `PlanBuilder.Attempt`·`Advise` 가 읽는 입력과 대조해 빠진 것이 없다. tr-TR·ar-SA·fa-IR·de-DE 에서 지문이 같다.
- **캐시 규약.** 빔 열쇠·채점 열쇠·`AdviceMemo` 열쇠를 읽는 입력과 전수 대조해 구멍이 없다(4-6 외).
- **비교자와 배정.** `PlacementQuality` 비교는 실질적으로 추이적이고 정렬 예외 경로가 없다. 헝가리안의 직사각 처리와 우선
  단계 기수가 맞다(92칸 최대 약 1.4e10, double 안전). Dictionary 열거 순서·LINQ 지연이 결과에 닿는 곳이 없다.
- **시험.** 1,029건 전부 단정이 있고 Skip 이 없다. Localization 은 비병렬 컬렉션으로 분리했고 할당 시험은 스레드별로 잰다.
  숫자 기대값만 바꾼 커밋은 196개 중 4개이고 모두 동작 변경과 함께다.
- **문서.** 링크·앵커 깨짐 0, 코드 식별자 376개 중 풀리지 않은 9개는 일반 용어나 게임 쪽 이름이다. README 다섯 벌의 UI 이름이
  번역 표와 일치하고 기본 키 표도 코드와 같다.
- **화면 원칙.** 입력을 뺏지 않는 HUD 와 컨트롤 스택에 올린 창의 분리가 일관된다. 다섯 언어 × 네 글꼴 20조합에서 누락
  글자가 0 이다(폴백 연쇄 포함, ★▽①② 는 Galmuri 로 간다).
- **히스토리.** 토큰, `uploadticket.json`, 디컴파일 소스, 리플레이, `.DS_Store` 가 들어간 적이 없고 트레일러가 0 이다.

**높음 · 대조 · 재검증.** 정할 것이 있다.

- 게임: `GridInventory.cs:2872` 가 `GetCustomStatUnsafe("ARRANGEMENTBONUS") > 0` 일 때만 탐색한다. 합치기형이면 `:3240`·

  | 레시피 | 묶음 | 효과 |

  | `0002_Trio` | 1101 + 1141 + 1175 | 셋 다 `FAST` |

  | `0005_Wing` | 날개 1143 + 천 갑옷 1215 | **합치기형 → 사과주스 27** |

  둘이고 둘 다 합치기형이 아니다" 도 낡았다.

## 7. 화면·조작

게임을 띄우지 않았으므로 수치는 1.1.2 에셋에서 뽑았다. `[UI] HUD` 의 CanvasScaler 는 640×360·Expand 다(21:9 는 860×360,

360단위는 51.4B 다. 글자 폭은 게임 TMP 글꼴 표의 advance 다(Galmuri 한글 1em, 공백 0.4em).

### 7-1. F8 에 확인도 되돌리기도 없고, 접힌 화면에는 첫 이동만 보인다

**높음 · 코드.** `Plugin.cs:1226-1267`, `NativeHud.cs:491-493`. F8 은 F7(펼치기) 바로 옆이다. 펼치려다 잘못 누르면 가방 전체가
재배치되고 원래 자리로 돌아갈 길이 없다. 되돌리기는 적용 실패 때만 돈다.

- 적용 직전 자리·각도를 저장하고 "직전 자동 배치 되돌리기" 를 바로 실행 탭과 키에 둔다(규모는 재지 않았다).
- 접힌 상태에서는 처음 몇 번만 두 번 누르게 한다: `Tr("{0} 한 번 더: 이동 {1}건 · 회전 {2}건 적용")`.
- 접힌 줄 앞에 총량을 붙인다: `이동 5건 · 다음: …`.

### 8-1. CI 의 간헐 실패는 원인이 셋이다

**중간 · 재현(메커니즘). CI 로그와의 일치는 확인 못 함.** STATUS "원인을 모르는 채" 의 단서(같은 클래스의 `Wait(5초)` 가 풀

1. **`ABoardThatIsNotTheAppliedPlanIsSolvedAsUsual`: 스레드 풀 주입 지연.** `PlanRunner.cs:534` 의
   `ThreadPool.QueueUserWorkItem`, `PlanRunnerTests.cs:442,447` 의 `SpinUntil(5초)`. 논리 코어 4개에서 작업자를 CPU 로 막으면
   큐 항목이 3,803ms 뒤에 시작한다(Sleep 으로 막으면 298ms). CPU 를 많이 쓰는 시험 클래스(`PolishIncrementTests` 합 14.1초,
   `SolverCostTests` 합 15.7초)와 겹치면 그 순간 돌던 실행기 시험이 걸린다. 셋을 함께 돌리면 3회 모두 같은 증상으로 실패했다.
   `PlanRunner` 에 실행 위임을 주입해 시험은 전용 스레드로 돌리거나, 시험 어셈블리에서 `ThreadPool.SetMinThreads` 를 올리고,
   두 클래스를 비병렬 컬렉션으로 뺀다.
2. **`WrongHashAndOversizedBodyAreRejected`: `Expect100ContinueTimeout` 기본 1초.** `DiagnosticServerTests.cs:211-213`
   `ExpectContinue = true`. 서버 응답이 1초를 넘기면 8MB 본문이 나가 소켓 오류가 된다(413 앞에 1.5초 지연을 넣자 3회 모두
   `HttpRequestException ← SocketException`). 시험 클라이언트에 `SocketsHttpHandler { Expect100ContinueTimeout = 1분 }` 을 준다.
   주석의 macOS 한정 서술도 고친다.
3. **새로 찾은 것: `PlanRunnerTests.cs:425-429`.** 호출 수(`settledCalls.Count == 2`)를 기다린 뒤 `IsCurrent` 를 단정하는데
   콜백과 게시 사이에 틈이 있다. CPU 포화에서 10회 중 1회 429줄에서 실패했다. 조건을 `settledCalls.Count == 2 &&
   runner.State.IsCurrent` 로 바꾼다.

## 부록 B. 게임 Mono 로 솔버 재기(macOS)

게임 앱에는 Mono 실행 파일이 없고 `Contents/Frameworks/libmonobdwgc-2.0.dylib`(universal)만 있다. 그것을 dlopen 하는 C 호스트로
Core 를 돌린다. 측정 코드는 netstandard2.1 라이브러리(`Bench.Entry.Run(string)`)로 짓고 Core 를 참조한다.

1. `Contents/Resources/Data/Managed` 를 통째로 작업 폴더의 `rt/Managed` 로 **복사**한다(심볼릭 링크면 아래의 `../lib` 가 게임 쪽을
   가리킨다). 측정 DLL 과 `SephPlanner.Core.dll` 을 그 안에 넣는다.
2. `Contents/Frameworks/libmono-native.dylib` 를 `rt/lib/` 에 복사한다. 없으면 `System.Console` 의 형식 초기화에서
   `DllNotFoundException` 이 난다.
3. 아래를 `clang -O1 -arch arm64 -o host host.c` 로 짓고
   `host <libmonobdwgc 경로> <rt/Managed> <Contents/MonoBleedingEdge/etc> <rt/Managed/측정.dll> <표시 문자열>` 로 돌린다.

```c
#include <dlfcn.h>
#include <stdio.h>
typedef void* P;
#define LOAD(name) name = dlsym(h, #name); if (!name) { fprintf(stderr, "missing %s\n", #name); return 2; }
int main(int argc, char** argv) {
  if (argc < 6) return 1;
  void* h = dlopen(argv[1], RTLD_NOW | RTLD_GLOBAL);
  if (!h) { fprintf(stderr, "dlopen: %s\n", dlerror()); return 2; }
  void (*mono_set_dirs)(const char*, const char*); void (*mono_set_assemblies_path)(const char*);
  void (*mono_config_parse)(const char*); P (*mono_jit_init_version)(const char*, const char*);
  P (*mono_domain_assembly_open)(P, const char*); P (*mono_assembly_get_image)(P);
  P (*mono_class_from_name)(P, const char*, const char*); P (*mono_class_get_method_from_name)(P, const char*, int);
  P (*mono_string_new)(P, const char*); P (*mono_runtime_invoke)(P, P, void**, P*);
  P (*mono_object_to_string)(P, P*); char* (*mono_string_to_utf8)(P);
  LOAD(mono_set_dirs) LOAD(mono_set_assemblies_path) LOAD(mono_config_parse) LOAD(mono_jit_init_version)
  LOAD(mono_domain_assembly_open) LOAD(mono_assembly_get_image) LOAD(mono_class_from_name)
  LOAD(mono_class_get_method_from_name) LOAD(mono_string_new) LOAD(mono_runtime_invoke)
  LOAD(mono_object_to_string) LOAD(mono_string_to_utf8)
  mono_set_dirs(argv[2], argv[3]);
  mono_set_assemblies_path(argv[2]);
  mono_config_parse(NULL);
  P domain = mono_jit_init_version("bench", "v4.0.30319");
  P assembly = mono_domain_assembly_open(domain, argv[4]);
  if (!assembly) return 4;
  P klass = mono_class_from_name(mono_assembly_get_image(assembly), "Bench", "Entry");
  if (!klass) return 5;
  P method = mono_class_get_method_from_name(klass, "Run", 1);
  void* args[1] = { mono_string_new(domain, argv[5]) };
  P exc = NULL;
  mono_runtime_invoke(method, NULL, args, &exc);
  if (exc) { P e = NULL; P s = mono_object_to_string(exc, &e); fprintf(stderr, "%s\n", s ? mono_string_to_utf8(s) : "?"); return 6; }
  fflush(stdout);
  return 0;
}
```

## 부록 C. 배포 DLL 참조 검사

릴리스 zip 의 DLL 이 새 게임 `Managed` 에서 풀리는지 본다(net10.0 콘솔, `Mono.Cecil` 0.11.6). BepInEx 쪽 범위는 건너뛴다.
`HarmonyLib.Harmony::Patch`(인자 여섯)와 다차원 배열의 `Get`·`Set`·`Address`·`.ctor` 는 알려진 거짓 양성이다.

```csharp
using Mono.Cecil;

var managed = args[0];
var resolver = new DefaultAssemblyResolver();
resolver.AddSearchDirectory(managed);
foreach (var d in args.Skip(1)) resolver.AddSearchDirectory(Path.GetDirectoryName(Path.GetFullPath(d))!);
var parameters = new ReaderParameters { AssemblyResolver = resolver };
foreach (var path in args.Skip(1))
{
    using var assembly = AssemblyDefinition.ReadAssembly(path, parameters);
    var module = assembly.MainModule;
    foreach (var type in module.GetTypeReferences())
    {
        var scope = (type.Scope as AssemblyNameReference)?.Name ?? type.Scope.Name;
        if (scope.StartsWith("BepInEx")) continue;
        try { if (type.Resolve() is null) Console.WriteLine($"[TYPE] {scope}: {type.FullName}"); }
        catch (Exception ex) { Console.WriteLine($"[TYPE] {scope}: {type.FullName} -> {ex.GetType().Name}"); }
    }
    foreach (var member in module.GetMemberReferences())
    {
        var element = member.DeclaringType.GetElementType();
        var scope = (element.Scope as AssemblyNameReference)?.Name ?? element.Scope.Name;
        if (scope.StartsWith("BepInEx")) continue;
        try
        {
            object? resolved = member switch { MethodReference m => m.Resolve(), FieldReference f => f.Resolve(), _ => member };
            if (resolved is null) Console.WriteLine($"[MEMBER] {scope}: {member.FullName}");
        }
        catch (Exception ex) { Console.WriteLine($"[MEMBER] {scope}: {member.FullName} -> {ex.GetType().Name}"); }
    }
}
```

# 참가자 세션의 고정 각인 실명

2026-09-22. 자동 제보 `c44e9d2eace54bc18c5de4cbe6efa348`을 조사했다.
수집 버전은 0.4.11, 게임 1.0.33이다. 게임 규칙과 가치 표는 바꾸지 않았다.

## 증상

`시뮬레이션 불일치`가 자동 제보로 반복해서 올라왔다. 한 세션 20분 동안 8번 경고하고 5건을
보냈다. 어긋난 칸은 매번 달랐다.

```
12:44:59 칸 (1,1) 레벨 0 != 게임 1    12:59:38 칸 (2,0) 레벨 0 != 게임 2
12:48:46 칸 (4,0) 레벨 0 != 게임 1    13:00:45 칸 (1,0) 레벨 0 != 게임 3
13:04:22 칸 (0,0) 레벨 0 != 게임 1
```

## 확정된 사실

- 첨부의 가방에는 석판 0개, 각인 0개, 고정 효과 0개이고 모든 아이템의 인챈트가 0인데,
  게임의 `levelMatrix`는 아티팩트가 놓인 7칸에 레벨 1~3을 들고 있다. 게임의
  `charm.CurrentLevelToIdx()`도 같은 값이다. 같은 세션 12:23에는 석판 13개로 검증을 통과했다.
- 인챈트 오독이 아니다. `UI_CharmTooltip`·`UI_ShopPanel`·`UI_SephiriteRewardPanel`이
  클라이언트에서 같은 `globalItemStatTable`을 읽는다.
- `GridInventory.fixedEngravingsOnServer`는 `InitSyncObject` 목록에 없고 SyncVar도 Rpc도 없다.
  `FixedEngraving`은 NetworkBehaviour 도 아니고, 만들 때 칸별 효과 딕셔너리로 구워진다.
- `tabletEngravingCount > 0`이면 `UI_CharacterStatusPanel.OnItemLongClicked`가 석판 각인을
  보낸다. `CmdCreateFixedEngravingFromInventory`는 효과를 구운 뒤 `ForceRemoveItem`으로 석판을
  가방에서 지우고, `CmdCreateFixedEngravingFromExternalItem`은 세피라이트 보상의 석판을 가방에
  넣지 않고 바로 각인한다.
- 따라서 참가자는 이 효과를 볼 길이 없다. 석판을 한 장씩 각인할 때마다 설명되지 않는 칸이
  하나씩 늘어나고, 어긋남 문장이 매번 달라 자동 제보의 세션당 중복 제거를 빠져나갔다.

2026-09-05의 신비 복원은 `mysticPositions`가 동기화되는 신비 콤보만 다뤘다. 석판 각인에는
그런 단서가 없다.

## 수정

원인을 읽는 대신 결과에서 되뺀다. `FixedEffectResidual`이 게임의 네 행렬에서 보이는 석판·각인과
인챈트로 설명되는 몫을 빼고 남는 것을 고정 효과 층으로 쓴다. 배수는 마지막에 곱해지므로 먼저
나누고, 나누어떨어지지 않으면 트랜잭션 도중이라 그 관측을 버린다. 우리가 만든 비활성·제한
해제·배수가 게임보다 많으면 고정 효과로 덮지 않고 어긋남으로 알린다.

되뺀 값은 정의상 행렬과 맞으므로 `FixedEffectTracker`가 성질로 가른다. 고정 각인은 만들 때
구워지는 칸별 표라 아이템을 옮겨도 변하지 않는다. 석판이 그대로인 채 배치만 달라졌는데 값이
달라지면 시뮬레이터의 오차이며, 보상 석판 각인과 구별되지 않는 한 번은 넘기고 연속 두 번부터
알린다.

호스트는 원본 목록을 그대로 쓰고 같은 순간의 되뺀 값과 대조해 되빼기 자체를 검증한다.
읽지 못한 석판·각인 참조가 있으면 어긋남이 아니라 `Unavailable`로 둔다.

곁들여 고친 것이 둘이다. 자동 진단의 중복 제거가 문장을 그대로 열쇠로 써서 좌표만 다른 같은
오류가 세션당 열 번까지 올라갔다. 숫자를 지운 모양으로 묶는다. 진단 덤프는 끊긴 석판·각인
참조를 조용히 건너뛰어 "0개"와 "전부 null"이 똑같이 보였다. 총 개수와 끊긴 수, 각인권,
서버·클라이언트 구분, 고정 효과 층을 적는다.

## 검증

- 되빼기·채택 판정의 회귀 테스트 15개를 추가했다. 되뺀 층으로 다시 돌리면 게임 행렬을
  그대로 재현하는 것, 인챈트를 고정 효과로 오인하지 않는 것, 배수를 먼저 나누는 것,
  트랜잭션 도중과 과다 생성을 구분하는 것, 배치를 따라 변하면 알리는 것을 검사한다.
- 첨부 자료의 실제 숫자로 확인했다. 되빼기 전 어긋난 칸 7개, 되뺀 층을 넣으면 0개다.
  층은 `(0,0)=1 (1,0)=3 (2,0)=2 (3,0)=3 (0,1)=1 (2,1)=3 (0,2)=1`이다.
- 보관 중인 제보 18개의 `--reproduce --allow-model-change` 결과가 변경 전후 모두 같았다.
  일부 자료의 기존 차이는 이번 변경 이전부터 있던 것이며 줄지도 늘지도 않았다.
- `scripts/check.ps1`: 테스트 807개 통과, 실패·건너뜀 0. 포맷 검사와 진단 도구·플러그인
  빌드도 통과했다.

실제 게임에서 석판을 각인한 참가자 세션은 아직 확인하지 않았다. 되뺀 층이 고정 각인과 같다는
호스트 대조도 실기 자료로는 아직 받지 못했다.

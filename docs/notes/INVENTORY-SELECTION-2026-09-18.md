# 자동 배치 중 선택 상세 조회

2026-09-18. 게임 1.0.33의 `Assembly-CSharp.dll`과 `Mirror.dll`을 디컴파일해 확인했다.
대상 제보는 0.4.10의 `d464e92da83f48e38e7a4111334d5d48`이다.

## 원인과 확인 범위

저장된 적용 목표에서 교환 순서를 재구성하면 17번째 이동은 빛나는 모래시계를
`(3,3) → (1,5)`로 옮긴다. 그 직후 아이템 위치는 오류 스냅샷과 모두 일치하지만,
게임의 `charms` 사전과 효과 객체 좌표는 모래시계가 아직 `(3,3)`에 있다고 가리킨다.
`ReleasePermission`의 오류 오프셋 `0x005f`는 `charm.Item.InstanceID`를 읽는 지점이다.

`LocalSwap`은 아이템 사전을 먼저 바꾸고 효과 사전과 좌표는 뒤에 바꾼다. Mirror는 사전 변경
알림을 동기 호출한다. `UI_CharacterStatusPanel.OnItemUpdated`는 바뀐 칸이 선택돼 있으면
`OnItemSelected`를 호출하며, 활성 모래시계의 연결 표시가 이전 좌표의 `Item`을 읽어 실패한다.
이 예외로 나머지 교환이 생략되고 `Dispose`의 효과 재계산 예외가 최초 예외를 덮는다.

디컴파일한 `LocalSwap` 본문과 동기 알림·선택 조회 대역을 사용한 로컬 실험에서 이 경로를
재현했다. 목적지가 선택된 활성 모래시계만 실패했으며, 선택 없음·출발지 선택·비활성 상태·
교환 후 상세 조회는 성공했다. 제품의 선택 보호 코드를 같은 실험에 연결해 실패가 사라짐도
확인했다. Unity에서 실행한 실기 검증은 아니며, 제보에는 당시 선택 칸이 없어 실제 최초
UI 호출이 이 경로였는지까지 확정하지는 않는다.

## 수정

- 호스트와 싱글의 동기 교환 동안 같은 가방의 선택을 해제하고, 교환 완료 뒤 같은 칸을
  다시 선택한다. 게임의 `OnSelect`가 최신 툴팁과 연결 표시를 재계산한다. 새 선택이 생기거나
  가방·선택 객체가 사라지거나 효과 연결이 깨지면 이전 선택을 덮어쓰지 않는다.
- 참가자 명령은 서버에서 나중에 실행되므로 로컬 선택을 동기 교환처럼 취급하지 않는다.
- 서버의 효과 사전 키·객체 좌표·소유 가방·아이템 참조를 양방향으로 대조한다. 끊긴 연결이
  있으면 레벨 잔량과 무관하게 추가 교환과 되돌리기를 중단하고 해당 가방의 자동 배치를 잠근다.
- 교환이 반영된 뒤 오류가 반환돼도 효과 연결이 정상이고 두 칸의 인스턴스가 예상대로라면
  해당 교환도 되돌리기 기록에 넣는다. 상태가 어긋났다면 억지로 복구하지 않는다.
- 표시 복원 오류는 따로 기록해 최초 교환 예외를 가리지 않는다.

예외를 무시하거나 모래시계 번호를 특별 취급하거나 게임의 효과 좌표를 직접 덮어쓰지 않는다.

## 검증과 남은 범위

`scripts/check.ps1`에서 포맷 검사, 전체 테스트 804개(실패·건너뜀 0), 진단 도구와
플러그인 Release 빌드가 통과했다. NuGet 취약성 정보 서버에 접속하지 못한 `NU1900`
경고가 남았으므로 취약성 정보 조회까지 성공한 것은 아니다.

회귀 테스트는 교환 중간 상태 조회 차단, 새 선택 보존, 손상 상태에서 상세 재표시 금지,
원래 교환 예외 보존, 인챈트 레벨이 남은 연결 손상, 쓰기 전 손상, 반영 후 오류의 되돌리기를
검사한다. 실제 게임에서 마우스·패드로 목적지를 선택한 채 자동 배치하고 툴팁·연결 표시가
완성된 가방과 일치하는지는 별도 확인이 필요하다.

동일 Core 빌드로 제보 리플레이를 두 번 실행해 저장 결과와 97개 항목이 다른 현상은
별도 미해결이다. 이번 수정은 게임 적용 계층과 오류 복구에 한정하며 그 차이를 해결했다고
간주하지 않는다. 원본 진단과 게임에서 추출한 코드는 로컬 `reports/`에만 보관한다.

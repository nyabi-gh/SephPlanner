# 망원경과 행성의 동시 재배정

2026-09-16. 제보 `24911147e07f49c197fa317bcac586b9`, 플러그인 0.4.4, 게임 1.0.33,
카탈로그 23. 별도 빌드 설정 없이 망원경 주변에 행성 다섯 개가 모이고 푸른 행성만 떨어져 있었다.
수정 전 0.4.5에서도 당시 계획과 차이 없이 재현됐다. 수정은 아직 공개 버전에 포함되지 않았다.

## 원인과 수정

푸른 행성은 망원경 밖에서 4레벨을 받고 있었다. 혼자 망원경 옆 빈칸으로 옮기면 0레벨이 되어
점수가 내려간다. 그러나 비워진 4레벨 칸을 팔라스의 카드가 쓰면 전체 점수가 올라간다.
카드와 행성을 먼저 교환하는 중간 배치는 동점이라 자리 유지 선호 때문에 선택되지 않았다.
현재 배치에서 한 번 이동·교환해서 더 좋아지는 후보는 없었다.

배정기는 망원경이 주는 거대화 이득만 보고 행성이 받는 이득은 보지 않았다. 그래서 여러
아이템을 함께 배정하는 단계에서 이 조합을 놓쳤고, 한 번씩 개선하는 후처리로도 복구하지 못했다.

`Assign`의 자리 선택 비용에 행성이 받을 이득을 더했다. 망원경 자체의 활성 상태와 가중치를
반영하고, 실제 소환 행성만 대상으로 삼는다. 주는 쪽과 받는 쪽은 같은 대상 판정·크기 계산을
공유한다. 최종 점수는 기존처럼 망원경 몫에서만 더하므로 받는 쪽의 이득을 다시 합산하지 않는다.
고정된 아이템 번호나 제보 좌표, 새로운 탐색 예산은 사용하지 않는다.

게임 근거는 같은 1.0.33 어셈블리의 `Charm_PlanetModule.SearchPlanet`과
`GreenBat.CreateBullet`이다. 주변 8칸, PLANET 카테고리와 소환 타입, 피해량의 50% 강화 규칙은
그대로다. 거대화 크기를 레벨 0 기준으로 추정하는 한계와 망원경 여러 개의 중복 평가는
이번 수정 범위에 포함하지 않았다.

## 결과와 회귀 검증

좌표는 덤프의 왼쪽 위 `(0,0)` 기준이다.

| 아이템 | 수정 전 | 수정 후 |
|---|---|---|
| 푸른 행성 | `(0,1)`, 4레벨, 거대화 없음 | `(4,3)`, 0레벨, 거대화 있음 |
| 팔라스의 카드 | `(0,0)`, 1레벨 | `(0,1)`, 4레벨 |

다른 아이템과 석판은 그대로다. 거대화 대상은 5개에서 6개, 점수는
56.61586276559312에서 56.89086276559311로 오른다. 새 비활성화·사용 유지 위반은 없다.
이것은 플래너의 점수 개선이며 실제 전투 DPS 측정 결과는 아니다.

- 실제 제보의 계획을 적용한 상태로 다시 계산했다. 이동 수는 2 → 0 → 0 → 0,
  매번 검증 통과·레벨 불일치 0건·거대화 대상 6개였다. 제보에 내장된 카탈로그와 설정을 썼다.
- 기존 제보 14개는 수정 전 DLL과 수정 후 코드의 `ReplayResult` 전체가 동일했다.
  붉은 이슬 제보도 포함한다. 로컬 카탈로그 재측정은 하지 않았다.
- 4칸 합성 가방으로 회귀 시험 7개를 추가했다. 배치·조언 양쪽 탐색, 재계산 안정성,
  꺼진 망원경·꺼진 이웃 칸·비대상·이동 불가·망원경 양보를 검사한다.
  핵심 두 시험은 수정 전 DLL에서 실패하고 수정 후에는 통과한다.
- `scripts/check.ps1`: 777개 전부 통과, 실패·건너뜀 0, 도구·플러그인 빌드 경고·오류 0.
  Core를 별도로 다시 빌드해도 경고·오류 0이다.

## 계산 비용

같은 개발 PC의 .NET 10에서 수정 전 DLL과 수정 후 코드를 나란히 측정했다. 제보 입력 그대로
배치와 조언을 함께 계산했고 합성기 상태도 유지했다. 각 판을 세 바퀴씩, 바퀴마다 새 캐시로
한 번과 같은 캐시로 세 번 실행했다. 첫 바퀴를 제외한 cold 두 번·warm 여섯 번의 중앙값이다.

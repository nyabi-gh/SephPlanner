# 0.3.0·0.3.1 수정 선별과 친타마니 확인

2026-09-10. 실제 공개 [0.3.0 릴리즈](https://github.com/nyabi-gh/SephPlanner-Release/releases/tag/v0.3.0)와
[0.3.1 릴리즈](https://github.com/nyabi-gh/SephPlanner-Release/releases/tag/v0.3.1)를 GitHub API로 읽고
`v0.2.8` 및 현재 기준 패치 소스와 비교했다. 처음에는 조사만 진행했고, 이후 사용자 요청으로 아래 미포함 항목을 구현했다.

## 친타마니 돌

발동으로 아이템이 사라진 뒤 원래 칸에 남은 레벨 보너스는 이미 적용된다.
`GameReader.ReadFixedEffects`는 `GridInventory.dungeonTempLevels`를 읽어 좌표별 `FixedEffectCell`로
추가한다. 호스트 전용 분기 밖에 있으므로 참가자의 동기화된 값도 읽는 경로다.
`PlanBuilder`는 이를 고정 칸 효과로 전달한다. 아이템 인챈트처럼 이동시키지 않는다.

현재 설치 게임 DLL의 `Charm_Chintamani`를 다시 디컴파일했다. 치명적인 피해를 받은 뒤 회복·
무적 처리와 함께 자기 좌표에 `AddDungeonTempLevel(..., addLevel)`을 호출하고 `ForceRemoveItem`한다.
클래스 초기값은 3이며, 플러그인은 이 숫자를 하드코딩하지 않고 게임에 실제 기록된 값을 읽는다.
임의로 버리거나 파괴하는 모든 경우에 +3을 예측해서 넣는 기능은 아니다.
발동 전 아이템의 회복·생존 가치를 정밀 평가한다는 뜻도 아니다.

`ChintamaniTests` 4개를 현재 작업 사본에서 재실행해 통과했다. 빈 +3 칸 활용과 배치 안정화,
아이템 이동 후 좌표 유지, 다른 칸 효과·인챈트·배수와의 조합, 보너스 제거 후 계획 무효화를 검사한다.
싱글·멀티 입력 테스트는 실제 멀티플레이 동기화 실기 검증을 대신하지 않는다.
게임 디컴파일 기록은 `artifacts/release-audit/Charm_Chintamani.txt`에 보관했다.

## 권장 순서

1. 버릴 수 없는 아이템 제외·교체 방지와 마음의 짐 활성 보호 수정.
2. F10 수치 지문 안정화 및 실제 Mono 생성 자료 호환 검사.
3. 합성 음수 표시 수정과 위 변경의 전체 검사·게임 실기.
4. 발리송 및 천칭·영원의 식은 구형 평가 기준의 별도 누락 조사로 진행.

새 카탈로그 속성을 읽는 수정은 형식 15의 기존 캐시를 그대로 쓰면 적용되지 않는다.
수집 변경을 이식할 때 카탈로그 형식 갱신과 재현 자료 호환을 함께 처리해야 한다.
지문 검사를 무시하거나 오래된 카탈로그에 값이 있다고 가정하지 않는다.

## 후속 반영

위 표의 미포함 항목 네 가지는 후속 패치에 반영했다. 천칭은 사용자가 선택한 현재 쪽 유지
방식으로 별도 구현했다. 실제 게임 Mono에서 생성한 구형·신형 자료를 회귀 검사에 포함했다.
표는 조사 당시 상태이며 최신 구현·검증은 `BASELINE-0.2.8-PLAN.md`를 따른다.

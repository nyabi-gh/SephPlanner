# 배치 평가와 활성 보호 개편

## 목적

보석 갑옷의 능력치를 환산한 순가치가 음수여서 빈 정상 칸이 있어도 효과를 끄는 배치를 선택하는 현상을 해결한다. 특정 아이템의 점수를 보정하지 않고, 게임 효과·빌드 선호·배치 정책을 구분한다. 경쟁처럼 감점이 있는 석판은 같은 효과를 유지할 수 있을 때 정상 빈칸을 더 많이 확보하는 배치를 선택한다.

현재 분석 기준은 게임 1.0.30과 프로젝트 0.2.6이다. 게임 규칙은 설치된 `Assembly-CSharp.dll`을 디컴파일해 확인한다. 능력치 원본 수치와 그 수치를 전투 가치로 환산한 추정은 같은 의미로 취급하지 않는다.

## 변경 범위

1. 능력치별 원본 레벨 표와 환산 근거를 카탈로그에 보존한다. 기존 순가치 표는 호환성과 설명을 위해 남긴다.
2. 확인된 적용 대상에 한해 주력 아티팩트의 선호를 지원 능력치 평가에 전달한다. 물리 공격 비중·시전 빈도·전투 피해량을 임의로 만들어내지 않는다.
3. 사용 유지와 자동 비활성화 정책을 분리한다. 기존 강화 우선·양보·고정의 의미를 조용히 바꾸지 않는다.
4. 배정·자리 교환·최종 선택에 공통 비교 기준을 사용한다. 실제 효과 점수와 이동 편의를 분리한다.
5. 석판의 이동·회전과 아티팩트 재배정을 함께 검토한다. 음수 능력치와 비단조 레벨 표가 있다는 전제로 탐색 후보를 구성한다.
6. 교체·빼기·합성 추천, 계획 무효화, 설정 저장과 재현 자료에도 같은 정책과 평가 입력을 전달한다.

## 기본 정책

`사용 유지`는 효과 활성과 필요한 지원 연결을 보호하며, 실패하면 자동 적용을 막는 기존 의미를 유지한다. 무기 불일치와 지원 대상 부재를 단순히 레벨이 낮은 상태와 혼동하지 않는다.

사용자 확인에 따라 기본은 활성 보존이다. F2의 `끄기 허용`을 따로 지정한 종류만 강화 이득과 비활성화 손해를 비교할 수 있다. 기존 `양보`는 좋은 강화 칸을 양보한다는 뜻이며 끄기 허용으로 바꾸지 않는다. `사용 유지`와 함께 지정하면 사용 유지가 우선한다.

현재 정상 활성·연결된 아이템은 인스턴스별로 보호한다. 하나를 끄고 다른 둘을 켜는 식으로 활성 개수만 늘리는 배치가 보호를 우회하지 못한다. 이미 꺼진 아이템은 가능한 한 복구하되, 무기 불일치는 배치로 복구할 상태에 포함하지 않는다. 복구할 배치를 찾지 못하면 대상과 이유를 표시하며, 새로 끄는 계획은 이동 안내와 자동 적용 모두 차단한다. 탐색 실패를 배치 불가능의 증명으로 표현하지 않는다.

최종 비교 순서는 다음과 같다. 각 단계가 같은 경우에만 다음 단계를 비교한다.

1. `사용 유지`와 현재 활성 보호 위반 수
2. 기존 제한 해제 칸 `고정` 위반 수
3. 지정 콤보의 완성 수와 진행도
4. 기본 활성·지원 연결 보존 실패 수
5. 실제 배치의 효과 환산 점수
6. 감점·비활성 효과가 있는 빈칸 수
7. 아티팩트 상한을 넘긴 강화 합계
8. 현재 자리·회전 유지, 직전 제안 유지

같은 필수 조건과 효과 가치를 만족하는 후보끼리는 감점·비활성 효과가 없는 빈칸을 더 확보하는 배치를 선호하고, 그다음 이동과 회전을 줄인다. 이전 계획은 동점에서 유지한다. 빈칸 수만 보고 활성 가능 여부를 결정하지 않으며 후보의 점유·석판 효과·배치 조건·지원 연결을 다시 계산한다.

## 평가 데이터와 추정

능력치별로 원본 값, 공통 단위 환산율, 환산 표본을 보존한다. 환산 가능한 능력치라는 이유만으로 실제 빌드의 전투 효과까지 측정됐다고 표시하지 않는다. 확인되지 않은 효과는 명시적으로 남기며 실패를 0으로 숨기지 않는다.

주력 선호를 지원 능력치에 반영하는 배수는 전투 사용률이 아니라 사용자 선호의 전달이다. 여러 주력 지정이 같은 지원 효과를 중복해서 부풀리지 않게 하며, 적용되지 않는 대상·비활성 대상은 실제 평가에서 제외한다. 능력치 손해를 임의로 제거하거나 모든 아티팩트에 양수 활성 보너스를 붙이지 않는다.

이번 지원 범위는 `MAGIC_CRITICAL`과 `MP_REGEN`이다. 치명타는 게임 `ActiveSkill_Bolt` → `Bullet.Pool.Spawn`의 마법 피해 경로와 `DamageInstance.Set`의 마법 치명타 적용을 확인한 대상에만 전달한다. 마나 회복은 현재 유효 레벨의 프리팹 기본 마나 비용이 양수인 마법에 전달한다. 전투 중 추가 비용 변경·실제 사용률은 반영하지 않는다. 다른 마법 구현의 치명타 적용은 추정으로 넓히지 않는다. 지원 아티팩트 자체를 양보했으면 주력 선호로 덮어쓰지 않고, 여러 주력의 배수는 최댓값을 한 번만 반영한다.

카탈로그 형식은 15다. 구형 카탈로그는 기존 갱신 절차에서 다시 생성하며 필요하면 F9로 갱신한다. 저장 설정에 `끄기 허용`이 없으면 허용 목록을 비워 기본 활성 보존을 적용한다. F10 재현 자료에는 허용 목록과 정책 위반·감점 빈칸·초과 강화 결과를 보존한다. 구형 재현 자료는 당시 의미를 임의로 바꾸지 않고 기존 버전 검사로 거부한다.

## 원인 확인

게임 1.0.30의 보석 갑옷(1166)은 마법 치명타·마나 회복 이득과 물리 피해 패널티가 함께 있다. 기존 환산표의 0/1/2레벨 순가치는 -0.4/-0.6/-0.8이고 비활성은 0이다. 따라서 기존 평가에서는 빈 정상 칸이 있어도 끄는 것이 이득이었다. 아이스 볼트(3027)는 상한 1이며, 경쟁(2019)의 질의는 `DIAUPLEFT -1`, `UP -1`, `DOWN +3`이다. 위쪽 경계에서는 두 감점을 밖으로 보내면서 아래 +3을 유지할 수 있다. 반드시 모서리일 필요는 없다.

`Charm_Basic.RefreshCharm`의 음수 레벨 비활성 처리와 `Charm_StatusInstance`의 능력치 제거를 디컴파일로 확인했다. 현재 게임과 로컬 카탈로그의 어셈블리 MVID는 `18f82577233a487384c32357d05323b3`로 일치했다. 제보의 “2강” 의미와 스크린샷 당시 전체 입력은 확인되지 않았으므로 해당 판의 정확한 재현이라고 주장하지 않는다.

## 탐색과 최적성

석판 후보 탐색은 제한된 탐색이다. 전역 최적성을 보장한다고 표시하지 않는다. 이웃·조건에 의존하지 않는 고정 석판 배정과 작은 가방의 전체 열거를 정확한 비교 기준으로 사용한다.

레벨 증가가 항상 가치 증가라는 가정을 하지 않는다. 빔은 각 레벨의 가치를 보존한 탐욕 배정으로 후보를 고른다. 같은 석판 효과를 가진 칸은 묶어 계산하되 인챈트·배수·활성·현재 자리·직전 자리 차이를 보존한다. 활성 복구 후보, 현재·직전 배치, 높은 효과 가치 후보를 함께 검토하고, 최종 후보에서는 석판 이동·회전·맞교환 후 아티팩트를 다시 배정한다. 이 추가 평가 예산은 기본 64회이며 실측 최적값이 아닌 제한값이다. 취소 요청과 탐색 예산을 지킨다.

## 검증과 완료 기준

- 보석 갑옷과 같은 양·음수 능력치를 가진 합성 정의로 정상 빈칸과 음수 칸을 비교한다.
- 경쟁의 모든 자리·회전을 비교해, 같은 효과에서 불필요한 감점을 남기는 후보가 이기지 않는지 확인한다.
- 중앙의 석판이 실제로 더 좋은 강화·지원 효과를 만들면 그 이득을 유지한다.
- 사용 유지, 양보, 끄기 허용 정책, 칸 부족, 무기 불일치, 인챈트와 배치 조건을 검사한다.
- 적용한 상태를 다시 입력해 같은 배치가 유지되는지 확인한다.
- 설정·카탈로그·재현 자료의 저장과 이전 형식 처리, 계획 무효화를 검사한다.
- 작은 가방의 전체 열거와 비교하고, 실제 로컬 카탈로그 사례의 결과와 실행 비용을 변경 전후 측정한다.
- `scripts/check.ps1`의 포맷·테스트·진단 도구·플러그인 빌드를 통과한다.

## 검증 결과

2026-09-09 로컬 검증이다. 새 배치 회귀 테스트는 21개이며 기존 정책·추천·설정·재현·자동 적용 검사와 함께 실행했다. 3×3 가방에서는 경쟁의 36가지 자리·회전과 아티팩트의 모든 배정을 열거한 결과와 일치했다. 고정 효과 6칸의 12개 입력은 비단조 가치, 인챈트, 배수, 비활성, 고정·사용 유지·끄기 허용을 섞어 전체 배정과 비교했다. 중앙의 네 방향 강화를 유지하는 것이 더 유리한 사례에서는 감점 빈칸 하나를 남기는 중앙 배치를 선택한다.

`scripts/check.ps1`을 통과했다. 전체 테스트 499개(실패·건너뜀 0), 포맷, 진단 도구 및 게임 어셈블리를 참조한 플러그인 빌드를 확인했다. NuGet 취약성 조회 서버에 접근하지 못한 `NU1900` 경고는 남아 있으며 취약성 목록의 최신 여부는 확인하지 못했다. 기존 캐시로 패키지 복원과 빌드는 성공했고 의존성 버전은 변경하지 않았다. 전체 검사 로그는 로컬 `artifacts/placement-objective/check-final.log`에 보관한다.

변경 전 기준은 커밋 `998ccd1`의 Core DLL이고 변경 후는 이번 작업의 Core다. Windows의 .NET SDK 10.0.401, Release로 사례별 준비 실행 2회 뒤 5회 중앙값을 비교했다. 시간에는 `Solve`만 포함하며 스냅샷 읽기·카탈로그 환산·조언 전체 계산은 제외한다.

| 입력 | 변경 전 시간 | 변경 후 시간 | 변경 전 할당 | 변경 후 할당 |
| --- | ---: | ---: | ---: | ---: |
| 로컬 카탈로그 보석 갑옷·아이스 볼트·경쟁, 38칸 | 8.44ms | 30.68ms | 2.70MiB | 5.45MiB |
| 합성 아티팩트 12개·석판 3개, 42칸 | 129.73ms | 212.21ms | 148.48MiB | 162.56MiB |
| 합성 아티팩트 35개·석판 6개, 42칸 | 485.31ms | 885.86ms | 451.89MiB | 522.58MiB |

로컬 사례는 실측 능력치 표와 아이스 볼트 강화 우선 4배를 사용했다. 구형 카탈로그에 없는 마법 치명타 적용 표시만 위에서 확인한 볼트 경로에 따라 보충했고, 마나 비용 등 없는 표는 만들지 않았다. 변경 전에는 갑옷이 꺼졌으며 변경 후에는 두 아티팩트가 활성이고 감점 빈칸은 0이었다. 점수는 평가 의미가 달라져 변경 전후 수치 증가를 전투 성능 향상으로 해석하지 않는다. 합성 두 사례는 효과 점수 26, 57과 전체 활성을 유지했다.

추가 탐색과 비교 항목으로 실행 비용은 증가했다. 첫 구현에서 큰 가방은 3922.85ms였지만 같은 효과의 칸을 묶은 뒤 885.86ms로 줄었다. .NET 측정이며 Unity 내 프레임 시간이나 최대 처리 시간 보장은 아니다. 재현 코드와 원본 로그는 로컬 `artifacts/placement-objective/bench/`, `bench-baseline.log`, `bench-current-grouped.log`에 보관한다. 게임 데이터와 DLL은 저장소에 포함하지 않는다.

실제 플레이 화면의 버튼 배치·F8 이동·멀티플레이 적용은 아직 검증하지 않았다. 플러그인은 게임 어셈블리를 참조해 빌드하되 자동 설치하지 않는다. 실제 제보 판을 비교하려면 새 플러그인의 F9 갱신 후 F10 재현 자료가 필요하다.

## 재검토

커밋 `f8f832d`를 다시 검토해 다음 문제를 재현하고 수정했다.

- `Solve`를 거치지 않는 직접 배치 평가와 추천 기준 계산에서는 현재 활성 아이템의 보호가 준비되지 않았다. 석판 탐색과 배치 평가 진입점에서 원래 가방의 보호를 계산한다. 획득·제거·합성 가상 배치는 그 보호 대상을 복사해 고정하고, 가상 변경 뒤 상태를 새로운 보호 기준으로 삼지 않는다.
- 가상 기준 배치부터 현재 활성 보호를 위반하면, 추천 결과가 같은 위반을 반복해도 새 비활성화가 아니라며 허용했다. 이제 원래 가방의 보호 위반은 가상 기준 배치와 무관하게 거부한다. 실제 현재 상태 비교도 함께 유지한다.
- 기존 합성 석판을 재료 목록에서 제외한 뒤, 줄어든 목록의 순번을 전체 석판 배치에 적용해 다른 석판을 잘못 빼고 있었다. 원래 슬롯의 위치로 재료를 식별한다. 합성 가상 배치의 복사도 획득·제거와 같은 경로를 사용해 설정과 보호 기준 상속이 갈라지지 않게 한다.
- `사용 유지`와 `끄기 허용`을 함께 지정했을 때 끄기 허용의 저장 상태가 꺼진 것처럼 보였다. 두 설정을 그대로 표시하며 사용 유지의 우선순위는 유지한다. 효과 점수가 같아도 배치가 바뀌면 `배치 정리`로 표시한다.

직접 평가·추천 기준의 활성 보호와 잘못된 기준 배치의 허용 문제는 수정 전 실패 3건으로 확인했다. 기존 합성 석판을 첫 번째·중간·마지막에 둔 세 입력 중 앞의 두 입력도 수정 전 실패했다. 설정 변경 뒤 재평가, 석판 제거 전 보호의 상속, 합성 재료의 실제 위치와 은팔찌 제보를 포함한 회귀 테스트 12개를 추가했다. 로컬 로그는 `artifacts/placement-objective/review-before.log`, `review-mix-before.log`, `review-after.log`에 보관한다.

은팔찌(1194, `WINDSONG`)도 같은 원인이었다. 로컬 게임 1.0.30의 능력치는 공격 속도 4/8/12/16과 이동 속도 -4/-6/-8/-10이고, 기존 환산 순가치는 약 -0.667/-0.333/0/0.333이다. 9칸과 38칸에서 아이스 볼트·경쟁과 함께 비교했을 때 0.2.6은 은팔찌를 -1강 비활성으로 남겼고 현재 코드는 0강 활성으로 복구했다. 두 경우 모두 아이스 볼트의 유효 1강을 유지했다. 은팔찌의 원본 능력치와 환산 점수표는 변경 전후 같으며, 제품 코드에는 아이템 ID 예외를 넣지 않았다. 제보별 입력은 회귀 테스트이며 해결책은 공통 활성 보호·배치 비교 정책이다. 측정 코드와 로그는 `artifacts/placement-objective/silver/`, `silver-before.log`, `silver-after.log`에 보관한다.

재검토 후 `scripts/check.ps1` 최종 결과는 전체 테스트 511개 통과(실패·건너뜀 0), 포맷·진단 도구·플러그인 빌드 통과다. NuGet 취약성 조회의 `NU1900` 경고는 남아 있다. 최종 로그는 `artifacts/placement-objective/review-check-final.log`이며 실제 게임에 설치하거나 적용하지 않았다.

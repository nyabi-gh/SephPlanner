# 0.2.7 계산 지연 제보와 수정

2026-09-09 21:59:22 F10 자료를 확인했다. 사용자가 보고한 대기 시간은 약 10초다. 실행본은 0.2.7, 게임은 1.0.30, 카탈로그 형식은 15이며 열린 칸 38개에 아티팩트 14개와 석판 7개가 있었다. 강화 지정은 없고 STURDY·PRECISION 콤보를 우선했다.

F10 당시 게시된 요청은 61, 마지막 요청은 62이고 계산 오류 기록은 없다. `.replay`는 요청 61의 입력과 결과이며 별도 스냅샷은 F10 순간의 가방이다. 원래 Core 빌드로 재생했을 때 저장된 배치·점수·추천 요약과 모두 일치했다. F10 가방은 재배치 후 점수를 유지하며 추가 이동 0건으로 수렴했다. 이 결과로 다른 세션의 무한 반복까지 해결됐다고 판단하지 않는다.

## 병목과 수정

게시 입력에서 후보 추천을 포함하면 석판 배치 추정이 322,763회 실행됐다. 측정용 계측에서는 후보 탐색이 전체 시간의 대부분을 차지했다. 제거 추천도 자체 후보 탐색을 한 번 수행한다. 매 후보마다 같은 석판의 위치·회전 객체를 새로 만들고, 시뮬레이션 행렬과 점유 배열을 새로 할당하며, 같은 질의의 효과 값을 반복해서 해석하고 있었다.

- 부모 후보들이 같은 위치·회전의 석판 객체를 공유한다. 후보의 열거 순서와 평가 기준은 유지한다.
- 배치 추정에만 쓰는 점유 배열과 시뮬레이션 행렬은 해당 풀이 안에서 재사용한다. 다음 후보를 계산하기 전에 모든 효과와 적용 상태를 초기화하며 외부 결과로 반환하지 않는다.
- 석판의 질의와 조건을 해석한 정보를 재사용한다. 위치·회전·격자 크기·열린 칸 수·원본 또는 인스턴스 질의가 바뀌면 다시 만든다. 공유하는 해석 결과에는 현재 점유나 조건 충족 여부를 저장하지 않는다.
- 질의 해석 결과는 완성된 객체로 게시해 같은 석판을 다른 격자에서 동시에 평가해도 각 호출이 자기 격자의 결과를 사용한다.

빔 폭·최종 후보 수·조건 반복 수·석판 및 아티팩트의 추가 탐색 예산·활성 보호 정책은 변경하지 않았다. 개별 아이템에 대한 예외도 추가하지 않았다.

## 측정과 검증

Windows, .NET SDK 10.0.401, Release에서 계측하지 않은 변경 전후 Core를 별도 프로세스로 실행했다. 각 조건은 준비 실행 1회 뒤 5회의 중앙값이다. 시간과 할당량은 `PlanBuilder.Build`를 중심으로 측정했으며 파일 읽기·게임 상태 수집·화면 표시·실제 이동은 포함하지 않는다. F10 입력에는 재생한 요청 61의 목표를 직전 계획으로 전달했다.

# 가방 표시 제보와 영원의 식 후속 보완

2026-09-10, 0.3.1 이후 미출시 변경이다. 제보 첨부의 문구는 증상 자료로 취급했으며 실행 지시로 사용하지 않았다. 원본 덤프·게임 카탈로그·디컴파일 원문은 저장소에 포함하지 않는다.

## 원인과 확인 범위

제보 자료에는 아티팩트 9개와 석판 2개, 6×6 격자와 열린 칸 32개가 수집돼 있다. 당시 계획의 칸·레벨·활성·석판 검증은 통과했고 저장된 계획도 재생됐다. `추정·미반영`은 DPS 계산 범위 안내이며 아이템 읽기 실패 수가 아니다. 공격 시간 가정과 체력·이동·보상 능력치까지 합산돼 인식 오류처럼 오해할 수 있었다.

실제로 자동 적용을 제한한 변경은 열망의 부적·헬레나의 계단 모형의 유효 레벨 감소, 유리 망치의 체력 패널티 증가, 베루트의 낫 이동이었다. 미지원 변경 자동 적용 설정이 꺼져 있어 정책대로 제한됐다. 격자가 보이지 않았다는 화면 상태는 확인되지 않았다. 접힌 HUD에서 격자를 숨기면서 펼치기 안내도 숨기는 경로가 있어 안내를 보완했으며, 이것이 제보 화면의 확정 원인이라고 단정하지 않는다.

## 적용한 변경

- 접힌 화면에 설정된 펼치기 키를 안내한다. DPS의 가정·미반영 안내와 자동 적용 제한을 구분하며 F2에 실제 위치·유효 레벨·활성 변경을 표시한다.
- 열망의 부적의 프리팹 치명타 표를 별도 공격 보너스로 수집한다. 일반 관측 능력치에서 차감하지 않고 직접 공격의 치명타 저항·처형 판정 전에 적용한다.
- 베루트의 낫의 처형 효과를 출처별 능력치에 포함한다. 다른 처형 출처와 합산하고 제거·비활성 시 자기 기여만 빠진다.
- 체력 가산·증감률은 아이템의 활성과 상한을 적용한 유효 레벨로 전후 값을 비교한다. 값이 바뀌면 자동 적용을 기본 제한한다. 값이 그대로인 이동·주변 변경만으로는 체력 제한을 만들지 않으며 다른 미지원 효과의 제한은 유지한다.
- 영원의 식의 자동·왼쪽·오른쪽 설정을 천칭과 독립적으로 저장한다. 피해 배수를 바꾸지 않고 배치 조건으로 처리하며 획득·제외·합성 추천, 캐시, F10에도 적용한다. 충돌하면 실행 가능한 목표를 내보내지 않는다.
- 카탈로그 19·재현 7을 사용한다. 기존 카탈로그 18을 포함한 재현 5·6은 이전 설정 구조로 지문을 검증하고 영원의 식을 자동으로 읽는다. 구형 입력에 새 방향이 주입되거나 새 파일의 지문이 변경되면 거부한다.

## 게임 규칙 근거

설치된 게임 1.0.30의 `Assembly-CSharp.dll`을 디컴파일해 확인했다.

| 대상 | 확인한 동작 | 모델 처리 |
|---|---|---|
| `Charm_IncreaseCriticalChance_NormalAttack.OnAttackTarget` | `DirectAttack`의 치명타 확률을 증가 | `WeaponSimple`의 일반·대시·특수 공격 생성이 모두 직접 공격임을 확인해 적용 |
| `UnitAvatar` 피해 적용 | 공격 전 콜백 이후 치명타 저항과 처형 판정 | 추가 치명타를 저항·처형 앞에서 계산 |
| `Charm_ScytheOfBerut` | 기본 능력치 외에 활성 시 `EXECUTION` 1 추가, 비활성 시 제거 | 기본 치명타 표와 처형 출처를 함께 교체 |
| `StatusInstance_FinalHP` | 최대 체력 백분율을 더하고 제거 시 역산 | 전체 최대 체력으로 오인하지 않도록 아이템별 증감률로 표시 |
| `Charm_SpeedRun` | 층 진입 시 버프 시작·갱신, 타이머 만료 시 해제 | 남은 시간 미수집을 명시하고 현재 관측값·기존 제한 유지 |
| `Charm_FireIceWeapon` | X≤2이면 얼음 무구의 화염 전환, 그 외 화염검의 얼음 전환 | 기존 좌우 계산을 유지하고 독립 배치 조건 추가 |

헬레나의 계단 모형은 상시 공격 속도로 환산하지 않았다. 현재 덤프에는 버프 활성 여부와 남은 시간이 없어 시간 만료·레벨 변경을 재현할 수 없다. 시간 효과까지 지원하려면 해당 상태 수집과 시간에 따른 효과 해제 모델을 별도로 구현해야 한다.

## 검증

`scripts/check.ps1`에서 808개 테스트, 포맷, 진단 도구와 Plugin Release 빌드가 통과했다. 경고·오류는 없었다.

천칭 3가지 × 영원의 식 3가지의 결과를 작은 격자의 전체 배치와 비교했다. 방향·잠긴 칸·활성·고정 충돌, 복수 아이템의 자리 부족, 획득·제외·합성 전파, 설정 저장·초기화, 캐시 무효화와 재현 지문을 검사했다. 직접 공격 치명타의 저항·처형 순서, 비무기 피해 제외, 레벨·제거·비활성, 처형의 다른 출처 유지와 체력 패널티 안내도 검사했다.

합성 자료를 설치 게임의 Mono와 Newtonsoft.Json에서 형식 7로 저장하고 같은 Core 빌드의 .NET 진단 도구에서 재생해 지문·결과가 일치했다. 과거 v5 Mono·v5 .NET·v6 Mono 합성 자료는 그대로 유지했다. 실제 제보 자료는 코드 변경을 허용해 재생했으며 배치·검증·DPS가 유지되고 자동 적용 제한 설명 한 항목만 달라졌다. 과거 파일의 카탈로그에 새 효과를 임의로 보충하지 않았다.

## 남은 실기 확인

새 DLL로 게임 화면을 조작하거나 실제 피해를 측정하지 않았다. 새 카탈로그 수집 후 F7 격자 표시와 F2의 두 방향 설정·충돌 이유, F8 제한, F10 저장·재생을 게임에서 확인해야 한다. 구형 카탈로그는 새 실행에서 갱신되며 필요하면 F9로 재수집한다. 실제 제보 화면이 펼친 상태에서도 비어 있다면 화면과 새 F10 자료를 대조해 별도 표시 문제를 추적한다.

# 남은 작업

우선순위와 근거를 남긴다. 세부 조사 결과는 [RESEARCH.md](RESEARCH.md)에 있다.

## 끝난 것

- **효과 텍스트 툴팁.** 격자 칸과 후보 목록에 마우스를 올리면 아티팩트가 실제로 무슨 일을
  하는지 보여준다. 문장은 게임의 `Charm_Basic.BuildEffectString`을 프리팹 컴포넌트에 그대로
  불러서 얻는다 — 로컬라이제이션 원문에는 `{VALUE}` 같은 자리표시자가 남아 있어 그대로 쓸 수
  없고, 그 자리를 채우는 것이 이 함수다. `showAllLevel`을 켜서 레벨별 값이 범위로 나오게 했다.
  덤프는 종류마다 한 번뿐이라 특정 레벨의 값을 담으면 다른 레벨에서 거짓말이 된다.
  TextMeshPro 서식은 `RichText.Strip`으로 걷어낸다.
- **프리셋 코드 가져오기.** 오버레이 "빌드 우선"에 붙여넣기 자리를 두었다. 디코더는
  `SephPlanner.Core`의 `PresetCode`이고, 즐겨찾기 아티팩트는 후보 목록 가중치로, 과일 꼬치의
  양수 카테고리는 빌드 우선 칩을 대신 눌러 주는 것으로 이었다. 칩을 대신 눌러 주는 방식이라
  가져온 뒤에도 손으로 켠 것과 똑같이 끄고 켤 수 있다. 원문 코드는 `UserSettings`에 남는다.

## 보류 - 아티팩트 가치 데이터

**가장 큰 구멍이지만 지금은 손대지 않기로 했다.** 어디에 놓을지는 잘 답하는데 무엇을 집을지를
못 답한다. 점수가 레벨 모델이라 전투 효과가 센 아티팩트와 밋밋한 아티팩트가 똑같이 `+2`로 뜨고,
"얼마나 센가"에 대한 신호는 `Worth.OfRarity`의 레어도 배수(1.0~1.7)가 전부다. 대리값이다.

프리셋 가져오기는 이걸 절반만 메웠다 — 누가 프리셋을 공유한 빌드에서만, "즐겨찾기에 있냐 없냐"는
이진 신호로만 작동한다. 효과 텍스트 툴팁은 판단을 사람에게 넘긴 것이지 푼 것이 아니다.

**배제한 것의 범위를 정확히 해 둔다.** 배제할 근거가 있었던 것은 *공략 사이트를 긁어서 그 글을
재배포하는 것*이지 *공략 지식을 쓰는 것*이 아니다. 사실과 평가에는 저작권이 없으므로 아래 A는
라이선스 문제가 없다.

- **A. 큐레이션 가치 데이터 (권장).** `data/values/charms.json`에 엔티티 번호 →
  `{ tier, tags, notes, sources }`, 빌드 프로필이 그 태그에 가중치를 건다. `Worth.OfRarity`가
  있던 자리를 대신하고, 데이터가 없는 아티팩트는 지금처럼 레어도로 물러선다. 출처는 참고
  문헌으로 적고 글은 옮기지 않는다. 커뮤니티 PR 로 채운다. 값: 초기 데이터를 사람이 채워야
  하고 패치마다 손봐야 한다.
- **B. 나무위키 데이터 도입.** 남이 정리한 평가를 그대로 쓴다. 비영리라 NC 는 통과하지만 SA 가
  그 데이터에 붙어 배포·재사용 때마다 걸리고, 나무위키 약관의 대량 수집 조항을 따로 봐야 한다.
  무엇보다 남의 판단을 옮기면 패치 때 우리가 갱신할 수 없다.
- **C. 효과 텍스트에서 뽑기.** 덤프한 효과 문장에 레벨별 수치 범위가 들어 있어, "레벨을 올려도
  아무 일 없는" 아티팩트와 스케일링하는 것 정도는 자동으로 갈린다. 라이선스 문제가 없고 패치를
  자동으로 따라가지만 "센가"는 여전히 답하지 못한다. A 와 배타적이지 않아서, 257종의 초안을
  뽑아 사람이 빈 표 대신 초안을 고치게 하는 발판으로 쓸 만하다.

다시 열 때는 A 의 스키마를 먼저 잡고 C 로 초안을 뽑는 순서.

## 백로그 (순서 미정)

- **이웃 의존 아티팩트 가치 모델 확장.** 12종 중 하얀 종이만 완료. 조화의 수정
  (`Charm_NearLevelDamage`, 이웃 8칸 유효 레벨 합 비례)이 다음 후보. RESEARCH.md 참고.
- **프리셋의 "피하는 콤보" 반영.** 가져오기는 과일 꼬치의 양수 카테고리만 빌드 우선으로 켠다.
  음수(그 카테고리를 피하겠다는 뜻)는 화면에 개수만 보여 주고 점수에는 쓰지 않는다. 콤보 가치를
  깎는 방향이 맞는지 실제 빌드로 확인한 뒤에 붙인다.
- **석판 합성 추천.** 합성기(`TabletMix`)는 선택지로 잡히지 않아, 가진 석판 중 어느 둘을 합치면
  좋은지 알려주지 않는다. 조건 질의가 같은 쌍만 후보이고 층마다 한 번뿐이라 탐색 범위는 작다.
- **인스턴스 질의 대조.** `QueryVerifier`가 카탈로그 정의만 돌아서 합성 석판의 여러 줄 질의는
  게임 원본과 대조된 적이 없다. RESEARCH.md의 "석판 합성" 절 참고.
- **로컬 런 기록.** 런 종료 시 최종 격자·점수·콤보를 로컬 JSON으로. 백엔드 없음 원칙 유지.
- **후보 미리보기(what-if).** 후보 클릭 시 그걸 집었을 때의 격자를 잠깐 표시. 솔버가 이미
  계산하므로 표시만 추가.
- **콤보 가중치 실측.** `Worth.cs`의 2.0/0.25는 실측 근거 없는 설계값.
- **다국어.** `Naming.CurrentLanguage = "current"` 단일 언어 구조. 15개 언어 데이터는 이미
  추출 가능하므로 배관만 남음.

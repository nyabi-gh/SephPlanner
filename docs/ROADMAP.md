## 다음 기능 (순서 확정)

### 1. 프리셋 코드 가져오기

추천이 빌드를 알게 하는 기능. 오버레이에 커뮤니티 프리셋 코드(`AAF_PRESET_OBFZ|v1…`)를
붙여넣으면 그 빌드 기준으로 추천 가중치를 잡는다.

- **왜 이 방식인가.** 게임 내 데이터만으로는 "이 아티팩트가 이 빌드에서 강한가"를 알 수 없다
  (전투 효과는 레벨 행렬에 안 나타난다). 공략 사이트 자동 수집은 배제했다 — 나무위키는
  CC BY-NC-SA의 SA 조건이 전염되고, 갤러리 글은 라이선스 불명의 산문이며, 영어권 "위키"들은
  SEO 콘텐츠 팜이다. 반면 커뮤니티는 이미 게임 내장 프리셋 코드로 빌드를 공유하고 있다
  (디시 세피리아 갤러리의 빌드 공략 글들, sephiria.wiki/builds). 작성자가 공유 목적으로 만든
  게임 네이티브 포맷이라 라이선스·스크래핑·백엔드 문제가 전부 없다.
- **포맷은 해석 완료.** XOR + GZip + Base64, 내용은 시작 무기 / 즐겨찾기 아티팩트 목록 /
  특성 포인트 / 차원 주머니 / 과일 꼬치 카테고리 성향. RESEARCH.md의 "프리셋 코드" 절 참고.
- **구현 방안.** 디코딩은 Core 에 구현(XOR 키는 짧은 상수라 게임 의존이 없다). 오버레이에
  붙여넣기 UI를 두고, 디코딩된 즐겨찾기 아티팩트는 강화 우선·추천 가중으로, 과일 꼬치
  카테고리는 빌드 우선 칩 자동 지정으로 잇는다. 기존 UserSettings 에 저장해 세션을 넘긴다.
  추천 끄기 토글의 지배를 받는다(판단 보조에 해당).

### 2. 효과 텍스트 툴팁

후보와 격자 칸에 마우스를 올리면 아티팩트의 실제 효과 설명을 보여준다.

- 로컬라이제이션 키 `Charm_{Id}_Effect`/`Effect2`는 DataTool 이 이미 추출한다. 플러그인
  카탈로그 덤프에 효과 텍스트를 싣고 오버레이 툴팁에 붙이면 된다.
- 게임에서 보이는 정보라 숨은 정보 금지 원칙에 어긋나지 않고, 로컬 덤프 원칙 그대로다.

## 성능 여지 (체감 문제 생기면)

- `TabletQuery.Parse` 메모이제이션 — 빔 확장마다 같은 질의를 문자열부터 재파싱한다.
- 빔 확장의 증분 시뮬레이션 — 현재 O(석판수²), 부모 결과 재사용으로 O(석판수) 가능.
- 빔 후보 전량 정렬 대신 top-k 선택.

# 0.3.0 배포 전 기존 제보 회귀 점검

2026-09-10에 다시 전달받은 제보를 DPS 전환 코드에서 확인했다. 합작 창의 열림 상태가 HUD 갱신 판정에 빠진 문제 하나를 추가 수정했다. 나머지 제보는 아래 재현 조건에서 회귀가 발견되지 않았다. 행성 공격의 DPS 미지원과 실제 인게임 검증 미실시는 남아 있다.

## 근거와 회귀 검사

게임 규칙은 로컬 게임 1.0.30의 `Assembly-CSharp.dll`에서 디컴파일한 `Charm_NearLevelDamage`, `Charm_RightSpellCooldownHelper`, `Charm_UpCharmDamage`, `Charm_FireIceWeapon`, `Charm_FireIce`, `TabletMix`, `UI_TabletMixPanel`과 대조했다. DLL SHA-256은 `C3939A7D431F1362DACA655938480569E11F501F7D0820A989873765555A7C39`다. 레벨 표는 로컬 활성 카탈로그의 실제 프리팹 수집값을 참고했다. 게임 원문·카탈로그는 배포물에 넣지 않는다.

`ReportedIssueRegressionTests` 24개를 새로 추가해 이전 가치 평가 전용 검사에서 빠진 DPS 경로를 확인했다. `HudFrameTests` 2개는 실제 HUD의 갱신 판정을 게임 객체 없이 검사한다. 수정 전 창 상태 비교를 제거한 코드에서는 둘 다 실패했고, 복구한 코드에서는 둘 다 통과했다. 기존 `AdvicePanelExpansionTests` 2개까지 묶은 제보 검사 28개가 통과했다.

개별 재현은 제보 당시 가방이 아닌 규칙별 시험 입력이다. 모래시계에 연결된 마법과 무기가 같은 시간당 피해를 낼 경우 마법을 더 자주 쏴도 총 DPS가 같을 수 있다. 연결 효율 검사는 마법만 쓰는 별도 조건으로 분리했고, 무기를 쓰지 않아도 기존 활성 보호가 작동하는지 따로 검사했다.

로컬 기록은 `artifacts/reported-issues-hud-before.log`, `artifacts/reported-issues-regression-after.log`, `artifacts/check-v0.3.0-reported-issues.log`에 남긴다. 테스트·빌드 통과가 실제 전투 피해 일치, 모든 가방의 전역 최적, 인게임 화면 확인을 대신하지는 않는다.

최종 `scripts/check.ps1`에서 전체 테스트 742개, 포맷, 진단 도구와 플러그인의 Release 빌드가 통과했다. 실패·건너뜀·경고·오류는 0이다.

# 아티팩트 가치 데이터

`charms.json`은 **손으로 채우는** 아티팩트 가치다. 게임 데이터로 잴 수 없는 아티팩트, 곧 값어치가
능력치가 아니라 고유 효과에 있는 것들을 위한 자리다.

능력치를 주는 아티팩트는 여기 적을 필요가 없다. 플러그인이 게임의 레벨별 능력치 표에서 값어치를
직접 재어 카탈로그 덤프에 실어 주기 때문이다(`CharmStatWorth`). 여기 적은 값은 잰 값보다 우선하므로,
측정이 틀렸다고 판단할 때만 덮어쓴다.

## 채우는 법

초안을 먼저 뽑는다. 지금 덤프 기준으로 아티팩트마다 무엇이 측정됐고 무엇이 비어 있는지 찍어 준다.

```powershell
dotnet run --project src/SephPlanner.DataTool -- --values
```

빈 채로 남은 아티팩트가 손으로 채울 대상이다. 항목 하나는 이렇게 생겼다.

```json
{
  "id": "SixLeafClover",
  "entityId": 1234,
  "tier": 4,
  "tags": ["magic", "cooldown"],
  "note": "쿨다운을 크게 줄여 주문 빌드의 축이 된다",
  "sources": ["디시 세피리아 갤러리 빌드 공략 2026-08"]
}
```

- `id` / `entityId` — 조회는 번호가 먼저다. 게임 패치로 번호가 밀리면 `id`가 받아 준다.
  둘이 어긋나면 `id` 쪽을 믿는다. 되도록 둘 다 적는다.
- `tier` — 1(하위)에서 5(상위). **칸의 값은 짐작이 아니다.** 측정된 순수 능력치 아티팩트
  110종의 분포에서 10·25·50·75·90 분위를 그대로 가져왔다. 그러니 3은 "평범한 아티팩트만큼",
  5는 "상위 10% 만큼"이라는 뜻이다.
- `base` / `perLevel` — 등급 대신 값을 직접 적고 싶을 때 쓴다. 단위는 **레벨**이다.
  `base`는 레벨 0에서의 값어치, `perLevel`은 레벨 하나가 더 주는 값어치다.
- `tags` — 빌드 성향. 지금은 저장만 하고 점수에 쓰지 않는다(docs/ROADMAP.md).
- `note` — 왜 이 값인지. 오버레이 툴팁에 그대로 보인다.
- `sources` — 판단의 근거로 삼은 글. **참고 문헌으로만 적고 본문을 옮기지 않는다.**
  사실과 평가에는 저작권이 없지만 남의 문장에는 있다(docs/LEGAL.md).

## 왜 저장소에 있는가

이것만은 게임에서 나오는 데이터가 아니라 우리가 만드는 데이터다. 그래서 `data/generated/`와 달리
저장소에 커밋하고 배포물에도 함께 나간다(오버레이 실행 파일에 포함된다).
